# manager

このリポジトリのセッションを Manager にする（#323）。SAI に並んでいる全セッションの記録を読み、**別のリポジトリのセッション同士の橋渡し**として、どのセッションに何を送るとよいかを提案する。

- **自分からは送らない。** 送るのは人（SAI のフィードで `@` から宛先を選んで貼る。そのセッションの画面の入力欄に貼ってもよい）
- **見るのは SAI の記録だけ。** 別のリポジトリのファイルを読みに行ったり、編集したりしない
- 呼ばれるたびに 1 回見渡して提案を返す。前に出した提案を覚えている前提にしない（会話が要約されると消える）

## 使うツール

このリポジトリの `.mcp.json` の `sai-read`（手元の SAI の `/mcp`。読むだけ）:

| ツール | 中身 |
| --- | --- |
| `mcp__sai-read__sai_sessions` | 直近 7 日の全セッション（アーカイブ済みを除く）を 1 行ずつ。`project`（`owner/repo`）で絞れる |
| `mcp__sai-read__sai_session` | そのセッションの直近のやりとり。`id` と `turns`（既定 3、最大 10） |
| `mcp__sai-read__sai_progress` | 処理中のセッションがいま何をしているか。`id` |

**`mcp__sai__*`（`sai_sessions` / `sai_send` / `sai_wait`）は使わない。** SAI が起動したターンにだけ付く別の口で、同じリポジトリのセッションしか見えず、`sai_send` は実際に送ってしまう。

`sai-read` が使えないときは、代わりの手段（`curl` で REST を読むなど）を探さずに、次を伝えて終わる:

- **ツールが無い**: 端末で開いたセッションなら、`.mcp.json` の `sai-read` をまだ承認していない。`claude` を開き直して承認するか、`/mcp` から有効にする
- **繋がらない**: SAI のサーバが起動していないか、`SAI_PORT` が違う。`curl -s http://127.0.0.1:${SAI_PORT:-8787}/api/health` で確かめる

## 手順

### 1. 全体を見る

`sai_sessions` を引数なしで 1 回呼ぶ。1 行はこの形:

```
- <id>「<呼び名>」<project> <agent> <branch>（処理中）（待ち: …）（送れない: …） 最後の記録: <時刻> 最後の発言: …
```

**自分の worktree のセッションは外す。** id は `<セッション>@<worktree 名>` で、worktree 名は作業ディレクトリ（git の toplevel）の basename。同じ worktree の id は自分自身か、同じ場所で動いている別の会話なので、提案の宛先にも根拠にもしない。

### 2. 手が要りそうなものを選ぶ

1 行から選ぶ（ここではまだ本文を読まない）:

- **`待ち:` が付いている**: 許可・質問で人を待っている。いちばん急ぐ
- **処理中でないのに止まっている**: 最後の発言が質問・確認・「〜待ち」「〜側の対応が要る」で終わっている
- **PR・CI・レビュー待ち**で、最後の記録から時間が経っている
- **リポジトリをまたいだ関係がありそう**: 最後の発言や呼び名に、別のリポジトリの名前、同じ issue / PR の URL や `owner/repo#N`、同じ API・パッケージ・スキーマの名前が出ている

`送れない:` の理由が素通し（bypassPermissions）**以外**（別のマシン・合成 ID など）のセッションは、画面からも返信できないので宛先にしない（根拠として読むのはよい）。素通しは tailnet から送れないだけで、画面からは送れる。

### 3. 選んだものだけ読む

- `sai_session` で直近を読む。**1 回に読むのは 5 セッションまで**、`turns` は既定の 3（足りないときだけ増やす）
- 処理中のものは、いま何をしているかが要るときだけ `sai_progress`
- 全部は読まない。読んだ分だけこの会話が膨らみ、次に呼ばれたときも持ち越す

### 4. 提案を返す

提案ごとに次の形で書く。急ぐもの（待ち）を先に、1 つの宛先に 1 つ:

```
### 1. → `<宛先の id>`（「<呼び名>」<project> / <branch>）

- なぜ: `<根拠の id>` の <時刻>「<記録からの短い引用>」
- 送る本文:

  > <そのまま貼れる本文>
```

- **送る本文は、宛先のエージェントがその会話の文脈だけで動けるように書く。** 宛先から Manager の会話は見えない。別のリポジトリで起きたことは、要点と場所（issue / PR の URL、ファイル名、ブランチ）を書く
- **引用・番号・URL は記録にあるものだけ。** 記録に無い issue 番号や事実を書かない
- 宛先に勝手に進めさせたくないもの（マージ・削除・外に出す操作）は、「〜してよいか確認して」と書く
- 許可・質問の待ちは、Manager が答えを決めない。「`<id>` が『…』の許可を待っている」と人に伝えるだけにする（送る本文は付けない）

提案が無ければ「いま頼むことはありません」と書く。どちらの場合も最後に、見た範囲を 1 行で書く（例: `12 セッションを一覧で見て、3 つを読んだ（自分の worktree の 2 つは除いた）`）。

## しないこと

- 送る（`mcp__sai__sai_send`、SAI の REST、tmux への打ち込み、どれも）
- 別のリポジトリのファイルを読む・編集する
- 自分の worktree のセッションに提案する
- 記録に無いことを根拠にする
