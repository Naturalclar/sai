# エンドポイント

サーバが返す API と、集計・返信の実行の中身。セットアップは [README](../README.md)。

| | |
| --- | --- |
| `GET /` | ビューア（`web/dist/index.html`） |
| `GET /assets/*` | ビルド成果物。`dist/` の外には出ない |
| `GET /api/sessions?days=7&project=&repo=&agent=&date=&archived=` | セッション一覧（集計済み）。`record_version` は窓の中の一番新しい行の `v`（画面の「record.py が古い」の判定）。各セッションの `waiting` は人を待って止まっていれば「何を待っているか」、そうでなければ空。`filters` に絞り込み候補、`replying` に処理中の返信（ID → `{ since, text }`）、`queued` に処理中に送って預かっている返信（ID → `{ items: [{ queue_id, text, since }], paused? }`。#305）、`approvals` に返信中のエージェントが待っている許可・質問（ID → 古い順の配列。**SAI が起こした `opencode serve` が答えを待っている許可も混ぜる**。#421）、`profile` に自分の表示名とアイコンも返す。既定ではアーカイブ済みを除き、`archived=1` でアーカイブ済みだけ（`total` と `filters` もその集合から）。`viewer` は tailnet 経由ならログイン名、直アクセスなら `null` |
| `GET /api/health` | `{ ok: true, viewer }`。認証の確認にも使う（偽ヘッダで `401` になること） |
| `GET /api/sessions/<id>?days=30` | そのエンティティの全行と `replying` / `queued`。別のセッションへ送ったことがあるか止めているセッションには `agent`（#311。`stopped`、いま回しているターンの `sent` / `limit` / `read_tokens` / `read_budget`、直近 5 件の `recent`: `message_id` / `to` / `to_name` / `since` / `status`（`pending` \| `done` \| `failed`））。端末で開いた Claude が質問（`AskUserQuestion`）で止まっていれば `question`（#333。`input` = transcript の返事の付いていない `tool_use` の入力そのまま、`asked_at`、`text` = 待ちの行と同じ `質問: …`。**`session.waiting` がその `text` と同じときだけ**載せ、SAI が回している `claude -p` の質問は `approvals` に出るので載せない）。`<id>` は `<セッション>@<リポジトリ>` |
| （`replying` の中身） | `{ "<エンティティID>": { "since", "text", "via"?: "terminal", "interruptible"?: true, "permission_mode"?: "acceptEdits", "failed"?: { "code"?, "tail" } } }`。`via` は端末（tmux）に打ち込んだ返信のときだけ付く（省略なら別プロセス。要対応の出し分けが見る）。`interruptible` は**いま SAI から止められる**ターン（#384。SAI の app-server が回している Codex で、`turn/start` の応答が返って `turnId` が決まっているもの）。画面はこれを見て仮バブルに「止める」を出す。`permission_mode` は Claude の返信を**起動したときに**付けた許可モード（`""` はフラグ無し＝既定、省略は分からない。#272）。動いている CLI には後から当てられないので、画面はセッションのメタと違えば「次の返信から」と出す。`failed` は返信の子プロセスが 0 以外で終わったとき 2 分だけ付く（`tail` は `reply.log` のそのターンぶんの末尾）。端末に打ち込んだ・開いている Codex の queue に渡した返信が 2 分たってもターンを始めなかったときも付き、そのときは `code` が無く `tail` が理由（#329）。付いている間は「処理中」ではない |
| `POST /api/sessions/<id>/reply?days=90` | body `{ "text": "..." }`。そのセッションを `cwd` で再開して1ターン回すのを投げっぱなしにし、`202` を返す。閉じたCodexはapp-server管理で応答の `via` が `app-server`。合成 ID は `400`、進行中は `409`、別オリジンは `403`。**body に `"queue": true` を付けると、進行中は `409` にせず預かる**（`202` で `via: "queued"` と `queue_id`。#305）。**`"steer": true`（#404）は、走っている Codex のターンに足す**（`202` で `via: "steer"`。足せなければ `queue` / `409` に落ちる）。前のターンが終わったら古い順に 1 件ずつ回す。預かりが残っていれば進行中でなくても後ろに並べる（追い越さない）。1 セッション 10 件までで、超えたら `409` |
| `POST /api/sessions/<id>/review?days=90` | その worktree の差分を Codex にレビューさせる（#403）。body は `{ "target": "uncommittedChanges" \| "baseBranch" }` だけで、**cwd もブランチ名も受けない**（cwd は行から、比べる相手は差分ビューアと同じ選び方）。**同一オリジンのみ**。`202` で `{ "accepted", "id", "session", "cwd", "target", "base" }`。Codex 以外は `400`、処理中は `409`。結果は普通のターン完了の行として届く |
| `POST /api/sessions/new?days=90` | 新しいセッションを始める（#314、Codex は #401）。body `{ "from": "<エンティティID>", "text": "...", "agent"?: "claude" \| "codex", "model"?: "opus", "permission_mode"?: "acceptEdits" }`。**作業ディレクトリは受け取らない**: `from` のセッションの `cwd` で `claude -p --session-id <uuid> -- <text>` を投げっぱなしにし、`202` で `{ "accepted", "id": "<uuid>@<repo>", "agent": "claude", "session": "<uuid>", "cwd", "via": "process" }`（body に `cwd` があっても見ない）。ID はサーバが決めるので、最初の行が届く前から `replying[id]` に載る（行を書く前に落ちた失敗もそこに出る）。`model` / `permission_mode` は `PUT .../meta` と同じ検査で、通らなければ `400`。通れば新しいセッションのメタに書く。`agent: "codex"` なら `thread/start` で thread id を作ってから 1 ターン回し、`session` はその id・`via` は `app-server`（`SAI_CODEX_APP_SERVER=0` では `400`）。`claude` / `codex` 以外の `agent` は `400`。`from` が窓に無ければ `404`、別のマシンのセッションか `cwd` が無ければ `400`、起動できなければ `500`、別オリジンは `403` |
| `DELETE /api/sessions/<id>/queue/<queue_id>` | 預けた返信を取り消す（#305）。`{ "id", "queue": { "items", "paused"? } }`（いまの預かり）。無ければ `404`、いま起動している先頭は `409`、別オリジンは `403` |
| `POST /api/sessions/<id>/queue/resume` | 止めた預かり（前の返信が失敗した・起動できなかった。理由は `paused`）を再開して先頭を回す。止めた理由の失敗ではもう止めない。応答は取り消しと同じ形。別オリジンは `403` |
| `POST /api/sessions/<id>/interrupt` | 処理中のターンを止める（#384。body は空）。**止められるのは SAI の app-server が回している Codex のターンだけ**（`turn/interrupt` は自分が `thread/resume` したスレッドしか止められないので、端末で人が回している Codex には手が出ない。`claude -p` と OpenCode は口が無いので `400`）。処理中でなければ `409`、`turn/start` の応答前（`replying.interruptible` がまだ無い）も `409`、別オリジンは `403`。**止めたら預かりは回さずに止める**（応答は取り消しと同じ `{ "id", "queue" }` で、`paused` に理由。人が「続けて送る」を押したときだけ回る）。実測（codex 0.154.0）では `{}` がすぐ返り、そのあと `turn/completed`（`status: "interrupted"`）が届く。**そのターンが起こしたシェルのコマンドは残る**（`sleep 120` が app-server の子として生き残った。SAI は殺さない） |
| `GET /api/agent/sessions?from=` | **エージェント用**（#310。SAI の MCP サーバの `sai_sessions`）。送り元（`from`）と同じ project の、返信できる別のセッションの一覧 `{ "from", "sessions": [{ "id", "name", "project", "branch", "agent", "busy", "last_text", "context_tokens" }] }`。本文は載せない。`context_tokens` は送ると相手が読み直す量（相手の transcript / rollout の直近の呼び出しの入力トークン。分からなければ `0`。#311）。**`X-SAI-Agent-Token`（feed dir の `agent-token` の中身）が要り、`Origin` / `Sec-Fetch-Site` が付いていれば（ブラウザから）`403`**。送り元が SAI から起動していまターンを回していなければ `409` |
| `POST /api/agent/send` | エージェント用。body `{ "from", "to", "text" }`。見出し（`【SAI】#<project> の「<送り元>」からのメッセージです（id: …）`）を付けて `to` のターンを起動する（処理中なら預かり。#305）。`202` で `{ "message_id", "to", "via", "sent", "limit", "context_tokens", "read_tokens", "read_budget" }`（`read_tokens` はこのターンで相手に読み直させた量の合計、`read_budget` はその予算）。同じ project の返信できる別のセッションでなければ `403`。`429`（#311）は次のとき: 受け取ったメッセージで回っているターンから（連鎖）、1 ターン 3 回を超えた、**相手のエージェントの 5 時間の枠が 80%・週の枠が 95% を超えている（か上限に当たっている。`GET /api/usage` と同じ値。取れなければ止めない）**、**1 ターンで相手に読み直させる量が 300 万トークンの予算を超える（相手の大きさが分からなければ足さない）**。本文が空か 4,000 字を超えたら `400` |
| `GET /api/agent/wait?from=&message_id=&wait=1` | エージェント用。送ったメッセージへの返答。相手のそのターンの完了の行（見出しの id で探す）が届いていれば `200` で `{ "status": "done", "text" }`（4,000 字で切る）、相手のターンが失敗した・預かりのまま止まったら `{ "status": "failed", "error" }`、まだなら `wait=1` で最大 20 秒待って `202`。送った本人でなければ `404`（記録はメモリだけなので、SAI を立て直したあとも `404`） |
| `POST /api/sessions/<id>/agent/stop` / `POST /api/sessions/<id>/agent/resume` | 画面から、そのセッションが別のセッションへ送るのを止める / 再開する（#311）。止めている間 `POST /api/agent/send` は `429`。止めたときは、そのセッションから送られて預かりに並んでいたメッセージも取り消す（相手でもう回っているターンは止めない）。`{ "id", "agent", "cancelled" }`。同一オリジンのみ（別オリジンは `403`、GET は `405`）。止めたことはメモリだけで、SAI を立て直すと戻る |
| `POST /mcp` | **tailnet から MCP で呼ぶ口**（#312。Streamable HTTP の最小: 1 通受けて `application/json` で 1 回返す。SSE とセッションは無し）。JSON-RPC の `initialize` / `ping` / `tools/list` / `tools/call`。ツールは `sai_sessions` / `sai_session` / `sai_progress`（読む）と `sai_send` / `sai_wait`（送る・待つ）。**使えるツールは身元で決まる**: ループバックの直アクセスと tailnet のユーザーは読むだけ、送る・待つは tailnet の ACL の grants で capability `github.com/naturalclar/sai/cap/mcp` の `tools` に `send` を与えたときだけ、タグ付きの端末は capability に書いたものだけ（無ければ `403`）。**`Origin` があれば capability の `origins` に書いたものだけ通し**（無ければ `403`）、そのときだけ CORS を返す。`OPTIONS` は preflight に `204`、`GET` / `DELETE` は `405`。`MCP-Protocol-Version` が受ける版（`2025-11-25` / `2025-06-18` / `2025-03-26`）でなければ `400`、配列（バッチ）・壊れた JSON は `400`、通知・応答は `202`。`sai_send` は `/api/agent/send` と同じく、相手のエージェントの使用量の枠と、相手に読み直させる量の予算（呼んだ人ごとに 10 分の区切り）で断る（#311）。手順は [docs/tailnet.md](tailnet.md) |
| `POST /api/approvals` | 返信中の CLI（`server/approvals/approve-mcp.ts`）が許可・質問を預ける。body `{ "id", "tool_name", "input", "tool_use_id"? }`。返信を処理中でないエンティティは `409`。`201` で `{ "approval_id" }` |
| `GET /api/approvals/<approval_id>?wait=1` | 答えが付いていれば `200` で `{ "behavior": "allow" \| "deny", "updatedInput"?, "message"? }`（渡したら消える）。まだなら `wait=1` で最大 20 秒待って `202`。無ければ `404` |
| `POST /api/approvals/<approval_id>/answer` | 画面から答える。Claudeはbody `{ "behavior": "allow" \| "deny", "updatedInput"?, "message"? }`。Codexの承認はAPIに載った `decisions[].id` を `{ "behavior", "decision" }` で返し、質問は `updatedInput.answers` を返す。**OpenCode の許可**（#421）も `decisions[].id`（`once` / `reject`）を `{ "behavior", "decision" }` で返す形で、サーバが `POST /session/<セッション>/permissions/<per_…>` に流す（`remember` は受けない）。未提示decisionは `400`、別thread/turnや切断済み・OpenCode 側から消えた許可は `409`、答え済みは `404` |
| `GET /api/sessions/<id>/skills?days=90` | `/` の候補になるスキル。`{ "id", "skills": [{ "name", "description", "source": "user" \| "project" }] }`。Claude は `~/.claude/skills/` とセッションの `cwd` の `.claude/skills/` から、Codex は `cwd` の `.codex/skills/` / `.agents/skills/` と app-server の `skills/list`（プラグイン・組み込み）から集める。プロジェクト側を先に、同じ名前はプロジェクトが勝つ。**OpenCode は本体に聞く**（#393。`GET /command?directory=<cwd>` の 1 本でスキルもスラッシュコマンドも返る。コマンドは `source: "command"`）。Grok は空。窓の中に無いセッションは `404` |
| `GET /api/sessions/<id>/models?days=90` | 返信で選べるモデルの候補（#394）。`{ "id", "models": ["provider/model", …] }`。**OpenCode だけ**本体に聞く（`GET /config/providers?directory=<cwd>` の**設定済みの provider**。`/api/model` の全件ではなく、その人が実際に使えるもの）。ほかのエージェントは空（記録に出てきたモデルから画面が組み立てる）。取りに来るのは**メニューを開いたとき**だけで、3 秒のポーリングには乗らない。窓の中に無いセッションは `404` |
| `GET /api/sessions/<id>/permissions?days=90` | そのセッションの `cwd` に効いている許可ルール。`{ "id", "cwd", "agent", "mode", "sources", "rules" }`。`rules` は評価順（`deny` → `ask` → `allow`）。**読むだけ**で、パスは `cwd` から固定で組み立てる。Codex は `sources` / `rules` とも空 |
| `GET /api/sessions/<id>/diff?base=&days=90` | そのセッションの worktree の差分（`git` を読むだけ）。`branch` が `base...HEAD`、`working` が未コミット、`untracked` は追跡外のファイル名。大きすぎれば `truncated`。`cwd` が git のリポジトリでなければ `404` |
| `GET /api/sessions/<id>/diff?summary=1` | 同じものの**大きさだけ**（`--numstat` のみで patch を作らない）。入力欄の差分ボタン（とフィードの PR に触れたバブルのボタン。#280）が開く前に出す行数と、そのブランチの PR 番号（`pr`。`gh` が引ければ）。`untracked` は数 |
| `GET /api/sessions/<id>/progress?days=90` | 処理中のターンがいま何をしているか（#302）。`{ "rev", "id", "active", "steps", "total", "updated_at", "context_tokens" }`。`context_tokens` は最後にモデルを呼んだときに読んだ量（Claude は assistant の `usage` の入力 3 つの和、Codex は `token_count` の `last_token_usage.input_tokens`。読めなければ `0`。セッション同士のメッセージの予算に使う。#311）。`steps` は最後のターンの直近の手順（古い順、最大 8 件。`kind` = `tool` / `thinking` / `text`、`tool`、`summary`、`started`、走っているツールには `ended` が無い）、`total` はそのターンの手順の数、`active` はターンが閉じておらず止まったまま古くなってもいないか。Claude は transcript（`~/.claude/projects/<cwd の記号を - に>/<session>.jsonl`）、Codex は rollout の**末尾だけを読む**（パスは行とホームから組み立て、リクエストからは受けない）。OpenCode・別のマシンのセッション・読めないときは空。3 秒のポーリングには乗せない（画面が処理中のセッションを出している間だけ取る） |
| `GET /api/sessions/<id>/meta` | 表示名・アーカイブ・返信のモデル・一言の性格。`{ "id", "meta": { "name"?, "archived_at"?, "model"?, "persona"? } }`。無ければ `meta` は `{}` |
| `PUT /api/sessions/<id>/meta?days=90` | body `{ "name"?: "...", "archived_at"?: "<ISO>", "model"?: "opus", "persona"?: "ISTJ", "permission_mode"?: "acceptEdits" }` をいまの値に重ねる。省略したキーは据え置き、空文字や `null` は「消す」で、全部消えたらエントリごと消える。知らないキーは捨てる。名前は100文字まで、`archived_at` は読める時刻、`model` は英数字で始まる 64 文字までの名前、`persona` は `shared/persona.ts` にある id、`permission_mode` は `acceptEdits` だけ（違えば `400`）。窓の中に無いセッションは `404`、別オリジンは `403` |
| `GET /api/sessions/<id>/icon?v=<mtime>` | アイコン画像そのもの（`image/png` など）。無ければ `404`。`v` がいまのファイルと同じなら `Cache-Control: immutable`、無ければ `no-store` |
| `PUT /api/sessions/<id>/icon?days=90` | body は画像そのもの（PNG / JPEG / GIF / WebP、1MB まで。種類は中身で見る。画面からは加工後の 256px の PNG が来る）。`{ "id", "icon": "<URL>" }` を返す。画像でなければ `400`、大きすぎれば `413`、窓の中に無いセッションは `404`、別オリジンは `403` |
| `DELETE /api/sessions/<id>/icon` | 画像を消す。`{ "id", "icon": null }`。無くても `200`。別オリジンは `403` |
| `POST /api/sessions/<id>/attachments` | 返信に添える画像を預ける。body は画像そのもの。`{ "id", "path", "url", "mime", "size" }`。10MB まで、種類は中身で見る。別オリジンは `403`、窓の中に無いセッションは `404` |
| `GET /api/attachments/<dir>/<name>` | 預けた画像を配る。名前が中身のハッシュなので中身は変わらない（`immutable`）。形の合わないパスは `404` |
| `GET /api/sessions/<id>/images/<key>?download=1&days=90` | 返答の本文に書かれた手元の画像を配る（#321）。`key` は本文に書かれたパスの鍵（`shared/images.ts` の `imageKey()`）で、サーバは**そのセッションのターン完了の行の本文から拾った参照の表**を引くだけ（パスはリクエストから受けない。表に無ければ `404`）。realpath が行の `cwd` の外なら `403`、中身が PNG / JPEG / GIF / WebP でなければ `415`、20MB を超えれば `413`、ファイルが無い・別のマシンのセッション・窓の中に無いセッションは `404`。`Content-Type` は中身から決め、`X-Content-Type-Options: nosniff`・`Content-Security-Policy: sandbox`・`ETag`（`If-None-Match` が合えば `304`）を付ける。`download=1` のときだけ `Content-Disposition: attachment` |
| `GET /api/profile` | 自分の表示名とアイコン。`{ "profile": { "name"?, "icon"? } }`。`icon` は `/api/profile/icon?v=<mtime>` |
| `PUT /api/profile` | body `{ "name"?: "..." }` をいまの値に重ねる。空文字や `null` は「消す」。100文字まで（超えたら `400`）。別オリジンは `403` |
| `GET /api/profile/icon?v=<mtime>` | 自分のアイコン画像そのもの。無ければ `404`。キャッシュの扱いはセッションのアイコンと同じ |

返信の実行は `server/reply/runner.ts`。`claude` / `codex` は `detached` で起動して待たず、stdout/stderr は `~/.agent-feed/reply.log` に追記する（うまく動かないときはここを見る）。**Claude には `--output-format json` を付ける**ので、その 1 行が `reply.log` の末尾に残る（#387）。ターンが終わると、そこから使ったトークンと費用を読んで `~/.agent-feed/turn-usage.jsonl` に 1 行足す（`{ ts, id, model, input_tokens, output_tokens, cache_read_input_tokens, cache_creation_input_tokens, cost_usd, duration_ms, num_turns, denials, is_error }`）。記録（`YYYY-MM-DD.jsonl`）には足さない。**応答では行の `usage` に載せる**（#411。`/api/feed` と詳細の行。どの行のぶんかは `shared/turnUsage.ts` の `usageByRow()` が決める: その使用量の `ts` 以前で一番新しい、同じエンティティの**ターン完了の行**で、差が 2 分以内のものだけ。フックの `Stop` は CLI が終わる前に走るので使用量のほうが必ず後になり、手元の実測では 0.6〜1.5 秒だった）。起動時に 1 回だけ読み、以後は書いた分をメモリにも足すので 3 秒のポーリングでは読み直さない（読み返すのは 90 日ぶんだけ。ファイルは切り詰めない＝消しても壊れない）。同じエンティティに同時に2本は走らせない。処理中に `queue: true` で送られた分は `server/reply/replyQueue.ts` が預かり（`~/.agent-feed/reply-queue.json` にも書くので再起動で消えない）、`-p` の exit・SAI 管理の Codex のターンの終わり・画面のポーリングのついでに `app.ts` の `drain()` が先頭を 1 件起動する。前の返信が失敗していたら回さずに止める。**OpenCode の許可待ちは、立っている `opencode serve` に聞いて画面のバブルにする**（#421。`server/reply/opencodePermissions.ts`）: 画面の 3 秒のポーリングのついでに **`GET /permission?directory=<セッションの cwd>`** を引き（**`directory` が要る**。`/command`・`/config/providers` と同じで、サーバは homedir で動いているので渡さないと保留があっても `[]` が返る。実測。聞きに行くのは**回しているか待っているセッションの cwd だけ**で、普段は 0〜1 本。**保留を見るためだけにサーバは起こさない**ので、返信を 1 度も回していなければ何もしない）、記録にあるセッションの分だけを `Approval`（`agent: "opencode"`、`answerable: true`、`decisions` = 許可（`once`）/ 拒否（`reject`））にする。答えは既存の `POST /api/approvals/<id>/answer` から `POST /session/<セッション>/permissions/<per_…>` に流す。**保留は v1 の `GET /permission` にだけ出る**（v2 の `/api/session/<id>/permission` は空だった。実測 1.18.30）。**答えられるのは SAI が起こしたサーバが持っている分だけ**で、端末の TUI や人が立てた別のサーバは URL も鍵も知らないので触れない。別のセッションへのメッセージ（#310）は、SAI が起動した `claude -p` の MCP サーバ（`--mcp-config`）に `sai_sessions` / `sai_send` / `sai_wait` を足し、エージェント用の口（`/api/agent/*`）を叩かせる。トークンは `~/.agent-feed/agent-token`（0600）で、MCP サーバには中身ではなく場所（`SAI_TOKEN_FILE`）を渡す。

集計はサーバ側（`server/rows/aggregate.ts`）。エンティティのキー（`<セッション>@<リポジトリ>`、セッションが取れない行は `unknown-<日付>`）は `shared/entity.ts` にあり、サーバの集計と画面のリンクが同じ関数を使う。ファイルは `(mtime, size)` で覚えていて、変わっていなければ再パースしない（`server/rows/store.ts`）。1日開きっぱなしにしても重くならないのはこのため。

レスポンスの形は `shared/types.ts` に1つだけ書いてあり、サーバの集計と画面の受け取りが同じ型を見る。フィールドを足すときはそこに足すと、片方だけ忘れたときに `pnpm typecheck` で止まる。
