# セッション同士のメッセージと MCPの経緯

なぜ今の形になったか（前はどうだったか・実測・レビューの指摘）。仕組みは [internals/agents.md](../internals/agents.md)。新しい経緯はこのファイルの該当する節に足す。

## セッション同士のメッセージ

### エージェント用の口を別の鍵にした

- 口は画面の返信とは逆で、`Origin` / `Sec-Fetch-Site` が付いていれば断り、`agent-token` の中身を要る。
- 同じマシンの CLI からループバックで叩くと Origin が無いので同一オリジンの検査は素通りするため、それとは別の鍵にした。
- MCP サーバには中身ではなく場所を渡す（`--mcp-config` は引数なので ps で見える）。

### 見出しに id を入れた

- record.py が `user_text` を 2000 字で切るので、本文の一致ではどのターンか決められないため（書いた当時の上限。いまの上限は 20000 字。#358）。

### 記録をファイルに残した（#440）

- 前はメモリだけで、立て直すと `sai_wait` が見失い、「送信を止める」が外れ、回数と予算が 0 から数え直しだった。いまは `agent-messages.json` に送った記録・止めたこと・1 ターンの回数と量・連鎖の印を書き、止めたことも同じファイルに残る。

### 相手で回っているターンは止めない

- CLI を殺すと相手の会話が途中で切れる。

## tailnet から MCP で呼ぶ口

### `sai_sessions` に待ちと最後の記録の時刻を載せた（#323）

- Manager が本文を読まずに急ぐものを選ぶため。

### `isCrossOrigin()` を使わない

- `Origin` は MCP の仕様（DNS rebinding）として必ず検査する。`isCrossOrigin()` は CLI が Origin を付けないので歯止めにならず、代わりが capability。

### 回数を `McpSendLimiter` で縛る

- tailnet から呼ぶ側は SAI が起動したターンではないので、1 ターンの回数では縛れない。呼んだ人ごとに 10 分 5 回にした。

### 素通しのセッションに送らない

- 呼び出し元の LLM が許可を聞かないエージェントを動かせてしまう。

### `sai_wait` を 120 秒で返す

- Serve を通る 1 本の HTTP を握りすぎないため。
