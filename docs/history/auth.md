# tailnet の認証の経緯

なぜ今の形になったか（前はどうだったか・実測・レビューの指摘）。仕組みは [internals/auth.md](../internals/auth.md)。新しい経緯はこのファイルの該当する節に足す。

## タグ付きの端末を素通ししていた（#312）

- `X-Forwarded-For` があって `Tailscale-User-Login` が無いもの（Serve を通ったタグ付きの端末）を、前はループバックと同じくそのまま通していた。

## 「whois と一致しない」の 401 が頻発していた（#486）

- 前は画面を開いた瞬間の同時リクエストぶん `tailscale whois` が走り、PATH の `tailscale` が asdf の shim（1 回 2 秒）だと 12 本同時で全部 5 秒の時間切れになって、その時間切れが「`Tailscale-User-Login` が whois と一致しない」の 401 として続いていた（実測）。
- キャッシュの期限を聞き始めた時刻から数えていたので、5 秒かかった失敗は覚えた瞬間に切れていた。
- レビューで、`peer not found` が exit 1 で返ることが分かった。非 0 を全部「聞けなかった」にすると、tailnet から外した端末が直前の本人のまま 5 分通る。
