# 差分と PRの経緯

なぜ今の形になったか（前はどうだったか・実測・レビューの指摘）。仕組みは [internals/diff.md](../internals/diff.md)。新しい経緯はこのファイルの該当する節に足す。

## 差分ビューア

### base は `origin/<x>` と `<x>` の新しい方（#289）

有るかだけで `origin/*` を先にしていたら、bare clone + worktree（fetch の refspec が無く `origin/main` が作られたまま進まない。`/sync-main` が進めるのはローカルの `main`）で 24 コミット前の `origin/main` と比べ、後から入った PR まで「このブランチの差分」に出ていた（`main` にいる worktree ですら 91 ファイル。行数の要約も同じ）。`origin/HEAD` は bare clone だと未設定なので、それだけに頼れない。

### 枠の見出しを流さない（#221）

`overflow-y` をモーダル自身に付けていたころは、閉じるボタンが差分の一番下まで流れた。

### 行の箱を一番長い行の幅まで伸ばす（#514）

見えている幅で止めていたころは、横に流すとはみ出した分に追加・削除の色が付かなかった。

### 本文は最初から開く（#221）

ファイル数で決めていたころ（旧: 5 件以下）は、ブランチの差分が必ず全部閉じて出ていた。行数の予算（`AUTO_OPEN_LINES`）に変えた。

### 見えている行だけ DOM に置く（#287）

狭い画面で大きい差分を開くと重かった。headless Chrome（390×844・DPR 3・CPU ×4）で 4,000 行近く描く差分は、差分だけで約 1.7 万要素、開くまで 0.9 秒、layout 321ms（`#287` の表）。前は表示領域外の行もすべて DOM に置き、1 ファイルの開閉で全ファイルを描き直していた。

- **A1（`content-visibility: auto`）と B（狭い画面だけ予算を下げる）は入れず、A2（仮想化）にした**。#511（行コメント）・#524（他人の PR）で大きい差分を開く場面が増えたので、描く量そのものを抑える。A2 を入れれば A1 / B は要らない。
- 仮想化の単位をファイルごとにしたのは、ファイルの開閉と、ファイルごとの横スクロールの箱をいまの形のまま残すため。
- 行コメントの高さは固定でないので、コメント付き・編集中の行は見えていなくても常に置いて、置いたあとに測る。多くて数十件なので DOM の量には効かない。
- 横幅を文字数から先に決めるのは、#514 の「一番長い行の幅まで伸ばす」を見えている行だけでやると、その行が画面外に出た瞬間に幅が縮んで横スクロールが跳ねるため。
- ページ内検索（⌘F）が DOM に無い行に当たらなくなるのは諦めた。困ったら差分の中を探す検索欄を別に足す。
- 指で押せる大きさのために `.no` に付けていた上下の padding が、タッチ端末では行の高さを 26px にしていた（固定の 18px という前提が崩れる）。負の margin で打ち消して押せる範囲だけ広げる手も、行が absolute の兄弟になったので隣の行と重なって後の行が押し勝つ（レビューで指摘）。高さは広げないことにした（幅 4em は残る）。
- #617 のレビューで直したもの: 保存を effect に遅らせたら、狭い画面の「入力欄に入れる」（`clear()` と同じバッチでモーダルが閉じる）で保存が走らず下書きが残った → updater の中で同期に保存（`useLocalState` と同じ）。罫線・矢印・幾何はコーディング用の等幅が 1 セルで持つので 2 に数えるのをやめた（※ と ①〜⑳ は残す）。
- #611（#587 の残り）: 上のファイルの開閉で下のファイルがスクロール無しでずれると測り直さない（根の高さを ResizeObserver で見る）、開いた直後の 1 フレームが空箱（mount 時に 1 回測る）、同じ行で編集欄→保存したときの高さが 1 フレーム古い（`renderLine` が変わるたびに測る）、`oldPath` でしか引けないファイルで編集欄が出ない（行を探し直さず `renderLine` の行を使う）、コメントを 1 件足すと全ファイルの memo が外れる（`add` / `remove` を関数型の setState で安定させ、ファイルごとに同じ口を渡す）、`ch` の px 換算がフォント依存（CSS の `calc` に戻す）、※ ① ● ─ → を幅 1 と数える、docs の古い文。
- レビューで直したもの: ピン留めが消えても余分な高さが残る（ResizeObserver は観測する要素が無いと鳴らない）、上のファイルの開閉でスクロールせずに位置がずれた分を測り直さない（IntersectionObserver で拾う）、`ch` が親のサンセリフで解決される、絵文字の一部（✅ ⭐ など）を幅 1 と数える、`comments` を毎回作っていて memo が効かない、上に流れたファイルの全行を毎フレーム歩く。

## Codex のレビュー（#403 / #430 / #482）

- 差分を渡す口が要るので `review/start` を使う。`commit` / `custom` は画面から選ぶ材料が無いので出していない。
- ほかで開いているスレッドを断る（#430）: `review/start` の前に `thread/resume` するので、端末の TUI や共有の app-server が握っている会話を SAI の app-server が奪ってしまう。返信はそういうスレッドを端末への打ち込みか queue に回す（#329）が、レビューには対象を持ち越す口が無い。前は返信とレビューで判定を別々に書いていて、レビューの方だけ見ていなかった。0.154.0 の TUI は lock を開かないので、lock だけでは取りこぼす（端末のペインを先に足す理由）。
- SAI 自身の app-server の pid を数えない（#482）: SAI の app-server が回したターンでも `notify` は鳴り、行の `pid` はその app-server になる（0.154.0 で実測）ので、`thread/closed` で `holds()` が偽になったあとに自分を「ほか」と数えていた。
- レビューは Codex が子スレッドを作って走らせるが、`turn/started` / `turn/completed` は親のスレッドに届くことを実測で確かめた（処理中の扱いを変えなくてよい根拠）。

## 差分ボタン（#211 / #351）

- 前は入力欄の中のモデルの左に並べていて、差分が出たり消えたりで入力欄が動いた。`position: absolute` で上に浮かせ、差分があってもなくても入力欄の高さと位置が変わらないようにした。浮かせても一番下の発言に重ならないよう、ボタンがある間だけチャットを縮める。
- 開く前に大きさを出す必要があるが、本文（patch）を作る `/diff` を 3 秒のポーリングに乗せるのは重い。そこで `?summary=1` を足した。
- `ReplyBox` の `diff` をフィードに渡さないのは、フィードは返信先が `@` で動き、差分のペインは開いているセッションのものなので押しても行き先が無いため。
- フィードのバブルに出すのを「いまのブランチの PR に触れているバブルだけ」にしたのは（#280）、差分ビューアは worktree のいまの差分で、worktree を使い回して PR を何本も出すのが普通なので、古い PR のバブルに出すと別のブランチの差分が出るため。

## PR（#211 / #524 / #525 / #526 / #548 / #554）

- #525 で打ちかけに足してから移る形にしたのは、移った先の `ReplyBox` が作られたときにもう来ている `insert` を当てた扱いにするので、#511 の `commentInsert` では入らなかったため。
- #548 の印を 1 行目（リポジトリ / ブランチ）に置かないのは、長いブランチ名の省略に隠れるため（実データの画面で踏んだ）。
- #554 でフィードの見出しを「その発言を書いたときのブランチ」で引くのは、いまのブランチで引くと前の発言に別の PR が付くため。
