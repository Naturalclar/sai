# feed の経緯

なぜ今の形になったか（前はどうだったか・実測・レビューの指摘）。仕組みは [internals/feed.md](../internals/feed.md)。新しい経緯はこのファイルの該当する節に足す。

## feed/record.py

### 「直前の行」を `ts` で選ぶようにした（#439）

- 新しい日から積んで「最後の要素」を採っていたころは、日をまたいだセッションで前日の最後の行が「直前」になり、今日の行が全部飛ばされていた（実データで、重なって書かれた `permission_prompt` の 29 件すべてが「前日のファイルにも同じセッションの行がある」回だった）。
- 2 日ぶん見るのは今までどおりで、変えたのはその中のどれを採るか。

### 知らない `event` を `other` に落とす（#235）

- 以前は既定が `turn` だったため、`SubagentStop` / `session-configured` のような行が「一番新しいターン完了」を奪って一覧の「最後の発言」が空になり、`last_turn_ts` がずれて一言が消え、`turns` も水増しされていた。

### Claude の `text` をそのターンの返答に限る（#467）

- 前は transcript の末尾から最初に見つかった assistant の本文を返していて、ターンの境目（`_is_prompt_row()`）で止まらなかった。
- `Stop` フックはそのターンの最後の行が transcript に書かれる前に走るので（実データで行の `ts` の 0.1〜0.89 秒あと、中央値 +0.50 秒）、遡った先が前のターンの返答になり、人が頼んだことと無関係な「前回と同じ返事」が記録されていた（Claude の Stop 行 1397 本中 39 本、うち 22 本が前のターンの返答そのもの。セッションによっては 26 本中 17 本）。
- 古い閉じた行を先に返さない理由: 実データの `stop_sequence` は 30 件すべて Claude Code の合成通知「You've reached your … limit」だった。
- `ASSISTANT_IDLE_S` の 1.2 秒は、実測の遅れの最大 0.89 秒に余裕を持たせた値。閉じた行が来ないターンは実データで 6.9%。
- 実データ 1547 ターンで競走を再現すると、いまのターンに無い本文を返したのは 672 件（43.4%）→ 0 件。

### 質問の待ちの行に選択肢を載せる（#334）

- 前は `tool_summary()` が質問の文だけを `text` に残し、見出し・選択肢・説明・`multiSelect` を捨てていた。
- 出す条件（いまの待ちがその文のまま・SAI で答えられる質問でない）は #518 のレビューで足した。行の `resolved` は次の行まで立たないため。

### 本文の上限を 20000 字にして `clipped` を載せる（#358）

- 前は 2000 字で、実データの返答の 4.0%（47/1169）が平均 677 字・最大 3005 字ぶん読めないところで切れていた。
- しかも `record.py` の `clip()` は `aggregate.ts` の `clip()` と違って `…` を付けないので、「もっと見る」を全部開いても文の途中で終わっていることに気づけなかった。

## feed/opencode/sai.js

### 送る前に状態を空にする（#392）

- `send()` は record.py の終了を待つので、送ったあとで空にしていたころは、その間に届いた次の idle が同じ行（自分の入力つき）をもう 1 本書いていた。
- ターンを止めると同じ秒に 2 回鳴るので、止めるたびに自分のバブルと「(本文なし)」が 2 つずつ並び、ターン数も水増しされていた。1.18.30 で実測。
