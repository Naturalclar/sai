# メタ・プロフィール・未読・スキルの経緯

なぜ今の形になったか（前はどうだったか・実測・レビューの指摘）。仕組みは [internals/meta.md](../internals/meta.md)。新しい経緯はこのファイルの該当する節に足す。

## セッションのメタ

### 表示名を `-n` で渡す（#391）

- 名前はセッションに残る（実測: 付けて回すと transcript の先頭に `{"type":"custom-title",…}` が入り、次に `-n` 無しで resume しても消えない）。そのため表示名が付いていないセッションには渡さないことにした。
- 名前が `-` で始まってもフラグに化けないことは `-n "--help"` で実測した。


### 同じ名前のセッションが見分けられなかった（#572）

- 要対応の行を押したら、同じ表示名を付けた別のセッションが開いた（2026-09-30）。リンクは ID で正しかったが、行に出るのは名前・`#<project>`・エージェント・待ちの文言だけで、ID は `title`（ホバー）にしか無く、携帯では見分ける材料が無かった。手元で重なっていたのは `sai_main` の 1 組（どちらも sai の `main` worktree・ブランチ `main`。9/2〜 と 9/25〜）。
- 名前は自由に付けられる（一意を強制すると、同じ名前にしたいときに困る）ので、**重なったときだけ**添え字を足し、付けるときに知らせる形にした。
- 添え字の中身（始まった日。同じなら ID の頭）と重なりを見る範囲（同じ project の中だけ）は、issue の案のまま入れた。人が見て変えられるように PR に書いてある。

### 合成 ID のセッションもアーカイブできる（#248）

#31 は「集計の切れ方で付け先がずれる」として画面のボタンを隠していたが、合成 ID は記録時に決めて行に書き込まれ、窓でも集計でも動かないので、隠す理由が無かった（サーバ側には元から制限が無かった）。

## アイコンの履歴（#465）

- `IconCropper` は同じファイルを同じように切れば同じバイト列を出すことを実機で確かめた（中身で名前を付ければ同じ画像が 1 つにまとまる根拠）。
- 消したあとにモーダルへフォーカスを戻すのは、押したボタンが項目ごと消えてフォーカスが body に落ちると、次の Esc がモーダルに届かず App の「Esc でフィードへ」まで動いたため（実機で踏んだ）。
- `ProfileEditor` の Esc を止めるのは、名前の欄にフォーカスがある間は App 側が入力欄として無視していたので、履歴を足すまで表に出ていなかった問題。
- 失敗の理由を履歴のモーダルの中に出すのは、後ろの編集欄に書くと背景に隠れ、別のタブで消された画像を押したときに「押しても何も起きない」に見えたため。

## `/` のスキルの候補

### Codex（#402）

- Codex にもスキルがあることを v0.154.0 で実測した。
- `scope: repo` を落とす代わりに `skills/extraRoots/set` で足す手もあるが、接続ごとの設定なので別のセッションのターンにも効いてしまうので採らなかった。
- Codex だけ `$` にするのは、端末に打ち込む経路で `/` が TUI のスラッシュコマンドとして先に解釈され、スキル名が「存在しないコマンド」になるため。

### OpenCode（#393）

- `GET /command` の 1 本でスキルもスラッシュコマンドも返ることを 1.18.30 で確認した。手元では 15 件 = スキル 13 + コマンド 2 で、13 は `/skill` と同じ顔ぶれだった。
- `directory` を渡すとそのリポジトリの `.opencode/skills/` まで出ることを実機で確かめた。
