## ターン完了の行が落ちた印（#614）

- 10/1 に、SAI から起こした 2 つのターンで `Stop` の行が落ちた（#613）。子は終わっていて `replying.json` からも消えているので「処理中」も出ず、最後の発言とブランチは前の作業のまま見えた。確かめるには transcript と `ps` を手で読むしかなかった。
- issue の案は「最後の行が人の入力で、処理中でなく、子も居らず、一定時間たっている」だったが、時間だけでは長いターン・Esc で止めたターンと区別が付かない。transcript でそのターンが閉じている（`end_turn`）ことを条件にした（分からないときは出さない）。
- レビュー（#616）で、ターンの途中で別の worktree に `cd` すると `Stop` の行が別のエンティティに載り、元のエンティティに印が付くと指摘された。同じセッション ID のターン完了の行がどのエンティティにあっても、落ちていないと見るようにした。
- 要対応に数えるか・未読と `turns` を進めるかは決まっていなかったので、控えめな側（数えない・進めない）で置いた。最後の返答を子プロセスの終了と `reply.log` から補う案（issue の 1）は見せ方が決まっていないので入れていない。

## 終わったターンの手順（#605）

- 手順が見えるのは処理中の間だけで、終わると最後の返答しか残らなかった。直近の週は返信の 93% が素通しで回っていて（#582）、何が実行されたかを人が見る機会が無かった。
- 仮置き（10/2。人はまだ決めていない）: 引けないターンは「記録がありません」、ツールの出力は出さない（大きい・秘密が混ざりやすい）、危ないコマンドの印は入れない。
- issue の案は「畳んだ状態でツールの数と種類の 1 行」だったが、数は transcript を読まないと分からず、読むのは開いたときだけ（ポーリングに乗せない）なので、畳んでいる間は「手順」とだけ出し、開いたあとに数と種類を出す。
- レビュー（#663）: 始まりの時刻だけで当てていたので、Esc で止めたターンの手順が次の返答に付くことがあり、途中で入力を足したターンは半分しか出なかった。始まりから終わりまでをつなぎ、止めた跡で切るようにした。
- 行には載せない（`record.py` に手順を足すと行が大きくなり、形も変わる）。transcript から派生で読むだけなので、transcript が消えたターンは引けない。

## 落ちた返答を transcript から補う（#614 の 1・3）

- 印だけでは「終わったこと」は分かっても返答が読めず、メッセージで起こしたターンだと返答が送り元のどの口にも出なかった（10/1 の `8d0778ca…`。#583 の PR 番号が届かなかった）。
- はじめの案は「子プロセスの終了と `reply.log` から補う」だったが、端末で回したターンに効かないので、決めたこと（10/1）で出どころを transcript にした。`reply.log` は読まない。
- 補うのは 2 つ: 行が無い、と、行はあるが本文が空（#613 の案 2。締切に間に合わなかったときに書かれる行）。
- 古いターンは transcript を頭から読むしかない（末尾の読み方は最後のターンしか分からない）。手元の transcript は数十〜数百 MB あるので、応答を待たせず裏で読み、結果を覚える形にした。実データ（10/1 と 9/30 の行）では、確かめたかった 4 件（チキ 11:45・くらら 11:53 / 17:32・かなで 17:32）のほかに、`Prompt is too long` や認証切れの合成の返答で終わったターンも補われた（どれも閉じた行で、そのターンの実際の最後の返答）。
- レビュー（#627）の 3 点を直した: 一覧の上書きを最後の行ではなく最後のターン完了と比べる（`入力待ち` の行が後に来ると補った返答が一覧に出なかった）、補った返答より前の待ちを畳む（「待機中」のまま要対応に数えていた）、決まらない候補を読む前に間引く（間引きが読んだ後にあり、ポーリングのたびに末尾を読んでいた）。
- 決めたこと: バブルに「記録から補った」の印・要対応は下段（数えない）・未読は進める・`turns` は進めない。補えたら見出しの「完了の記録なし」は出さない（「返答はここに出ていない」が嘘になるため）。
