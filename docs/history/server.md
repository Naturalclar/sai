# server の経緯

なぜ今の形になったか（前はどうだったか・実測・レビューの指摘）。仕組みは [internals/server.md](../internals/server.md)。新しい経緯はこのファイルの該当する節に足す。

## 終わり方（shutdown）

- #296: 前は 2 回目の C-c でも同じ `close` を呼ぶだけで、連打しても何も起きなかった。いまは 2 回目はすぐ終わる。
- 実測では、ポーリングする keep-alive もアイドルの keep-alive も `close()` が自分で切って 3ms で終わり、抜けられないのは「リクエストを最後まで送っていない接続」（ブラウザの先読み・送信途中）だった。
- listen だけ消えて node が生き続けると、`/sync-main` が打った起動コマンドが foreground の pnpm に飲まれ、SAI が止まったままになる。これが「必ず終わる」にした理由。

### `opencode serve` を落とす・引き継ぐ（#457 / #440）

- 実測（2026-09-25）で、SAI が起こした `opencode serve` を落とさないと、ppid 1 の孤児になって走り続けた（立て直すたびに 1 本ずつ増える。保留中の許可もその中に残る）。一方 `codex app-server --stdio` は親が死ぬと stdin のパイプが閉じて自分で終わるので、触らないことにした。
- serve の出力を pipe のままにすると、SAI が落ちたあとに書いた瞬間に EPIPE で死ぬ。そのため `opencode-serve.log` に書かせる。
- 実機で、ターンの途中の C-c のあとも serve が生き残り、立て直した SAI が同じ serve を引き取って「止める」が効くこと、回していないときの C-c では落ちてファイルも消えることを確かめた。

## 行の読み込み（store.ts）

## 本文の検索（rows/search.ts）

- #230: 索引を持たないのは、実測で 9 日ぶん 1.52MB・本文 0.42MB だったため。`store.rows()` のパース済みの行を舐めるだけなので、`server/` の依存ゼロも保てる。
- `thinking` と待ちの行を見ないのは、考えたことと機械的な要約に当ててしまうため。
- アーカイブ済みも出すのは、探しているのは見失ったものなので、除くと目的に反するため。

## 使用量（local/usage.ts）

- #216 / #250: API は叩かない。Claude の割合を API から取らないのは意図的で、`claude` CLI に `usage` のサブコマンドは無く、TUI の `/usage` が叩く口は OAuth のトークンが要る（「SAI は外に出さない」）。
- `quotaLimits` は弾かれたときにしか空でないので、割合はステータスラインから別に取る（#250）。
- ステータスラインの割合は Claude が動いている間しか更新されないので、`resets_at` を過ぎたものと 8 日より古いファイルを捨てる。
- `statusLine` は 1 つしか持てない（Codex の `notify` と同じ問題）ので、既存のものがある人向けのラッパーを README に置いた。
- Codex の rollout は手元で 12MB あったので、末尾 64KB だけ読む。
- #275: `UsageStore` のコンストラクタが置き場に既定値を持っていたころ、テストが feed dir を省いて本物の `~/.agent-feed` を読み、`usage-claude.json` のあるマシンでだけ落ちていた。それで既定値を外し、本番の組み立ては `createApp` にだけ置いた。
- #347: Claude Code が `rate_limits` に `five_hour` を載せない日があり、5 時間だけを見ていたので、パネルには週のゲージが出ているのにチップから Claude が消えていた。それで 5 時間が無ければ週に落とす。
- #347: Claude を先に並べ、狭い画面で入らないときに落とすのは Codex 側にした。実測では 320px でも両方 1 行に入る。
- 「ステータスラインを設定すると出ます」の案内を割合が 1 つも無いときだけにしたのは、週だけ取れている人には嘘になるため。

## フックの配線のずれ（local/claudeHooks.ts）

- #567: 行からは分からない。`SessionEnd` は `/clear`・`/exit` でしか書かれず、9 月の実データで 0 件だったのが、実は繋がっていなかった。そのため設定ファイルを見る。
- 本物の設定を読むのを `main.ts` だけにし、`createApp` の既定を `NoClaudeHooks` にしたのは、テストの結果が回したマシンの設定で変わらないようにするため。
- `/setup-sai` が `node server/hooksCheck.ts` を呼ぶのは、規則をスキルに書き写さないため。
