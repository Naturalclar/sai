# 画面（SAI）

セッション一覧とチャットの見え方、返信の届き方、許可・質問への答え方、差分の見方、使用量、一言コメント。セットアップは [README](../README.md)。

## 1画面: 左にセッション一覧、右にチャット

Slack と同じ形。左のサイドバーがチャンネル一覧（先頭に固定の「フィード」「要対応」、その下にセッション）、右がチャット。URL は hash で、`#/` と `#/feed` がフィード、`#/todo` が要対応、`#/s/<id>` が選んだセッション。横幅 900px 未満では一覧かチャットのどちらかだけになり（`#/` が一覧、`#/feed` / `#/todo` / `#/s/<id>` がチャット）、チャット側に「← 一覧」が出る。

キーボードでも動ける。`↑` / `↓`（vim 風に `k` / `j` でも）で、**いま開いているセッションを起点に**サイドバーの並びのまま隣へ移り、右のチャットも変わる（選んだ項目が見えるようにサイドバーがスクロールする）。**固定の「フィード」「要対応」もサイドバーの見た目どおりセッションより上の項目**として扱うので、一番上のセッションで `↑` を押すと要対応へ、そこからもう一度 `↑` でフィードへ行き、フィードで `↑` を押しても下には動かない（`↓` で戻る）。末尾で `↓` は止まる（回り込まない）。開いているセッションが一覧に無いとき（絞り込みで隠れている）は先頭のセッションへ。`Esc` でも一気にフィードに戻れる。入力欄にフォーカスがある間はそちらの操作（caret の移動、`@` の候補）なので効かない。サイドバーを閉じていても効く。

**`→` で返信の入力欄へ、空の入力欄で `←` で一覧へ戻る**（#204）。`↑↓` で選び、`→` で書き始め、書かずに `←` で戻る、という往復ができる。`←` が効くのは**本文が空**のときだけで、書きかけの文中では今までどおりカーソルが左に動く（画像だけ添えて本文が空なら戻れる。添付は消えないので `→` で戻ってくればそのまま送れる）。候補メニュー（`@` / `/` / `:`）が開いている間と IME 変換中、`⌘←` / `⇧←` のような修飾キー付きは触らない。戻った項目には枠が付く。入力欄が無いセッション（アーカイブ済み、再開できないもの）で `→` を押しても何も起きない。サイドバーを閉じていれば `←` で開いてから当て、狭い画面では `→` がチャット側・`←` が一覧側への移動を兼ねる。

**`⌘K`（`Ctrl+K`）で検索して移動できる。** モーダルが出て、フィードとセッションを名前で絞り込み、`↑` `↓` で選んで `Enter` でその画面へ飛ぶ（`Esc` かもう一度 `⌘K` で閉じる）。**入力欄にフォーカスがあっても効く**（`⌘\` と同じ）。絞り込むのはセッションの表示名・タイトル・リポジトリ名・ブランチ・ID で、空白で区切ると AND になる（`sai 画像`）。候補はモーダルを開いたときに**絞り込み無しで取り直す**（直近 90 日、アーカイブ済みも含む）ので、サイドバーの絞り込みで隠れているセッションも探せる。アーカイブ済みには印が付く。候補は本物のリンクなので、⌘クリックで新しいタブにも開ける。**移動だけ**で、アーカイブや返信のようなコマンドは実行しない。

`⌘K` は **2 つの群**を出す（#230）:

| | 何を探すか | いつ出るか |
| --- | --- | --- |
| **セッション**（上） | 表示名・タイトル・リポジトリ名・ブランチ・ID | 開いたときの一覧を手元で絞るので**打つたびに即座に** |
| **発言**（下） | 会話の本文（自分の入力とエージェントの返答） | サーバに聞くので**打ち終わってから**（250ms）届いて下に足される |

`↑` `↓` は 2 つの群を通しで動くので、境目を意識しなくていい。発言の候補を選ぶと、**そのセッションを開いて当たった発言まで送り、そこをしばらく光らせる**（`#/s/<id>?ts=…`）。長いセッションでも「どこにあったか」を探し直さずに済む。

- 探すのは `text`（エージェントの返答）と `user_text`（自分の入力）だけ。**`thinking` は探さない**（言ったことではなく考えたことなので、「言っていないこと」に当たってしまう）。**待ちの行**（`許可待ち: Bash: …`）も機械的な要約なので探さない
- **アーカイブ済みも探す**（探しているのは見失ったものなので、除くと目的に反する）。印は付く
- 既定は直近 90 日。多すぎるときは新しい方から 100 件で切り、その旨を出す
- 飛び先は**当たった側の発言だけ**（`#/s/<id>?ts=…&side=me|agent`。#503）。1 本の行から自分の入力と返答が同じ時刻で 2 つ出るので、当たった方に着いて、そちらだけ光る

### セッションを横に並べて見る（#633）

広い画面（900px より広い）では、チャットの領域を左右に分けて**セッションと要対応を 3 つまで並べられる**（tmux の split pane のように）。セッションのペインはそれぞれが自分の入力欄と差分のボタンを持ち、3 秒ごとの取得も別々に回る。

| やること | 操作 |
| --- | --- |
| 横に並べて開く | サイドバーの項目（セッションと「要対応」）を **⌘ + クリック**（Windows / Linux は Ctrl + クリック）、または項目に乗せたときに出る枠のボタン（アーカイブの左） |
| 横に分ける | **`%`**（tmux と同じ）。新しいペインにフォーカスが移り、サイドバーの並びで次の、まだ出していないセッションが入る（末尾まで無ければ先頭から探す）。もう 3 つ並んでいる・出すものが無いときは何もしない |
| 検索から横に開く | `⌘K` → **`⌘Enter`**（`Enter` は今までどおりフォーカスのあるペインに開く。発言の当たりなら、その発言まで送る） |
| フォーカスのあるペインの中身を入れ替える | ふつうのクリック・`↑↓` / `j` `k`（今までどおり） |
| フォーカスを移す | **`h`** / **`l`**（左 / 右。端では止まる）、またはそのペインの中を押す（入力欄にフォーカスが入っても移る） |
| 入力中にペインを移る | **`Ctrl+1`** / **`Ctrl+2`** / **`Ctrl+3`**（左から数えた番号のペインの入力欄へ） |
| 閉じる | **`x`**、またはペインの右上の ×。1 つになれば今までの画面に戻る |

- **フォーカスのあるペインが「いま開いているセッション」**で、上の辺に色が付く（無い方は見出しが薄くなる）。URL・タブの題名・`↑↓` の起点・ヘッダの「更新 hh:mm」・`→` で入る入力欄は、どれもフォーカスのあるペインのもの。サイドバーでは、フォーカスの無い方に出ているセッションにも薄い線が付く。
- **同じセッションは 2 つ並べない。** もう並んでいるセッションを選ぶと、そのペインへフォーカスが移るだけ。
- 横に並べて開くと、フォーカスのあるペインの右に足され、フォーカスは開いた方へ移る。**もう 3 つ並んでいるときは右隣のペイン（右端にいれば左隣）の中身を入れ替える**（いま見ているものは残る）。
- **並びはブラウザに残る**（localStorage の `sai.panes`）。再読み込みしても戻り、同じブラウザの別のタブとも共有する。**URL には載せない**ので、「戻る」で戻るのは見ているセッションだけで、並びは戻らない。
- **`%` `h` `l` `x` は入力欄で打っている間は効かない**（`j` `k` と同じ扱い。文字として入る）。`Ctrl+数字` だけは入力中でも効く。モーダル（⌘K など）を出している間はどれも効かない。`←` `→` はペインの移動に使わない（「一覧へ / 入力欄へ」のまま）。Windows / Linux のブラウザは `Ctrl+数字` をタブの切り替えに使うので、そこでは効かないことがある。
- **要対応もペインの 1 つとして出せる**（サイドバーの「要対応」を ⌘ + クリック、要対応を開いて `%`、ふつうのクリックならフォーカスのあるペインが要対応に入れ替わる）。**要対応の行からセッションへ飛ぶリンクは、隣のペインに開く**（要対応は残る）: 右隣があればその中身を入れ替え、無ければ右に 1 つ足す（足せなければ左隣を入れ替える）。要対応だけを開いているときも同じで、行のリンクを押すと右にそのセッションが並ぶ。狭い画面では今までどおりそのセッションへ移る。
- フィード・PR・新しいセッションを選ぶと**全幅でその画面**になり、セッションか要対応に戻ると並びも戻る。狭い画面（900px 以下）では分けず、フォーカスのあるペインの 1 つだけが出る。
- **許可の `⌘Enter` を受けるのはフォーカスのあるペインだけ**（2 つのペインに許可待ちが出ていても、押した 1 回で両方は通らない。要対応のペインの一番上の答え待ちも同じ）。**モーダルの中で押した `⌘Enter` は許可に使わない**（⌘K の `⌘Enter` は「横に開く」）。
- 既読は、並べて見えているセッションのどれも進む（最下部まで見えたときだけ、は今までどおり）。
- **差分は 1 つだけ**で、右端に出る。出るのは差分のボタンを押したペインのセッションのもので、**フォーカスを移しても付いていかない**（別のペインの差分のボタンを押すと入れ替わる）。行へのコメントは差分のセッションの入力欄に入る。そのペインを閉じると差分も閉じる。**モーダルになるかは画面全体の幅だけで決まる**（#647。900px 以下ならモーダル、それより広ければ並べていても右のペイン）。差分を出すとチャットのペインはそのぶん狭くなるので、足りなければペインを閉じるかサイドバーを畳む。
- フィードはペインに出せない。上下に分けるのもまだ無い（`"` を空けてある）。

### 発言のメニュー（リンクと本文のコピー）

発言（自分の入力もエージェントの返答も。セッション画面とフィードの両方）の右上の `⋯` から、**その発言へのリンク**と**本文**をコピーできる（#503）。別のセッションへの指示や issue に「この返答を見て」と貼るとき、画面を開いて探し直したり本文を範囲選択したりせずに済む。

- リンクは `<いま開いている SAI>/#/s/<id>?ts=<時刻>&side=me|agent`。開くとそのセッションのその発言まで送って光らせる（検索の飛び先と同じ口）。**7 日より前の発言でも着く**（その行まで描く）。フィードで作ったリンクもセッション画面を開く
  - 発言を名指しする鍵は**時刻とどちら側か**。バブルの内部の鍵（`時刻:位置`）は、7 日の窓が動いたり「前の 7 日を表示」で広げたりするとずれるので使わない
  - 頭は開いている SAI のもの（手元なら `127.0.0.1`、tailnet の Serve 越しならそのホスト）。開けるのは SAI に届く人だけで、外に出す話ではない
- 本文は**記録の文そのもの**（エージェントは Markdown の元の文。一言ではない）。自分の入力に添えた画像のパスは外す（このマシンの置き場を指すので、よそに貼っても開けない）。記録の時点で切れている本文（#358）はそう書き添える
- クリップボードが使えないとき（tailnet の素の IP の `http://` など、安全なコンテキストでない）は、リンクを選べる欄で出す
- ホバーで出る（時刻と同じ）。**ホバーの無い端末では常に出す**（本文と重ならないよう右を空ける）。待ちのバブル・区切り線には出さない
- 閉じ方は見出しの `⋯` と同じ（外側を押す・Esc。Esc で画面は移らない）
- セッション画面の返答には「**ここから未読にする**」もある（#502。下の「未読」）

### 未読（#502）

フィードも一覧も、読んだものと読んでいないものが同じ顔で流れていたので、**セッションごとに「どこまで読んだか」を 1 つだけ**持つ（行ごとには持たない）。

- **数えるのはエージェントの返答（ターン完了）だけ**。待ち・自分の入力・終わりの区切りは数えない。「待機中」（相手が人を待っている）とは**別の軸**なので両方出る
- 一覧の項目に「**未読 N**」。窓（既定 7 日）の中の返答から数える
- **既読になるのは、そのセッションのチャットを最下部まで見たとき**（タブが見えているときだけ）。フィードを流し読みしただけでは既読にしない（そうしないと未読が一瞬で消える）
- セッション画面には、**開いたときの印**より新しい最初の返答の前に「**ここから未読**」の線を引く。読んだそばから印は進むが、線は開いている間そこに残る
- 返答の `⋯` の「ここから未読にする」で、その返答の直前まで印を戻す（線もそこへ動く）。押したあとは、**そのセッションを離れるまで自動の既読を止める**（最下部にいると押したそばから既読に戻ってしまうため）
- 印は `~/.agent-feed/read-marks.json` に持つ（**立て直しても消えない**。Mac と携帯で揃う）。**既読は前にしか進めない**（別の端末で先まで読んだのを、古い画面の自動の既読で巻き戻さない）。戻すのは「ここから未読にする」だけ
- 入れた直後は**その時点まで読んだ扱い**（印の無いセッションは、ファイルを作った時刻 `since` まで読んだことにする。入れた瞬間に 7 日ぶんが全部未読にならないように）
- 通知は別の話（#341 / #342）
- **2 文字から**（1 文字だと全部に当たってうれしくない）
- 索引は持たず、毎回そのぶんの行を舐める。実測で 9 日ぶん 1.52MB（本文 0.42MB）なので一瞬で、`server/` の依存ゼロも保てる

サイドバーはヘッダ左端の「≡」か `⌘\` / `Ctrl+\` で折りたためる（閉じた状態は localStorage に残る。開閉は 0.2 秒で滑らかに動き、OS で「視差効果を減らす」にしていれば即座に切り替わる）。閉じている間はチャット側に「← 一覧」が出て、押すとページは変えずにサイドバーが開く。狭い画面ではこの開閉は効かない（一覧かチャットのどちらかだけ、のまま）。

**狭い画面（900px 未満）のチャット見出しは 2 行に畳む**（#274）。1 行目が `←`（一覧へ）・アイコンと表示名（無ければ `#sai`、あれば `#sai` を小さく添える）・状態の印（別のマシン・合成・端末・待機中・返信中・アーカイブ・`default` 以外の許可モード）・`⋯`、2 行目が題名 1 行（押すと全文）。エージェント・リポジトリへのリンク・使ったモデル・ブランチ・期間とターン数・セッション ID と出どころ（`payload` など）と、操作（アーカイブ・表示名とアイコン・許可されているもの・一言の性格・思考を全部開く）は `⋯` のパネルに入る。見出しはスクロールしない場所なので、全部並べていた頃は 390px 幅で見出しだけ 283px になり、チャットが画面の 1/3 を切っていた。**幅が足りないときは名前の側を省略し、状態の印は省略しない**（素通しの `bypassPermissions` を選んだまま忘れていないか見えるように。#253）。一言の全体の設定（既定の性格・Linear の workspace）も、狭い画面ではヘッダの 2 行目ではなく右上の自分のメニューの中に入る。

サイドバーの一覧は**リポジトリごとの塊**（#364）。見出し（リポジトリ名・中の件数・要対応の数）を押すと畳める。**塊が 1 つでも見出しは出す**（並びが場合によって変わらない方が読みやすく、畳む場所もいつも同じ）。**既定は全部開いた状態**で、畳んだものだけが localStorage に残る（新しいリポジトリのセッションが増えても勝手に畳まれない）。塊の順は**中で一番新しいセッション**の順、塊の中は新しい順。どのリポジトリか分からないセッション（origin の無い worktree）は「その他」にまとまる。**畳んでいても中の「要対応」の数は見出しに出る**（畳んで見落とさないため）し、`↑↓` は畳んだ中には入らない。

サイドバーの1項目 = 1エンティティ = **(セッション, リポジトリ)** の組。新しい順。同じセッションIDが別リポジトリに現れても（IDの衝突や cwd の移動）、リポジトリごとに別の項目になる。IDは `<セッション>@<リポジトリ>`。

| 出すもの | 出どころ |
| --- | --- |
| セッション / ブランチ | `repo` / `branch`。`repo` は GitHub のリポジトリ名ではなく worktree のディレクトリ名（`dev-worktree-c` など）なので、画面では「セッション」と呼ぶ。ブランチが途中で変わったら最後の値を出して「+N」。先頭の色の点が `agent` |
| 最終更新 · ターン数 | 最後の `ts` と、ターン完了の行数（待ち・再開の行は数えない） |
| モデル（画面2の見出しだけ） | 一番新しいターンの `model`。途中で変わっていれば「+N」（マウスを乗せると順に全部）。変わった位置のバブルにもモデル名が小さく出る。一覧とフィードには出さない |
| タイトル | 一番新しい `user_text` の1行目。画面から返信しても端末で続きの指示を打っても、次のターンが記録された時点で最後の入力に変わる。`user_text` が無ければ `first_user_text`、それも無ければ最初の `text` の1行目。60文字で切る |
| 最後の発言 | **最後に誰が何を言ったか**（#300）。**自分が返信したら、次のターンを待たずに自分の返信**（`あなた: …`。プロフィールの名前があればそれ）: SAI から送った返信は送った瞬間から、端末で打った Claude への入力は入力の行が届いた時点から（Codex / OpenCode は入力だけの行が無いので、端末で打ったぶんはターンが終わるまで分からない）。ターンが終わるとエージェントの返答（最後の `text` の1行目。Markdown の記号は落とす。一言があればそれ）に戻る。最初の指示は題名と同じ文になるだけなので出さず、返答は今までどおり 2 ターン目から。失敗した返信は出さない |
| 印 | `session_source` が `synth` なら「合成」。最後の行が待ちの行（`waiting`）なら「待機中」（マウスを乗せると何を待っているか。**`入力待ち` はここに出ない**。#438）。画面からの返信を処理中なら「返信中」。まだ読んでいない返答があれば「未読 N」（#502）。そのセッションのブランチから open な PR が出ていれば `#番号`（#548）。アーカイブ済みなら「アーカイブ」（「アーカイブ済みを見る」のときだけ出る）。**別のマシンで記録されたものなら `@<host>`**（#114） |
| アーカイブ | 項目にマウスを乗せると右上に箱のアイコン。押すと一覧とフィードから隠れる（新しい行が届けば自動で戻る）。タッチ端末では項目を左にスワイプすると右からレールが出て、途中で止めればアイコンを押す、幅の半分近くまで引いて離せばそのまま実行（Gmail と同じ）。アーカイブ済み一覧では同じ操作で「戻す」。**合成 ID（`synth`）のセッションにも出る**（#248。以前は隠していたが、合成 ID は `record.py` が記録時に決めて行に書き込むので `days` の窓や集計の切れ方で変わらない。アーカイブは表示の都合なので、再開できるか（`replyBlockedReason`）とは別） |
| アーカイブ後も継続 | **アーカイブしたのに、そのあとも返信が続いているセッション**の印（#583）。アーカイブは新しい行が届くと黙って一覧に戻るので、片付けたはずのセッションに送り続けていても分からなかった。サイドバー・要対応の行・チャット見出し（狭い画面の 1 行目にも）に出る。セッション画面では入力欄の上に「9/4 にアーカイブしたセッションです。」の 1 行が出て、**［このまま使う］** でアーカイブの印を外す（以後は出ない）。同じ worktree にアーカイブのあとで始まったセッションがあれば、一番新しいものへのリンク（「sai_main（9/25〜）を開く」）も並ぶ。**返信は止めない**し、送る前の確認も挟まない |
| 完了の記録なし | **ターンは終わっているのに、ターン完了の行が記録されず、返答も補えなかったセッション**の印（#614）。`Stop` フックが間に合わないと行が落ちる（#613）。**返答は Claude の transcript から補って出す**（下の「記録から補った」）ので、この印が出るのは transcript にそのターンの本文が無かったときだけ。出すのは分かるときだけ（記録の最後の行が人の入力で、そのあとに transcript の上でターンが閉じていて、閉じてから 1 分たっている。回っている・Esc で止めた・transcript が読めない・別のマシン・SAI が返信を回している、では出さない）。要対応・未読・`turns` には数えない。Claude だけ |
| 記録から補った | **ターン完了の行が落ちた・行はあるが本文が空だったターンの返答を、Claude の transcript から補ったバブル**に付く小さい印（#614）。補うのは transcript でそのターンが閉じている（`end_turn`）ときだけで、入力の時刻で突き合わせるので**前のターンの返答は出さない**。端末で回したターンにも効く。補った返答は、一覧では「最後の発言」になり、要対応では「終わって次を待っている」の下段に出る（バッジ・題名・通知には数えない）。**未読は進む**（終わったことを知らせる）が、**`turns` は進まない**（`Stop` の行だけで数える）。セッション同士のメッセージの返答としても送り元に届く（画面の返答・次のターンの頭・`sai_wait`）。**記録（JSONL）には書かない**。最後のターンは閉じてから 1 分待って出し、古いターンは裏で transcript を読み終えてから出る。別のマシンのセッションは補わない |

絞り込み（リポジトリ / worktree / エージェント / 日付 / 日数）はサイドバーの上。**リポジトリ**は行の `project`（`Naturalclar/sai`）で、**複数選べる**（#529。押すとメニューが開き、項目を押すたびに入れ外しする。「すべて」で全部外す。閉じているときは `#sai` / `#sai +2`）。bare + worktree の構成でも worktree ごとに分かれない。どのリポジトリか分からないセッション（`cwd` が消えている古い行）は候補に出ず、リポジトリで絞ると外れる（一覧には worktree 名で並ぶ）。**worktree** は行の `repo`（toplevel の basename）で、同じリポジトリに複数あるときだけ出る。件数は「N / M 件」（M は絞り込み前）。「アーカイブ済みを見る」を押すとアーカイブ済みのセッションだけが薄く出る（既定では出ない）。項目にマウスを載せる（かフォーカスする）と右上に「アーカイブ」が出て、セッションを開かずにその場でアーカイブできる（「アーカイブ済みを見る」中は「戻す」）。フィードのリポジトリはここで選んだものに従う。フィードの日数だけはチャット側の右上で選ぶ。

**リポジトリはフィードの見出しからも切り替えられる**（#215）。前は `#sai` と読むだけで出ていた所がそのままボタンになっていて、押すと候補（+「すべて」）が出て、複数選べる（#529）。**触るのはサイドバーと同じ絞り込み**（`filters.projects`。部品も同じ `ProjectPicker`）なので、切り替えたあとサイドバーに戻れば同じものが選ばれている（絞り込みが 2 つに増えるわけではない）。狭い画面では一覧（`#/`）とフィード（`#/feed`）が別の画面なので、これが無いとリポジトリを変えるのにいちいち一覧へ戻ることになる。閉じているときは短い名前（`Naturalclar/sai` → `#sai`）、メニューには `owner/repo` の全体を出す（別のオーナーの同名リポジトリと見分けが付かなくなるため）。メニューを開けている間の `↑↓` `Enter` `Esc` はメニューの中で使い切る（そのまま通すと裏のセッション移動が動く）。候補は `App` が持っている一覧の `filters.projects` をそのまま渡すだけで、取得は増えない。いま選んでいるものは候補に無くても必ず並べる（`web/src/projectChoices.ts`。その窓に行が 1 本も無いと `facets` から落ちるので、消すと自分で解除できなくなる）。

## 要対応（#/todo）

**いま自分を待っているものだけ**を、待たせている順（古い順）に並べた画面。セッションが増えるとサイドバーの「待機中」の印を目で探すことになり、狭い画面ではなおさら見落とすため。サイドバーの「フィード」の下に固定で並び、**0 件でない間は件数のバッジが付く**。

出るのは 3 種類で、見た目（左の色帯）でも文言でも分けている。行の見出しには**どのエージェントのセッションか**（サイドバーと同じ色の点と名前。狭い画面では点だけで、名前は `title`）も出す（#520。答え待ちはバブルのアバターで分かるので出さない）。**上段が「答えを待っている」（答え待ち・待機中）、下段が「終わって次を待っている」**（#438）:

| | 出どころ | ここで答えられるか |
| --- | --- | --- |
| **答え待ち** | `/api/sessions` の `approvals` | **答えられる。** 許可・質問のバブル（`ApprovalBubble`）がその場に出るので、セッションを開かずに [許可] や選択肢を押せる。`⌘Enter` が効くのは一番上の 1 つだけ（フィードと同じ） |
| **待機中** | `SessionSummary.waiting`（記録の行から見た待ち） | **バブルは出せない**（選択肢が SAI に届いていない）が、**返信欄からは打てることが多い**。その会話に返信できるなら「開いて返信欄から答えられます」、再開できないセッション（合成 ID など）なら「端末で答えてください」と添える |
| **終わって次を待っている** | **最後の行がターン完了**か `入力待ち` の行（#438 / #513。`shared/todoItems.ts` の `awaitsNext()`）で、返信が処理中でない（端末に打ち込んだ返信も含む）もの。文言は最後の発言（一言があればそれ）、`入力待ち` ならその文言 | 詰まっていないので**答えるものは無い**。「開いて次の指示を送れます」（返信できないセッションなら「端末で続きを打ってください」）と添えるだけ |

- **「終わって次を待っている」は下段に分け、バッジ・タブの題名・通知には数えない**（#438）。Claude は**ターンが終わって 60 秒放置されると `idle_prompt` の `Notification` を鳴らす**ので、これを待ちとして数えると「返信が 1 回終わるたびに要対応が 1 件増える」ことになる（実データ 15 日ぶんで、待ちの行 331 件のうち 137 件が `入力待ち`、その 134 件は同じセッションのターン完了の直後だった）。tmux のペインがあるセッションは `WaitingSettle`（下記）が入力欄を見て偶然畳んでいたが、**ペインの無い端末では次の入力まで何時間でも残っていた**。数えるぶんの判定は `shared/todoItems.ts` の `pendingItems()` 1 つで、バッジ・題名・通知が同じものを通る
- **「終わって次を待っている」は `入力待ち` だけでなく、最後の行がターン完了のセッションも数える**（#513）。`idle_prompt` は**端末の TUI で開いた Claude が 60 秒放置されたとき**にしか鳴らず、SAI から返信した `claude -p`・Codex・OpenCode は鳴らさないので、`入力待ち` だけを見ていたころは終わっているセッションのほとんどが下段に出なかった（実測で直近 7 日のターン完了 360 本に対して `入力待ち` 17 本、一覧 20 件のうち下段に出ていたのは 1 件で、判定を変えると 15 件）。ターン完了のあとに次の入力・`SessionEnd`・待ちの行が来ていれば、**最後の行の種類**（集計の `last_kind`）が変わるので自然に外れる（時刻では比べない。行の `ts` は秒までなので、同じ秒に届いた入力や `/clear` を見分けられない）。並びは**終わった時刻の古い順**（上段と同じく待たせている順）で、絞り込み（日数・リポジトリ）とアーカイブ済みを除くのはサイドバーの一覧と同じ
- **「終わって次を待っている」の行は、その場でアーカイブして片付けられる**（#527。行の右端の `TodoArchiveButton`。中身はサイドバーと同じ `useArchive`）。要対応はアーカイブ済みを出さないので、押せば次のポーリングで行ごと消える。**記録は消さず、新しい行が届けば自動で戻る**（SAI に「削除」は無い。記録の正本は record.py）。上段には出さない（待っているものを片付けると、止まったまま見えなくなる）
- **未読の返答があるセッションは、答え待ちのすぐ下の「未読」の段に上げる**（#551）。並びは 答え待ち → 未読（待機中も終わったものも）→ 待機中 → 終わって次を待っている で、段の中は待たせている順のまま。終わったセッションの返答を読んでいないと下段の奥に埋もれていたため。**並びを変えるだけで、バッジ・タブの題名・通知の数は変えない**（未読の「終了」を数えると、返答を 1 回読まないだけで通知が鳴る）。行の区分も変えないので、返信欄を最初から開くのは今までどおり「終了」の行だけ。行には一覧と同じ `未読 N` の印が付く（答え待ちは未読でも一番上なので付けない）。段分けは `shared/todoItems.ts` の `todoSections()`。この画面を開いただけでは既読にならない（既読はセッション画面で最下部が見えたときだけ。#502）
- **一言（要約）が出ている「終了」の行は、もとの本文を行の下に開ける**（#537。`元の文`）。一言だけでは次に何を頼むか決めきれないことがあり、前はセッション画面に移るしかなかった。一覧が持っているのは本文の 1 行目の 120 字だけなので、**押したときに 1 回だけ** `GET /api/sessions/<id>/turn?ts=<last_turn_ts>` で取る（ポーリングには載せない）。描き方はバブルの「詳細」と同じ Markdown で、長ければ折りたたむ。画像は印と名前だけ。出す行は `web/src/todoRowSource.ts` の `sourceTs()` が決め、**行の文言が一言のときだけ**（`入力待ち` が出ている行・一言の無い行・上段の待ちには出さない）

- **待機中と「終わって次を待っている」は、返信欄から打てるものなら行の下でそのまま送れる**（#522）。その行の下に**セッション画面と同じ返信欄**を出す（送り先はその行のセッションに固定）。**「終わって次を待っている」の行は最初から開いていて**、「返信を閉じる」で畳める。待機中は「返信する」を押したときだけ開く。**押して開いた返信欄にはフォーカスが入り、そのまま打ち始められる**（打ちかけがあれば末尾から。最初から開いている行にはフォーカスしない）。開け閉めは行ごとで、送って並びから消えた行は、戻ってきたら既定（終わった行なら開いた状態）に戻る。モデル・許可モード・画像・`/` のスキル・次の案もそのまま使え、**打ちかけはセッション画面と同じ鍵**なので行き来しても続きから打てる（↑ の履歴だけは出ない。この画面は行を取りに行かないため）。送る仕組みも同じ `useReply`（端末の打ちかけの確認・預かり・失敗したら戻す）で、**画面の側で持つ**: 送ると行は次のポーリングで「処理中」として並びから消えるので、上に「『名前』に送りました」を出し、失敗して行が戻ってきたらその行の下に理由と「入力欄に戻す」を出す。**狭い画面では開かず、セッション画面へのリンクにする**（入力欄とキーボードで画面がほぼ埋まる）。答え待ちは行の中のボタンで答えるので出さない
- **「SAI からは答えられない」とは言わない**（#232）。端末（tmux）で開いていればそのペインに打ち込めるし、開いていなくても `-p` / `codex queue` で再開できる。判定は返信欄と同じ `replyBlockedReason()` を使う（`TodoItem.replyable`）
- **別プロセスの返信を処理中のセッションは「待機中」を出さない**（#232）。`claude -p` の許可・質問は必ず `--permission-prompt-tool` を通るので、答え待ちがあれば「答え待ち」の側に載っている。載っていないなら待っているのではなく動いている。行の `waiting` は**待ちの行のあとにターン完了の行が届くまで消えない**（許可や質問への回答は `UserPromptSubmit` ではないので `record.py` は再開の行を書かない）ため、これをしないと答えたあとも残り続ける。端末に打ち込んだ返信（`replying[].via === 'terminal'`）は SAI に口が無く行の `waiting` しか手がかりが無いので、そのまま残す
- **`WaitingSettle` は `waiting` だけを見る**（#438）。`入力待ち` は `waiting` に入らなくなったので、端末の入力欄を読みに行く対象からも自然に外れる（挙動は変えていない）
- **端末で答えたら、次のターンを待たずに消える**（#255）。行の `waiting` は答えても消えない（上のとおり再開の行が書かれない）ので、**端末で開いていて行の上では待っているセッションだけ、ペインを見て畳む**（`server/reply/waitingSettle.ts`）。ダイアログが消えていれば人が答えたということなので `waiting` を空にする。**分からないときは畳まない**（入力欄が読めない・ペインが消えた・別のプロセスになった、は全部「残す」側）。畳むのは応答を組み立てるときだけで記録は触らないので、**要対応・サイドバーの「待機中」・チャット見出しが同時に**正しくなる。`SAI_TERMINAL=0` なら見に行かない
- **OpenCode は「答える相手が居るか」で畳む**（#422）。OpenCode の待ちは必ず許可待ちで、**保留は聞いてきたプロセス（`opencode serve` か TUI）のメモリの中にしか無い**。そのプロセスが消えると誰も答えられないが、記録には `permission.asked` の行が残るので、いままでは要対応に**永久に 1 件**残っていた（実データで 1 件あった）。そこで **待ちの行を書いたプロセスの pid が生きていないとき**と、**保留を引けて、そのセッションが保留に居ないとき**に畳む。**いま保留があるものは畳まない**（この瞬間に答えられる）。**pid が分からない・引けなかった（サーバが立っていない）ときも畳まない**（#255 と同じで「分からないなら残す」）。**時間では畳まない**（「N 時間たったら」は当て推量で、端末で開いたまま席を外しているだけの待ちまで消してしまう）。tmux は見ないので `SAI_TERMINAL` とは無関係
- **答え待ちは絞り込みに関わらず全部出す。** サーバが返す `approvals` はリポジトリや日数の絞り込みを通っていない（`Approvals.snapshot()` そのもの）。エージェントを止めている＝取りこぼすと困るものなので、一覧から消えていても出す（その場合は名前が分からないので ID を出す）。逆に **待機中は `SessionSummary` からしか作れないので絞り込みに従う**
- **返信の失敗（`replying[].failed`）はここには出さない。** 2 分（`FAILED_TTL_MS`）で消える作りなので、一覧に出しても取りこぼす。失敗はいままでどおり送った画面にその場で出る（#172）
- アーカイブ済みは出さない（ただし答え待ちだけは出す。プロセスが止まっているのは変わらないため）
- **この画面はデータを取りに行かない。** サイドバーと同じ `/api/sessions` の結果（`App` が 1 回だけ取っているもの）を使うので、ポーリングも API も増えていない。組み立ては `shared/todoItems.ts` の純粋関数（`todoItems.test.ts`）

### タブを見ていなくても気づけるようにする（#231）

要対応の画面とバッジは「SAI のタブを見ている」ときの話なので、その外にも出す。**出すものは同じ `todoItems()`** から作るので、バッジ・題名・通知が食い違うことはない。

**タブの題名に件数**が出る（`(2) SAI`）。**件数は先頭**に置く（タブが狭いと後ろから省略されるため）。ブラウザの許可が要らないので、通知を切っていても常に出る。

**通知**（`Notification`）は**入にした時だけ**。ヘッダ右端の自分のメニューから入切でき、入にした瞬間にブラウザの許可を求める（勝手にダイアログを出さない）。設定は localStorage（`sai.notify`）。

- 鳴らすのは**タブが隠れている間だけ**。見ているなら要対応のバッジがそこにあるので邪魔になるだけ
- 鳴らすのは**新しく待ちに入ったものだけ**。見分けの鍵に「いつから待っているか」を混ぜてあるので、待ち続けている間は鳴り続けず、答えたあと再び待てばまた鳴る。**開いた直後は覚えるだけで鳴らさない**（溜まっていた分が一斉に鳴るのを防ぐ）
- **「終わって次を待っている」（`入力待ち`）では鳴らさない**（#438）。ターンが終われば必ず 60 秒後にその行が来るので、鳴らすと**返信が 1 回終わるたびに通知が出る**。落とすのは `appeared()` の 1 か所で、バッジ・題名と同じ `pendingItems()` を通す
- **2 件以上はまとめて 1 通**。行き先はどちらも要対応（`#/todo`。答え待ちならその場で答えられる）
- ブラウザ側で拒否されている・通知を出せない環境では、メニューにその旨だけ出す

**そのために、タブが裏にある間も一覧だけはポーリングを続ける**（`usePolling` の `hiddenMs`。3 秒 → 20 秒）。チャットとフィードは見ていないので今までどおり止まる。

## 使用量（usage limit）を見る

ヘッダの右に、いまエージェントの**枠をどれだけ使ったか**が出る（#216）。返信を投げる前と、止まった理由を知りたいときに、端末へ戻って `/usage` や `/status` を打たなくて済む。押すと詳細のパネルが開く（`Esc` か外側のクリックで閉じる）。

**エージェントで手元に残っているものが違う**ので、出るものも違う。**どちらも API は叩かない**（`~/.codex` と `~/.claude` のファイルを読むだけ。「SAI は外に出さない」）。

| | 何が出るか | 出どころ |
| --- | --- | --- |
| Codex | 5 時間と週の**使用率**（`Codex 59%`。80% から色が変わる）と復帰時刻、プラン | `CODEX_HOME/sessions/**/rollout-*.jsonl` の `token_count` の行の `rate_limits`。ほぼ毎ターン載る |
| Claude | 5 時間と週の**使用率**（SAI から Claude に返信していれば出る。端末だけで使う人はステータスラインを設定していれば）と、**上限に当たっているとき**はその復帰時刻 | 割合は **SAI から回した返信の出力**（`<feed dir>/usage-claude-replies.json`。#694）と `<feed dir>/usage-claude[.<host>].json`（`feed/statusline.py` が書く。#250）。上限中かどうかは `~/.claude/projects/*/*.jsonl` の `quotaLimits` |

- **Claude の割合はステータスライン経由でしか取れない**（#250）。`claude` CLI に `usage` のサブコマンドは無く、TUI の `/usage` が叩いている API は OAuth のトークンが要るので使わない。`statusLine` に `feed/statusline.py` を向けると、Claude Code が描画のたびに渡してくる JSON の `rate_limits` を SAI が受け取れる。設定していなければ今までどおり「上限中」だけ（パネルに設定の案内を出す）。設定の仕方は [README](../README.md)
- **割合は Claude が動いている間しか更新されない**（Codex は rollout に毎ターン載るのと非対称）。枠の復帰時刻を過ぎたものは出さないので、古い数字が残り続けることはない。復帰時刻を過ぎた割合を持ったままのセッション（再開した古いセッション）が描画しても、取れている割合は消えない（#683）。同じ枠の中では高いほうの割合を残し、「時点」は割合が最後に変わった時刻（#689）。**実際（`/usage`）より低く出ることがある**: Claude Code が割合を渡してくる描画は一部だけなので、新しい値が来るまでは前の値のまま
- **Claude の割合は 2 つの口から届く**（#694）。どちらも Claude Code が API を呼んだときだけで、SAI は API を叩かない。
  - **SAI から回した返信**（`claude -p`）: 出力（stream-json）に API の応答ごとに流れる `rate_limit_event` を読む。5 時間と週の両方が載り、ターンの途中でも進む。`<feed dir>/usage-claude-replies.json` に置く（10 秒に 1 回まで。`AGENT_FEED_HOST` を設定していればマシンごと）。`SAI_CLAUDE_ARGS` で `--output-format` を変えていると出ない
  - **端末の Claude Code**: ステータスライン（`feed/statusline.py` → `usage-claude.json`）。`-p` はステータスラインを描かないので、前はこちらしか無く、SAI から回しているあいだ値が止まっていた
  - 2 つのまとめ方: 返信の値のほうが新しければ返信の値を出す（返信に無い枠だけ端末の値）。端末の値のほうが新しければ枠ごとに端末の値を出すが、同じ枠で返信の値より低いもの（古い値を持ち回っている端末が書いたもの）は返信の値のまま。2 つを混ぜて出すときの「時点」は古いほう
  - 拾えるのは、SAI が入力の口を開けて回している返信だけ（サーバを立て直したときに引き取った走りかけのターン・端末に打ち込んだ返信の出力は読まない）
- **Claude の割合が古いときは、そう分かるように出す**（#694）。どちらの口も動いていなければ値は進まない。値が 30 分（`shared/usage.ts` の `USAGE_STALE_MS`）より前のものなら、ヘッダのチップは割合を薄くして「27時間前」を添え、パネルの「◯ 時点」を色付きの太字にして「27時間前の値」を並べる（今日の値でなければ「10/5 10:57 時点」と日付も出す。開いたままのタブでも 5 分おきに取り直して付ける）。「時点」は、返信の出力から拾った値では届いた時刻、ステータスラインの値では割合が最後に変わった時刻なので、ステータスラインだけの人では届いているが変わっていない値にも付く（だから「◯ 前の値」としか言わない）。週は届いているのに 5 時間の枠が無いときは、パネルに「5時間 取れていません」と出す。どちらのときも、パネルとチップの title に理由を 1 文出す。色（80% / 95%）は割合のまま決める。8 日（`STATUS_MAX_AGE_MS`）を過ぎた値・復帰時刻を過ぎた枠は、今までどおり出さない
- **Codex の枠が復帰時刻を過ぎていたら、割合を出さず「更新待ち」にする**（#726）。Codex の値は最後に使ったときのままなので、しばらく使っていないと、もう戻った枠の古い割合が残る。チップは `Codex 更新待ち`（色には数えない。狭い画面では `待ち`）、パネルは「5時間 更新待ち」と、下の行に「10/5 15:38 に戻った・次に使うと更新」。**5 時間の枠は過ぎていても、週の枠が 80% 以上なら、チップは週の割合を `週` の印付きで出す**（週で使い切っているのに「更新待ち」だけにしない）。パネルの見出しには、値を拾った時刻（「10/5 12:47 時点 · 2日前の値」）を出したままにする（週のゲージがいつの値かが分かるように）。Claude の枠も、取ってきたあとに復帰時刻を過ぎたら同じ「更新待ち」になる。0% とは出さない（別の端末で使い切っているかもしれない）。次に Codex を 1 ターン回せば新しい値になる。復帰時刻の前でも、値を拾ってから 30 分を過ぎたら Claude と同じ「古い」の印（`31分前`）を付ける。戻る時刻の言い方は、過ぎて 5 分までは「まもなく戻る」、それより前は「◯/◯ ◯:◯ に戻った」（「更新待ち」の脇では、過ぎた直後でも「戻った」）
- `quotaLimits`（上限中）と割合は**出どころが別**なので、片方だけのことがある。両方あればゲージと「上限に当たっています」を並べて出す
- 取れないエージェントは**何も出さない**（Codex を使っていない人のヘッダに「不明」を並べない）。どちらも取れなければヘッダには何も出ない
- **ヘッダのチップに出すのは 5 時間の枠だが、Claude は 5 時間が無ければ週に落とす**（#347。`web/src/usageChips.ts` の `usageChips()`）。Claude Code は `rate_limits` に `five_hour` を載せないことがあり（手元では `seven_day` だけの日があった）、5 時間だけを見ていると、割合が取れていてパネルには週のゲージが出ているのにチップから Claude が丸ごと消えていた。週のときは `週` の印を付けて 5 時間と混ざらないようにする
- **並びは Claude が先**（#347）。狭い画面で入らないときに落とすのは Codex 側だが、実測では 320px でも `● 36% 週 ● 15%` が 1 行に収まる
- 上限は**口座単位**なのでセッションごとではなく画面に 1 つ。狭い画面ではエージェント名を落として色の点だけにする（`● 92% ● 上限中`）
- 3 秒のポーリングには乗せない（ファイルを漁るので）。取り直すのは、画面を開いたとき・タブに戻ってきたとき・パネルを開いたときだけで、サーバ側も 30 秒キャッシュする。手元の一番大きい rollout は 12MB あったので**末尾だけ**読む

### そのターンが使ったトークン（#411）

**SAI から送った返信の返答**のバブルには、時刻の隣に `26k トークン` が出る（フィードでもセッション画面でも）。マウスを乗せると内訳（入力 / 出力 / キャッシュ読み / キャッシュ作成）・CLI の中で回ったターン数・かかった時間・費用・モデルが出る。

- **出るのは SAI が起こした Claude のターンだけ。** 端末で打ったターン・Codex / OpenCode・別のマシンのセッションには最初から付かない（`claude -p` の stream-json の最後の `result` から読んでいるため。#387 / #386。止めたターンには付かない）。**付いていないことが「そのターンは SAI から送っていない」の印**になる
- **未許可で断られたツールがあれば `26k トークン・未許可 2` と目立つ色で出す。** 非対話の `claude -p` は許可されていないツールを拒否するので、返信が空振りしたように見える回はここで理由が分かる（返信で使う許可モードは入力欄の右で選ぶ）
- **費用はそのターンぶん**（#602）。CLI が返す費用はそのセッションの積み上げなので、同じセッションの前の返信との差を出す（数え直しで下がったときは、その値をそのまま）。前は積み上げをそのまま出していて、長いセッションほど大きく見えていた。**2026-09-19 14 時（JST）より前の返信は、記録の値がもともと 1 ターンぶん**なので、そのまま出す（境目の前後数時間は 1 ターンぶんずれうる）
- **費用はタグの文字には出さず、マウスを乗せたときだけ出す。** 定額プランでは実際に請求される額ではないので、数字だけを並べない（記録には残っているので、知りたいときは読める）
- どの返答のぶんかは**時刻で当てる**（`shared/turnUsage.ts` の `usageByRow()`）。フックの `Stop` はターンが終わった時点で走り、CLI はそのあと終了するので、使用量のほうが必ず後にできる（手元の実測で 0.6〜1.5 秒）。その使用量より前で一番新しい、同じセッションのターン完了の行に当て、2 分以上離れていれば当てない（行を書かずに終わったターンのぶんを 1 つ前のバブルに付けないため）。当たらなければ**何も出さない**
- 溜め先は `~/.agent-feed/turn-usage.jsonl`（1 ターン 1 行）。記録（`YYYY-MM-DD.jsonl`）は触らない派生データなので、消しても履歴は壊れない（トークンの表示が消えるだけ）。サーバが読み返すのは 90 日ぶん

### トークンと費用の内訳（#/usage。#602）

使用量のパネルの「トークンと費用の内訳を見る」か、自分のメニューの「使用量（トークンと費用）」から開く。

- **数えるのは SAI から送った Claude の返信だけ**（`turn-usage.jsonl`）。端末で直接回したターンと Codex / OpenCode は入らない（画面にもそう書いてある）
- 期間は **24 時間 / 7 日 / 30 日**（既定は 7 日。選んだ期間は覚える）。「24 時間」はいまから 24 時間前までで、今日の 0 時からではない
- 上に合計（ターン・トークン・うち読み直しの割合・費用・未許可で断られたツールの数）、下に **セッション別・日別・モデル別**の表。どの表も列は同じで、トークンは **読み直し（キャッシュ読み）・キャッシュ書き・入力・出力**を分けて出す（読み直しが大半なので、合計だけだと何が効いているか分からない）。正確な数はマウスを乗せると出る
- セッション別はトークンの多い順で、名前を押すとそのセッションへ移る。**モデルを 1 回呼ぶたびに読み直す量が大きいセッション**（平均 40 万トークン以上。見出しのコンテキストの注意と同じ区切り）には「読み直し大」の印が付く
- 日別は新しい日から（日付は Asia/Tokyo）。モデル別はトークンの多い順で、CLI がモデルを返さなかったターンは「（不明）」
- **費用は API 換算の目安**で、定額プランでは実際に請求される額ではない。CLI が返す費用はセッションの積み上げなので、**前の返信との差**で数える
- 取るのは開いたとき・期間を切り替えたとき・「更新」を押したときだけ（3 秒のポーリングには乗せない）。狭い画面では表だけが横に送れる

## チャット

Slack のチャット風。1ターンは「自分の入力（`user_text`）→ エージェントの返答（`text`）」の2つのバブルで出るので、往復で読める。Claude は入力した瞬間に `UserPromptSubmit` の行が先に届くので、自分のバブルはターン完了を待たずに出る（続く `Stop` の行に載っている同じ入力は重ねない）。同じ発言者の連続した発言（10分以内）は Slack と同じくまとめる。人を待って止まった行（`PermissionRequest` など）は `⏳ 許可待ち: Bash: rm -rf node_modules` のような**待ちのバブル**になり、後にターン完了か再開の行が来ていれば薄く残る。再開の行（`UserPromptSubmit`）は本文が無いのでバブルにしない。**セッションが終わった行（`SessionEnd`。#385）は発言ではないので、バブルではなく日付と同じ区切り線**（`セッション終了: 会話をリセット（/clear）`）にする。`/clear` の線は、**それより前をエージェントが覚えていない**という印でもある（会話は新しいセッション ID で続くので、一覧では別のセッションになる）。リポジトリ名がチャンネル。自分のバブルは Markdown にせずそのまま出す。長い本文（600 字か 9 行を超える）は「もっと見る」で開く折りたたみが付くが、**フィードでもセッション画面でも最初から開いた状態で出る**（#365 / #369。読むたびに押さずに済む。畳みたいものだけ「折りたたむ」で畳めて、畳んだ状態は 3 秒ごとの更新をまたいでも残る）。長すぎて記録のときに切られた本文には、末尾に「✂ ここで切れています」が薄く出る（#358。「もっと見る」を全部開いても続きが無いので、そこで終わったのと見分けが付くように）。エージェントのバブルにそのターンの思考（`thinking`）があれば、本文の上に「▸ 思考（N 文字）」の折りたたみが付き、押すと薄い字でそのまま（Markdown にせず）出る。見出しの「思考を全部開く」で全部開いた状態にでき、localStorage に残る。フィードには出さない（API の行からも落とす）。3秒ごとに更新するが、サーバが返す `rev` が変わっていなければ state を触らない（= 描き直さない）。タブが隠れている間は止まる。新しい行が来たら最下部に追従するのは最下部を見ていたときだけで、上に遡っている間は読んでいる位置を動かさない。追従して最下部へ送るのは**中身の高さが変わったとき**だけなので、何も届いていなければ 3 秒ごとの更新で位置は動かず、最下部のすぐ上（40px 以内）で直前の発言を読み返していても引き戻されない（#344）。**チャットの箱の方が縮んだ・広がったとき**（差分ボタンが出て入力欄の上に余白を取った・入力欄が複数行に伸びた・狭い画面でキーボードが出た）も、最下部を見ていれば送り直す（#544）。前は中身の高さしか見ていなかったので、差分のあるセッションを開くと、ボタンが出たぶん（32px）最後の発言の下が隠れたまま止まっていた。読み返している間は動かさない。代わりに右下に「↓」（一番下へ）が浮かび、遡っている間に届いた行の数を添える。押すと最下部まで動いて、以後は追従に戻る。フィードもセッション画面も同じ。

**画像は、それが出てきた発言のバブルの下に出る**（#504 / #507）: 端末で貼った画像（`[Image #1]`）と自分の入力に書いた画像のパスは自分のバブルの下、エージェントが Read で開いた画像はそのターンの返答のバブルの下（Claude の transcript から）。返答の本文の中の画像と SAI から添えた画像は今までどおりバブルの中に出るので、二重には出さない。配れないもの（`/tmp` の下・作業ディレクトリの外・消えた）は名前だけ。取りに行くのは開いたときと新しい発言が記録されたときだけ（3 秒のポーリングには乗せない）。**フィードでも同じ発言の下に出る**（#657）: フィードに流れているセッションのうち新しい順に 20 個までの分を、1 つずつ順に取りに行く（それより古いセッションの画像は、そのセッションを開けば出る。別のマシンのセッションには出ない）。**画像を押すと、別のタブではなくページの中のライトボックスで大きく開く**（バブルの中の画像・添えた画像も同じ）。Esc・背景・✕で閉じ、同じ発言に複数あれば ← → のボタン・キー、または**横にスライド（指でスワイプ・マウスでドラッグ）**で送る（#509。左へ払うと次）。ダウンロードもできる。⌘ クリックなら今までどおり新しいタブで開く。 **Codex の画像生成（`imagegen`）で作った画像も、作ったターンの返答のバブルの下に出る**（#575）: 返答の本文には保存先が書かれず、画像は `~/.codex/generated_images/<スレッド>/` にしか無いので、rollout の画像生成の完了（と、見せた画像）の記録から拾う。配るのはその置き場の中のファイルだけ。 **Codex が `view_image` で見せた画像も、作業ディレクトリ（`cwd`）の中にあれば、そのターンの返答のバブルの下に出る**（#704。確かめのために見ただけの画像も並ぶ）: 本文に `![名前](パス)` を書き忘れても出て、本文にも書かれていれば 1 回だけ出す。`/tmp` のような作業ディレクトリの外・外を指すシンボリックリンク・SVG は出さない。 **バブルの下の枠・本文の中・添えた画像の枠に出すのは軽い版**（#589）: 200KB 以上の画像はサーバが縮めたもの（macOS の `sips`）を出し、元の画像はライトボックスで開いたとき・ダウンロードしたときだけ読む（Codex の生成画像 6 枚のセッションで 12MB 読んでいたのが数百 KB になる）。 横に細長い画像（幅が高さの 4 倍以上）は、縮めても字が読めるように短い辺を 120px に保って縮める（#709。長辺 512px のままだと、広げて出しても 14:1 の表は高さ 36px ぶんの絵しか無い）。初めて出すときだけ 1 枚 0.1〜1 秒ほど待つ。縮められない（`sips` の無いマシンなど）ときは、枠に画像の印・名前・大きさ（`2.3MB`）だけを出し、押すと元を開く。

バブルの本文は **Markdown として描く**（`shared/markdown.ts` → `web/src/Markdown.tsx`）。扱うのはエージェントの返答で頻出するものだけ: URL と `[ラベル](URL)` のリンク（別タブで開く。先が http(s) 以外ならリンクにしない）、`**太字**`、`` `コード` ``、`- ` / `1. ` の箇条書き、`#` 見出し、` ``` ` のコードブロック、`> ` 引用、`---` 罫線、`| a | b |` と `| --- | --- |` の**表**（#328。GitHub と同じ規則で、区切りの行の列の数が見出しと同じときだけ表にする。揃えの `:---:`、`\|` のエスケープも効き、セルの中のコードや太字も効く。罫線と見出しの背景で出し、横に長い表は表の枠の中だけで横に流れる）、`:tada:` の絵文字（Slack と同じ記法。`shared/emoji.ts` の表に載っている名前だけを 🎉 にする。`14:08:30` のような時刻や表に無い名前はただの文字のまま。`` `:tada:` `` とコードブロックの中も変えない）、**手元のファイルの画像への参照**（#321。`![alt](パス)` と、リンク先が画像の拡張子（png / jpg / jpeg / gif / webp）の `[名前](パス)`。Codex は後者の形で出す）。画像はサムネイル（押すとページの中のライトボックスで開く。#507。同じ発言の本文の画像は ← → で送れ、画面より小さい画像は画面に収まる範囲で 3 倍まで拡大して出す。#702）と、名前の付いたダウンロードのボタンで出す。サムネイルは幅 320px・高さ 320px までで、**横に細長い画像（幅が高さの 4 倍以上。ボタンの並びだけを切り抜いた帯など）は、高さが 80px になるところまで幅を広げる**（バブルの幅まで。収まらなくても高さ 18px より小さくは縮めず、はみ出すぶんは横にスクロールする）。押せる場所は絵が小さくても 44px ある（#702）。一言が付いたバブルでは、一言の中は画像の印と名前だけにして、「詳細」を開かなくても一言の下に元の本文の画像が並ぶ。配るのはサーバで（`GET /api/sessions/<id>/images/<key>`）、**そのセッションの返答の本文に書かれていて、作業ディレクトリ（`cwd`）の中にある、中身が PNG / JPEG / GIF / WebP の 20MB 以下のファイルだけ**（`/tmp` のような作業ディレクトリの外・外を指すシンボリックリンク・SVG は配らない）。配れないとき（ファイルが無い・条件に合わない・別のマシンのセッション）は画像の印と名前だけを出し（パスはマウスを乗せると出る）、`[名前](/Users/…)` の Markdown がそのまま文字で出ることは無い。**外の URL の画像（`![alt](https://…)`）は読み込まずリンクにする**（画面が外のホストに取りに行くと、見ていることが外に出る）。スキーム付き（`file:` / `data:` / `javascript:`）や画像でないパスは文字のまま。それ以外はそのまま改行を保って出す。HTML 文字列は組み立てず React 要素にするので、`text` に HTML が入っていてもただの文字として出る。一覧の「最後の発言」は同じ字句解析で記号だけ落とした1行。

**返答の中のファイルのパスを押すと、SAI の中でそのファイルを読める**（#603）。押せるのは、エージェントの返答の `` `コード` `` で**中身がまるごとファイルのパスの形**のもの（`server/app.ts`・`docs/screen.md:12`。文字のファイルの拡張子で終わるものだけで、点線の下線が付く。`store.rows()` や `127.0.0.1:8787` はただのコードのまま）。押すとページの中にビューアが開く（広い画面はモーダル、幅 900px 以下は全面。Esc・背景・✕ で閉じる）。**読むだけ**で、書き換えはできない。

- `.md` は描いた形で出し、「元の文字で見る」で切り替えられる。ほかは等幅・行番号つき。**HTML は描かない**（文字として見せるだけ。同じオリジンでスクリプトが動くため）。色付けはしない
- `path:行`（`:12`・`:12:3`・`:12-20`・`#L12`）で書かれていれば、その行に印を付けてそこまで流す（Markdown でも元の文字で開く）
- **読めるのは、そのセッションの返答に出てきたパスで、作業ディレクトリの中にある、1MB 以下の、文字のファイルだけ**。無い・作業ディレクトリの外（リンクで外に出るものも）・大きすぎる・文字でない、は理由を 1 行出す。名前だけ書かれたファイル（`record.py`）は作業ディレクトリの直下で探すので、下の階層にあると「ありません」になる
- **秘密が入っていそうな名前は開かない**: `.env*`・`*.env`・`*.pem`・`*.key`・`id_*`、名前に `credential`・`secret`・`password`・`private_key` を含むもの、`token.json`・`auth.json` のような設定のファイル、`.npmrc`、`.git/`・`.ssh/`・`.config/` の中など（リンクを解いた先がそれでも開かない）。名前だけで決めるので、すり抜ける名前は残る
- **当面、SAI を動かしているマシンのブラウザからだけ**（tailnet 越し＝携帯からは「開けません」と出る。名前の一覧をすり抜けた秘密が手元の外に出ないように）。自分の入力・待ちのバブル・別のセッションからの返答・別のマシンのセッション・一言の中のパスは押せない

**同じ名前のセッションは、名前のあとの添え字で見分ける**（#572）。同じリポジトリの中で表示名（無ければ題名）が重なったときだけ、`sai_main（9/2〜）` / `sai_main（9/25〜）` のように始まった日を添える（日も同じなら ID の頭）。要対応・サイドバー・`⌘K`・`@` の返信先・通知・チャットの話者名のどこでも同じ添え字になる。重なっていなければ何も付かない。名前を付けるとき、同じリポジトリに同じ表示名のセッションがあれば入力欄の下に知らせが出る（保存は止めない）。

**セッションに付けたアイコンは、そのセッションの発言がどこに出ても出る**（#666）: 自分の返答（セッション画面・フィード）に加えて、**送ったメッセージへの返答**（送り元のセッション画面に並ぶ、別のセッションの返答。#588）と、**許可・質問のバブル**（セッション画面・フィード）も、頭文字ではなくそのセッションのアイコンになる。アイコンを付けていないセッションと、記録に 1 行も無いセッション（端末の Codex のダイアログ）は今までどおりエージェントの頭文字（`C` / `X` / `O`）。アイコンが出ているときは、エージェントの種類の印は添えない（自分の返答と同じ）。

**アイコンは今まで使った画像から選び直せる**（#465）。見出しの画像の口の隣の時計（自分のアイコンは「表示名とアイコン」の「今まで使った画像から選ぶ」）を押すと、置いたことのある画像が新しく使った順に並び、押すとそのまま付く（加工済みなので切り抜きはやり直さない）。いまのアイコンと同じ画像には枠が付く。セッションのアイコンと自分のアイコンは**同じ履歴**を使うので、自分と同じ画像をセッションに付けることもできる。同じ画像はまとまる（中身で名前を付けるので、同じファイルを同じように加工すると 1 つになる。実機で確かめた）。**画像を外しても履歴には残る**（間違えて外したものを戻せる）。履歴から消すのは各画像の隅のゴミ箱で、**2 回押すと消える**（1 回目で「消す」に変わる）。消しても、いまその画像を付けているアイコンはそのまま残る。上限は設けていない（1 枚 40〜110KB）。初めて開いたときに、それまでに付けていたアイコンを取り込む（手元では 13 ファイルが、同じ画像がまとまって 10 個になった）。

チャット見出しには**そのリポジトリへのリンク**が出る（#212。GitHub のアイコン + `Naturalclar/sai`。押すと別タブで開く）。飛び先は行の `remote`（`record.py` が origin を `https://host/owner/repo` に正規化して載せる）で、**古い行で `remote` が無いセッションはサーバが `cwd` の git から埋める**（`server/git/project.ts`。`project` を引くときにどのみち origin を読んでいる）。origin の無いリポジトリでは飛び先が無いので**何も出さない**。ホストが `github.com` のときだけ GitHub のロゴを使い、GitLab や self-hosted には汎用のリポジトリの印を出す。出すのは見出しだけで、一覧とフィードには出さない。

チャット見出しには**いまのコンテキスト量**も出る（#441。`いま 830k トークン`。マウスを乗せると正確な数と「返信 1 回でこの量を読み直します」）。返信のたびにこの量を読み直すので、長く続けたセッションほど 1 回が重い。**40 万トークンを超えたら状態の印に `コンテキスト 830k` が付き**、狭い画面の 1 行目にも残る（気づかないまま続けるのが一番高くつくので、`bypassPermissions` の印と同じく畳まない）。切り替える・`/compact` するかは人が決める（SAI は自動では何もしない）。材料は「いま何をしているか」と同じ transcript / rollout の末尾（OpenCode は SAI の `opencode serve` が立っているときだけ本体に聞く）で、別のマシンのセッションと読めないときは出さない。

チャット見出しの「アーカイブ」でそのセッションを一覧とフィードから隠せる（アーカイブ済みなら「戻す」）。アーカイブ済みのセッションは `#/s/<id>` で直接開けば普通に読めるが、入力欄は出ない（返すなら先に戻す）。

90 日ぶんから、`cwd` ごとに一番新しいセッションを選ぶ。別のマシンのものは出さない）と、**そのリポジトリの記録の無い worktree**（#319。`git worktree add` で作ったばかりのものなど。`· 記録なし` と添えて後ろに並ぶ）で、パスを手で入れる口は無い。**git は別のセッションに写してしまうため。止めても会話は残り、attach すれば SAI から送った分も入った状態で起きる）。**端末で `claude attach` して開いていれば止めない**——`claude stop` はその端末をその場で閉じる（`Session … has exited.`。打ちかけも消える。2026-09-24 に実測）。ターンが回っている間も止めない。どちらのときも送った返信は**預かり**、条件がそろったら回る。許可モードは Claude にしか渡らないので、Codex と OpenCode を選ぶと出ない（Codex の許可は app-server のバブル、OpenCode は serve の保留のバブルで答える）。

セッションを開いているときは、下の入力欄から**そのセッションに続きの指示を送れる**（Enter で送信、Shift+Enter で改行）。サーバが `cwd` でセッションを非対話モードの CLI で再開して1ターン回す:

入力欄の**先頭で `/` を打つと、そのセッションで使えるスキルの候補**が出る（`@` と同じ操作で、↑↓ で移動、Enter / Tab で確定、Esc で閉じる）。候補は `~/.claude/skills/` と**そのセッションの `cwd` の `.claude/skills/`** から集めるので、worktree ごとに違う（**Codex のセッションでは置き場が変わり**、`cwd` の `.codex/skills/` と `.agents/skills/` に、プラグインと組み込みのスキルが加わる）。名前でも説明でも絞れる（説明には「issueの優先度をつけて」のような呼び出し文句が入っている）。選ぶと Claude / OpenCode は本文が `/<name> `、Codex は `$<name> ` になり、展開は CLI に任せる。Codex だけ `$` なのは、端末に打ち込む経路で `/` が TUI のスラッシュコマンドとして先に解釈され、スキル名が「存在しないコマンド」になるため。`/` は候補を探す入口として先頭のときだけ拾うので、文中のパス（`/Users/…`）では出ない。当たりが無いときも出ないので、Enter はそのまま送信になる。**OpenCode のセッションでは本体に聞く**（#393）ので、スキルに加えて**スラッシュコマンド**（`/init` など）も同じメニューに並ぶ（コマンドには「コマンド」の印が付く）。Grok のセッションでは何も出ない。

**候補メニュー（`@` / `/` / `:` と `⌘K`）で、いま選んでいる項目には左端に色の帯が付く**（#254）。前は薄い背景色だけで、選ばれていない項目との差がライトで 1.14:1・ダークで 1.11:1（区別できる目安は 3:1）しかなく、画面に出ているのにどれを選んでいるか分からなかった。帯はサイドバーの「いま開いているセッション」と同じ見た目で、こちらは 5.7:1（ダークは 6.5:1）ある。マウスを乗せた項目も同じ状態になる（hover と選択は同じもの）。

入力欄で **`:` に続けて 2 文字以上打つと絵文字の候補**が出る（`@` / `/` と同じ操作）。名前でも部分一致でも絞れて、選ぶと**絵文字そのもの**が本文に入る（`:tada:` ではなく 🎉）。そのままエージェントにも届き、自分のバブルにも出る。当たりが無ければメニューは開かないので、`14:08:30` のような時刻を打っても邪魔にならない。表は `shared/emoji.ts` によく使うものだけを手書きで持っている（増やすときはここに足す）。

**打ち始めると、前に送った内容の続きが薄く出る**（#219。fish シェルのオートサジェストと同じ）。そのセッションに前に送った文のうち、いま打った文で**始まる一番新しいもの**の残りをゴーストとして重ね、**カーソルが末尾のときの `→`** で本文に入る。文の途中の `→` は今までどおりカーソルが動く。出典は `↑` の履歴と同じ（行の `user_text`）なので、サーバも新しい API も要らない。**本文が空のときは出さない**（毎回ゴーストが見えると邪魔で、`→` が `↑` とほぼ同じ働きになるため）。IME で変換している最中と、`@` / `/` / `:` の候補が開いている間も出さない。 **タッチ端末では、入力欄のすぐ上に「▸ 続きの頭」のボタンが出て、押すと同じように入る**（#349。ソフトキーボードには矢印キーが無く `→` を押せないため）。出るのは `(hover: none) and (pointer: coarse)` のときだけで、マウスのある画面では今までどおりゴーストと `→` だけ。押しても入力欄のフォーカスは外れないので、そのまま続きを打てる。

**返答の一部を選んで、引用として返信欄に入れられる**（#604）。セッション画面で返答の文字を選ぶと、選択のすぐ下に「引用して返信」が出る。押すと打ちかけの末尾に `> 選んだ文` が足され、カーソルがその下に来る（**送らない**。打ちかけは消さない）。続けて別の所を選べば引用が順に並ぶので、「決めてほしいこと」に 1 つずつ答えられる。出るのは 1 つの返答の中を選んだときだけで、自分の入力・待ちのバブル・複数の発言にまたがる選択には出ない。長い選択は 600 字で切って `…` を付ける。携帯でも同じボタンが選択の下に出る

**打ちかけ（本文と添えた画像）は、送らずに別の画面へ移っても残る**（#306）。別のセッション・フィード・要対応・一覧（狭い画面）へ行って戻ると、入力欄にそのまま戻る。セッションごとに持つので、A で打ちかけて B を開いても B の入力欄には出ない。置き場はブラウザの localStorage（`sai.drafts`）で、**再読み込みしても残る**（iPhone の Safari は裏に回したタブを捨てて読み直すことがよくあり、メモリだけだとアプリを切り替えて戻っただけで消えるため）。送ったら消える。**送れなかったときは本文・添えた画像・`@` の返信先が入力欄に戻り**（#350）、打ちかけにもまた残る（端末の打ちかけの確認で「やめる」を押したとき、返信の起動に失敗したとき、SAI のサーバとの通信が切れたときなど）。戻すのは入力欄がまだ空のときだけなので、失敗を待つ間に次を打ち始めていれば上書きされない。**受け付けられたあとで失敗した**とき（`claude -p` が落ちた・記録が増えなかった・端末に打ち込んだが届かなかった）は、勝手には戻さず「送信失敗: …」の横に**「入力欄に戻す」**が出るので、押したときだけ戻る。`↑` で前に送った内容を呼び戻している最中に離れたときは、呼び戻した文ではなく、その前に打っていた文を残す。画像は置き場のファイルを消さないので、戻したときもサムネイルが出る。溜まり続けないように、7 日より古いものと、新しい順に 50 件を超えたものは次に書くときに捨てる。**フィードの入力欄は残さない**（返信先を `@` で選んで本文に表記が入る形なので、本文だけ戻しても返信先が合わない）。

**返信のモデル**は**入力欄の、送信ボタンの左**で選べる（#193。Claude Desktop の入力欄と同じ位置）。押すとメニューが開き、そのセッションで出てきたモデル、Claude なら別名 `fable` / `opus` / `sonnet` / `haiku`、`Default`（CLI に任せる）、候補に無い名前を入れる `Custom model…`（モーダル）が並ぶ。**OpenCode のセッションでは、開いたときに本体へ聞いて実際に使えるモデルも並べる**（#394。そのリポジトリの `opencode.json` で足した provider のぶんも出る。使ったことが無いモデルも選べるので、`Custom model…` に頼らなくてよい）。閉じているときは短い名前（`claude-opus-5` → `opus`、未設定なら `Default`）で、全体はマウスを乗せると出る。**選択肢の名前は英語**（#282）で、隣の許可モード（#271）と揃えてある。言い回しは Claude Code 自身のモデル選択（`Default (recommended)` / `Custom model`）から取った。何が起きるかの補足・マウスを乗せたときの説明・モーダルの文言は日本語のまま。未設定のセッションでは `[Default] [Default]` と並ぶが、どちらも「CLI に任せる」なので同じ言葉にしてある（左がモデル、右が許可モード）。メニューには正式名を出す（別名と見分けが付かなくなるため）。セッション画面でもフィードでも同じ（フィードはサイドバーの一覧に居るセッションのときだけ）。選ぶと `session-meta.json` の `model` に残り、次の返信から Claude は `--model <m>`、Codex は `-m <m>` が付く（`SAI_CLAUDE_ARGS` に `--model` があってもセッションの設定が後ろに来て勝つ）。見出しの `claude-fable-5-1` のような表示は**実際に使われた**モデル（記録から）で、設定とは別。見出しに操作は無い（変えるのは入力欄の 1 か所だけ）。返信が終わって行が届けば表示のほうも変わる。

注意: Claude は `--resume` に `--model` を付けると**セッションのモデル設定そのものが変わる**（確認済み: `--model sonnet` で 1 回返信したあと、`--model` 無しで再開しても `claude-sonnet-5` のまま）。つまり SAI から返信のモデルを変えると、端末でそのセッションを再開したときのモデルも変わる。端末で `/model` を打ち直せば戻る。

`--` は本文が `-` で始まっても（`-v` や `--help`）CLI のフラグとして解釈されないようにするため。

**返信に画像を添えられる。** 入力欄への貼り付け・ドロップ・写真のボタン（iPhone ではカメラロール）の 3 つで、1 回 4 枚・1 枚 10MB まで。選んだ瞬間に `POST /api/sessions/<id>/attachments` で `~/.agent-feed/attachments/<sha1(ID) の先頭16桁>/<sha1(中身) の先頭16桁>.<ext>` に置き、送信時にそのパスを `attachments` で渡す。サーバは**そのセッションの置き場のパスだけを通す**。**Claude** は本文末尾のパスをReadし、**Codex** はapp-serverの `localImage` と本文末尾のパスの両方で受ける。**端末で開いている Codex**（`codex queue` で足す経路）は画像の口が無いので本文末尾のパスだけで渡り、Codex が自分で開く（#678。送ったあと入力欄の上に「この経路では、画像はパスとして渡ります」と出る。セッション画面だけ）。画面はパスではなくサムネイルを出す。中身で種類を見るのでHEICは選んだ瞬間に弾く。

**画像以外のファイル（文字のファイルと PDF）も添えられる**（#608）。ログ・テキスト・CSV・JSON・ソースコードなど UTF-8 として読めるものと PDF で、**種類は中身で決める**（拡張子は信じない。`.txt` と名乗るバイナリは断り、拡張子の無いログは通す）。上限は画像と同じ（1 回 4 個・1 個 10MB、画像と合わせて数える）。置き場には中身のハッシュの名前で置き（文字のファイルは元の拡張子に関わらず `.txt`、PDF は `.pdf`）、元のファイル名は画面に出す名前としてだけ持つ（パスには使わない）。エージェントには本文の末尾に「添付したファイル:」の見出しで `<絶対パス>（<元の名前>）` を足して渡す（画像の「添付した画像:」とは別の塊。Codex の `-i` などの画像を受ける口には画像だけを渡す）。選ぶ口は写真のボタンの隣の紙のボタン（写真のボタンは画像だけのまま）とドロップ。入力欄の並びには印・名前・種類と大きさ、自分のバブルには印と名前で出る。**画面からは開けない**（配る口は画像だけ。HTML と SVG も文字として保存はするが、描かない・配らない）。動画・Office の文書・圧縮ファイルは受けない。置き場を掃除する仕組みはまだ無い。

**長い貼り付けを、本文に入れずファイルにして添えられる**（#609。**既定は切**。自分のメニューの「長い貼り付けをファイルにして添える」で入にする。設定は `settings.json` に残るので Mac と携帯で揃う）。入にすると、入力欄に貼った文が **10,000 字を超えた**とき、貼り付け全体を本文に入れずテキストファイルの添付にする（上の「画像以外のファイル」と同じ仕組み・同じ上限。エージェントには `貼り付けた文.txt` の名前でパスが渡る）。長い文が本文に入ると、そのセッションの以後のターンで毎回読み直されるため。入力欄の並びには「貼り付けた文（12,340 字）」と出て、押すと中身の頭（4,000 字）を確かめられ、**「本文に戻す」**で添付をやめて入力欄に入れ直せる（送りはしない。そのまま本文に貼りたいときの逃げ道もこれ）。対象は貼り付けだけで、手で打った長い文は変えない。添付の数が上限に達している・大きすぎる・預けられなかったときは、今までどおり本文に入る。打ちかけにも残る（別の画面へ行って戻っても消えない）。

**Claude のログインが切れていると、ヘッダの下にバナーが出る**（#685。「Claude のログインが切れています。返信・新しいセッションは失敗します。Mac の端末で `claude auth login` を打ってください」）。切れると SAI が起こす `claude` の仕事（返信・新しいセッション・口が `claude` の一言）が全部失敗するが、前は返信の失敗の末尾に CLI の文言が出るだけだった。SAI が確かめるのは**起動したとき**と **Claude の返信・新しいセッションが失敗したとき**だけ（定期的には聞かないので、切れてから最初の失敗までは出ない）。そのとき失敗した返信の文も「Claude のログインが切れています…」で始まる。**SAI からはログインしない**（読むだけ。#577）ので、Mac でログインし直したらバナーの「確かめ直す」を押す（できていれば次の更新で消える）。`claude` が無い・古い・応答が無いときは何も出さない。

**そのバナーから、SAI の画面でログインし直せる**（#577。携帯から tailnet 越しに見ているときも、Mac の前に戻らずに直せる）。「SAI からログインする」を押すと、サーバが `claude auth login` を起こして、ログイン用のリンクとコードの欄を出す。①「ログインのページを開く」を**いま見ている端末のブラウザ**で開いてログインし（**Mac のブラウザは開かない**）、② そのページに出たコードを欄に貼って「送る」。通ればバナーが消える（サーバが `claude auth status` を聞き直して決める）。コードが違えば「コードが違うようです」と出て貼り直せる。10 分たつと時間切れで、「もう一度始める」から。「やめる」で途中でやめられる（子を落とすのはこのときだけ。絞り込みを変えた・別のタブで開いて閉じた、では進んでいるログインは落ちず、開き直すと同じリンクの続きになる）。**ログインできている間はこの口は動かない**（いまのログインを差し替えない）。SAI はリンクもコードも残さない（コードは送ったら欄から消える）。失敗した返信は自動では送り直さないので、ログインし直してから送り直す。

**ログインが切れて途中で止まったターンには、返答の所に「ログイン切れで停止」の印が出る**（#577）。そのターンはフックが鳴らないので記録の行が無く、SAI が transcript から補って出す（#614 の「記録から補った」と同じ仕組み）。本文は CLI が出した文（`Not logged in · Please run /login`）で、エージェントの返答ではない。

回したターンが完了すれば既存のフック（Stop / notify）が動いて JSONL に1行増えるので、返信の結果は今のポーリングでそのまま画面に流れてくる。送信直後は「送信中…」の仮バブルが出て、`UserPromptSubmit` の行が届けば本文はそちらの本物のバブルに置き換わり「処理中」の1行だけ残る。行が増えたら消える（増えた行の `user_text` が同じ文なので、見た目はそのまま本物の自分のバブルに変わる）。

**終わったターンで実行したコマンド・ツールは、返答のバブルの「手順」から見られる**（#605）。押すとそのターンで呼んだツールが順に出る: 時刻・ツール名・コマンドやファイルのパス（許可のバブルと同じ要約。300 字まで）と、あれば「何のためか」の一文。**ツールの出力は出さない**。開いたときに 1 回だけ Claude の transcript / Codex の rollout から読む（畳んでいる間は取らないので、数と種類は開いてから出る）。そのターンが transcript に無い（要約で消えた・ファイルが無い）ときと別のマシンのセッションは「記録がありません」。OpenCode には出ない。素通し（bypassPermissions）で回したターンで何が実行されたかも、ここで確かめられる。

**処理中の間は、いま何をしているかが出る**（#302）。**エージェントが途中で書いた文も出る**（#680。Codex の作業の途中の文・Claude のツールの合間の文。仮バブルのすぐ下に、時刻を付けて薄く並ぶ。セッション画面は直近 5 つ、フィードは最新の 1 つで、長い文は畳んで「全文」で開く）。この文は記録（JSONL）には無いので、ターンが終わって最後の返答が届くと仮バブルと一緒に消え、未読・検索・一言には乗らない。**あとから読むには、返答のバブルの「手順」を開く**（ツールの呼び出しと時刻順に混ざって出る）。**OpenCode はエージェント自身の段取りも出る**（#397。`1/3 件 直す` のように、済んだ数 / 全体と、いま動かしているもの。押すと `✓ 調べる` / `▶ 直す` / `· 確かめる` と全部が開く。サブエージェントを起こしていれば `サブ 1` も添える）。OpenCode は transcript が読めないので手順（`steps`）は空で、**段取りだけが唯一の中身**になる。取りに行くのは**すでに `opencode serve` が立っているときだけ**（= SAI から返信したセッション）で、段取りのためにサーバを起こしはしない。`cancelled` は数から外す。「処理中 12分」の横に `Bash: pnpm test 42秒` / `考え中` / `返答: …` のように**いまの手順を 1 行**出し、押すと直近の手順（最大 8 件と「ほか N 手順」）が開く。同じツールが 5 分を超えて走っていれば時間の色を変える。

- 出どころは Claude の transcript と Codex の rollout の**末尾**（`GET /api/sessions/<id>/progress`。`server/local/progress.ts`）。ツールを呼んだ行は実行前に、結果は終わってから書かれるので、長いコマンドの間も「いま何が走っているか」が読める。考え中の中身は出さない（ほとんど空で、入っていても考えている途中の文）
- ツールの要約は、Bash / Agent は `description`、無ければ許可待ちと同じ（コマンド・ファイルのパスなど）。Codex の `exec` はコマンド（`cmd`）
- **止められるのは SAI が起こした Codex・OpenCode・Claude のターンだけ**（#384 / #392 / #386）。その仮バブルにだけ「止める」が出て、押すと Codex は `turn/interrupt`、OpenCode は `/session/<id>/abort`、Claude は入力の口（`--input-format stream-json`）に `interrupt` が飛ぶ（端末で開いているセッションと、SAI を立て直す前から回っている Claude のターンには出ない。Claude を止めたターンは**行が届かない**（`Stop` フックが鳴らない）ので、自分の入力のバブルだけが残る。OpenCode を止めると、そのターンの行は**本文の空の行**として 1 本届く。Codex のターンは実測で p90 が 47.9 分あり、止める手段が端末の `kill` しか無かった）。**止めても預かった返信は走らない**（「前のターンを止めたので…」と出て、「続けて送る」を押したときだけ回る）。止めたターンが起こしたシェルのコマンドはそのまま残る（SAI は殺さない）
- 取るのは**処理中のセッションを出している間だけ**（一覧のポーリングには乗せない）。サーバはファイルの `(mtime, size)` が変わったときだけ読み直し、transcript は 64KB から倍々に、ターンの始まりが見えるまで（上限 4MB）読む
- **端末で打ったターンにも「処理中」が出る**（セッション画面だけ）。SAI から送った返信ではないので `replying` には無く、行の上で「人の入力のあとターン完了がまだ」で、transcript の上で本当に動いている（ターンが閉じておらず、走っているツールがあるか、10 分以内に書かれている）ときだけ出す。Esc で止めたターンは入力のあとターン完了が来ないので、書き込みが止まって 10 分で消える——**が、`claude agents --json` で「そのセッションでターンが回っていない」と分かれば、待たずに消える**（#418）。`claude agents --json` はこのマシンで生きている Claude のセッションを全部返すので（`status` が `busy` か `idle`）、`busy` が 1 つも無ければ処理中を落とす。`claude` が無い・古い・時間切れのときは今までどおり 10 分待つ（`SAI_CLAUDE_AGENTS=0` で聞きに行かない）。Claude だけ
- **端末で打った Codex のターンにも「処理中」と手順が出る**（#693。セッション画面だけ）。Codex は入力の行を書かない（入力はターン完了の行に載る）ので、上の「人の入力のあと」では拾えない。このマシンの Codex のセッションを開いている間は rollout を見て、**ターンが開いていて動いている**（上と同じ条件）ときに、ターンの始まり（rollout の `task_started`）を起点にした「処理中」を出す。最後のターン完了の行より前に始まったターンは出さない。前は、Codex が許可で止まって SAI で答えると、許可のバブルが消えたあとターンが終わるまで画面に何も出なかった
- **画面から答えた許可・質問は、そのターンが終わるまで「処理中」の上に残る**（#693。「✓ 許可した 12:34 `git add -A`（Yes, proceed）」「✕ 拒否した …」。どのエージェントでも）。許可のバブルは答えると消えるので、何を答えたかをここで見る。ターンが終わったら消える（ターン完了の行が来たとき。止めたターンは行が来ないので、transcript / rollout の上でターンが閉じたとき）。終わったターンで走ったコマンドは、返答の「手順」から見られる。**SAI を通さず端末で直接答えたものは出ない**（手順には走ったコマンドとして出る）。サーバのメモリにあるだけなので、SAI を立て直すと消える
- 出ないもの: OpenCode（手元にファイルが無い）、別のマシンのセッション、サブエージェントの中の手順

### 端末（tmux）で開いているセッションには打ち込む

セッションが **tmux のペインで開いていれば、返信はそのペインに打ち込む**（`tmux load-buffer` → `paste-buffer -p` → `send-keys Enter`）。別プロセスを立てないので、端末に入力と返答がそのまま出て、フックが普通のターンとして JSONL に足す。開いているセッションに 1 ターン足すだけなのでプロンプトキャッシュも効き、トークンも一番少ない。見出しに「端末」の印が付き、`POST /reply` の応答は `via: "terminal"`。

「開いているか」は行の `pane`（フックが受け取る `TMUX_PANE`）と `pid`（Claude は `CLAUDE_PID`、Codex は notify の親）で見る。一番新しい行に両方あり、`pid` が生きていれば端末で開いている。**SAI 自身が起動したターン（`claude -p` など）にはこの `pane` が付かない**（サーバが子に `TMUX_PANE` を渡さない。#234。渡していた頃は、`pnpm start` を打ったペインが全セッションの `pane` として記録されて「端末で開いている」が嘘になり、処理中の二重起動の歯止めまで外れていた）。打ち込む前に、ペインが今もあってその `pid` がペインのプロセスの子孫であること（別のセッションに打ち込まない）、入力欄が空でダイアログ中でないこと（打ちかけの文字に混ぜない、許可の答えにしない）を確かめ、だめなら `409` で何も打たない。ペインが消えていれば、Claude と閉じた Codex は別プロセス、開いている Codex は queue に戻る。

**Codex だけ、`pid` が死んでいても補欠がある**（#332）。`notify` を「受け手を順に呼ぶラッパー」経由にしていると、記録された `pid` は**すぐ終わるシェル**のものになる（Codex の `pid` を親から辿るようにしたのは #335 で、それより前の行はラッパーのまま）。この形では pid が死んでいるので端末扱いにならず、ペインでは Codex が動いているのに許可待ちの検出にも打ち込みにも回らなかった。そこで、pid が死んでいる Codex は **thread writer lock（`CODEX_HOME/thread-writer-locks/<セッション>.lock`）を握っている生きたプロセス**を本体として引き直す。lock はセッションごとのファイルなので、**同じペインで別の Codex を起動し直していても取り違えない**。結果は 30 秒覚える（3 秒のポーリングのたびに `lsof` を起こさない。見つからなかったことも覚える）。`lsof` が使えない環境では引き直さない（今までどおり端末扱いにしない）。ペインとの対応は、打ち込む前の「ペインの子孫か」の確認がそのまま効く。

**Codex は `pid` が生きていても、ペインの中かを確かめる**（#562）。codex 0.153 の TUI は**共有の `codex app-server --listen unix://` の客**として動くことがあり、ターンを回して rollout を書き `notify` を鳴らすのは app-server の方なので、行の `pid` は**tmux の外の app-server**（ppid 1）、`pane` は **app-server を起こしたペイン**の `TMUX_PANE` になる。その app-server が回す**どの会話の行も同じペインを指す**ので、`pid` が生きているだけで端末とみなすと、別の会話の TUI に打ち込みうる。いまは `pid` がペインの子孫のときだけ端末とし、外なら下の補欠（lock・ペインの側からの引き当て）に落とす（30 秒覚える）。そういう TUI は、**起動したときに作った会話にだけ**結ぶ（#568）: 起動時刻と rollout の名前の時刻・同じ worktree・TUI が作った目印が揃った 1 本があり、それを開いている app-server にその TUI が繋いでいて、その app-server が同じ worktree の別の会話を読み込んでおらず、ペインに `codex resume <その id>`（その会話から離れた印）が出ていないときだけ。**ペインの中にいても、共有の app-server そのものは端末にしない**（#653。codex 0.160 の常駐デーモンは最初の TUI が起こすのでそのペインの子孫になり、どの会話の行もそのペインを指す。端末とみなすと、同じペインの別の会話に打ち込む）。どれか 1 つでも合わなければ端末にしない。**TUI の中で `/resume` した会話は結べない**（Codex がどの会話を映しているかを外に出さないため）。Claude は今までどおり。

**Codex TUI が質問・許可のダイアログで止まると、次の画面ポーリング（最大約3秒）で一覧の「待ち」とチャット末尾に表示する。****記録に 1 行も無いセッションも、ペインで動いていれば「要対応」に出す**（#417。`notify` はターン完了でしか鳴らないので、最初のターンの許可で止まると記録が無い。一覧には出ないので、項目にはセッション ID だけが出る）。**アーカイブ済みのセッションも見に行く**（ターンの途中の質問では新しい行が届かないので、アーカイブしたまま止まったセッションは自動では戻らない。一覧からは消えていても「人を待っている」ことは出す）。 `notify` はターン完了まで来ないため、SAI が端末付きの Codex セッションのペインを読み、同じ pid の子孫であることを確認してからダイアログかを判定する。履歴の JSONL には書かず、ダイアログが閉じたら表示も消える。通常起動の TUI から質問内容・選択肢を**構造化して**受け取る口は無いが、**画面の文字からは読める**ので、見出し（`Would you like to run the following command?`）・`Reason:` などの説明・`$` のコマンド・番号付きの選択肢をバブルの下に出し、いまカーソルが当たっている選択肢には「いまここ」と印を付ける（#425）。一覧と「要対応」に出る 1 行も `Codex の許可待ち: git add -A` のように中身になる（読めない形のダイアログでは、今までどおり「Codex の画面で質問または許可への回答を待っている」に落ちる）。**そのまま画面から答えられる**（#450）: バブルのボタンを押すと、SAI が**印をその選択肢まで矢印で動かして `Enter`** を送る（実機（codex 0.154.0）で測ったところ、数字キーは効かず、矢印＋ `Enter` か近道キー（`y`）だけが効いた。どのダイアログでも同じ手にするため矢印を使う）。**「今後も聞かない」（`2.` の `don't ask again for commands that start with …`）は、範囲が全部読めたときだけボタンにする**（#741）。ボタンには**覚えられる範囲をそのまま書く**（「許可して、`git add` で始まるコマンドを今後聞かない」）。**押すといまのコマンドも実行され**（元の文は `Yes, and don't ask again …`）、Codex が自分の規則にその先頭一致を足し、以後その形は聞かれなくなる（SAI は規則を書かない・読まない）。**出るのは**: 2 番の文が終わりまで読めていて（折り返していても、閉じる引用符と `(p)` まで辿れている）、幅で切れておらず、読めた範囲が見出しのコマンドの頭（1 行目）と語の区切りで一致し、120 字以内のとき。**出ないのは**: 途中で切れている・引用符が閉じていない・範囲がコマンドの頭と合わない（コマンドが折り返していて、範囲が 1 行目に収まらないときも）・範囲が長すぎる・別の形の文のとき（そのときは今までどおり「はい」「いいえ」だけで、2 番は端末で）。範囲が広いか（1 語だけ、など）は SAI は判定しないので、ボタンの文を読んで決める。**誤って別の許可を押さないための歯止めが 3 つ**ある: ①送る前にもう一度画面を読んで**同じダイアログのまま**か確かめる（人が端末で答えた直後・次の許可に入れ替わった直後は送らずに「画面が変わりました」）、②矢印を送ったあとに読み返して**印が狙った選択肢に来たか**を確かめてから `Enter`、③`Enter` のあとにもう一度読んで**ダイアログが消えたか**を確かめる（残っていれば「答えが届きませんでした」。押し直さない）。**中身が読めなかったダイアログは今までどおり端末で**（ボタンを出さない）。**半分しか読めなかったものも同じ**（#595）: 番号が 1 から続いていない・いまここの印がちょうど 1 つでない・選択肢が 1 つだけ・「はい」に当たる選択肢が残らない、のどれかなら、読めたぶんだけ見せて「画面から読めませんでした」と出す（押しても届かないボタンは出さない）。選択肢が画面の幅で折り返していても読む（長いコマンドでは `don't ask again for commands that start with <コマンド全文>` が 2〜3 行になる）。拒否を押すと Codex は「どうしてほしいか」を聞いてくるので、そのまま返信欄から送れる。`SAI_TERMINAL=0` ではこの監視も無効。

**端末で開いた Claude が質問（`AskUserQuestion`）で止まると、セッション画面の ⏳ のバブルの下に選択肢が出る**（#333）。フックの待ちの行には質問の文しか載らないので、サーバが Claude の transcript の、返事がまだ付いていない質問から、見出し・選択肢・説明・推奨・複数選べるかを読む（「いま何をしているか」を出すときと同じ読み方で、末尾だけ）。出すのは**待ちの行と同じ文の質問だけ**（次の質問が transcript に先に書かれても、前の質問の選択肢は出さない）で、端末で答えると消える。**読むだけで、SAI からは選べない**（Codex の TUI と同じく、選択の画面にキーを送ると選び間違えうる）。答えるのは端末で。SAI から返信して回した `claude -p` の質問は、今までどおり答えられるバブル（下の「返信中の許可・質問に画面から答える」）に出る。まだセッション画面だけで、フィードと要対応には出ない。

打ちかけの文字があるときだけ（`409` の `code: terminal_typed`、`typed` にその文）、画面が「端末の入力欄に打ちかけの文字があります。これを消して送りますか？」と確認する。「消して送る」は `replace_typed: true` で送り直し、サーバは `C-u` で入力欄を空にし、**もう一度 `capture-pane` して本当に空になったときだけ**貼る（キーが効かない端末で文を混ぜない）。Claude Code は `C-u` で 1 回で空になり「Ctrl+Y to paste deleted text」と出るので端末側で戻せる。消した文は `reply.log` にも残す。許可・質問のダイアログ中（`code: terminal_dialog`）と入力欄が見つからないとき（`terminal_unknown`）は確認を出さず、消させない。 `C-u` は Claude Code も Codex も**いまの行しか消さない**ので、複数行の打ちかけは空になるまで繰り返す（上限 20 回。画面が変わらなくなったら止めて `409`）。消した全文は `reply.log` に残す（`Ctrl+Y` で戻せるのは最後の 1 行だけ）。空の入力欄に出る placeholder（Claude Code の `Try "…"`、Codex の `Ask Codex to do anything`）は打ちかけではないので、そのまま打ち込む。入力欄は区切り線（`──`）の直上の `❯` の行で見る。`/` で始めると出るスラッシュコマンドの候補メニューは選択行にも `❯` が付くが、区切り線の下なので入力欄とは読まない。メニューが開いていれば `Escape` で閉じてから `C-u` を送り、`C-u` のあと画面が変わらないときは描き直しの遅れを疑って何回か見直してから「消せない」と決める。

**確認から送り直して受け付けられたら、入力欄は空になる**（#338）。「消して送る」「端末を使わず送る」のどちらでも、送れた本文は入力欄からも打ちかけ（#306）からも消える（前は残ったままで、そのまま Enter を押すと二重に送っていた）。「やめる」を押したときは、打ち直さずに済むように本文を残す。

**端末に打ち込めなくても送れる。** 打ちかけを消せなかった、許可・質問のダイアログ中、入力欄が読めない、のどれでも `409` の body に `can_process: true` が付き、画面の確認に「**端末を使わず送る**」が出る（打ちかけがあるだけなら「消して送る」と並ぶ）。押すと `via: "process"` で送り直す。Claude は下の `claude -p --resume`、開いている Codex は `codex queue` を使う。

**開いている Codex は queue へ送る。** 同じスレッドを別プロセスから `codex exec resume` すると、`thread-store conflict: ... already has an active writer` で失敗する。`CODEX_HOME/thread-writer-locks/<session>.lock` を**開いているプロセスがいる**とき（`lsof -t` で見る。補欠で記録時の pid）は `codex queue --thread <session> --message <text>` を実行し、active writerを奪わず開いている会話へ足す。queueコマンドの終了まで待つので、受付に失敗したのに `202` を返すことはない。応答の `via` は `queue`。

- **lock のファイルがあるだけでは開いているとみなさない**（#329）。Codex が終わっても（`C-c`、サーバの立て直しで app-server ごと落ちた、など）ファイルは残る。前はそれを読んで、閉じたセッションへの返信を誰も受け取らない queue に渡していた。`lsof` が無い環境では今までどおり lock があれば開いている扱い
- **SAI の app-server が読み込んでいるスレッドは queue に回さない**。app-server は `thread/resume` したスレッドの lock をターンが終わっても開いたままにするので、見分けないと SAI から始めたターンの次の返信が queue に行く
- 打ち込んだ返信の許可ダイアログは**端末側に出る**（下の `--permission-prompt-tool` は使わない）。SAI には検出専用の「Codex の画面で回答待ち」が出るが、答えるのは端末
- 「処理中」は、その後にターン完了の行が届いたら解消。届いたと確かめられないまま 30 分たてば諦める。届いていれば（入力の行や rollout で確かめた）ターン完了かエラーまで残り、行が届かないまま終わったとき（Esc で止めた・ペインを閉じた）のために 6 時間を上限にする（#559）
- **2 分たってもターンが始まっていなければ、黙って消さずに失敗として出す**（#329）。始まったかは、Claude は入力の行（`UserPromptSubmit`）、Codex は rollout への書き込みで見る。端末の入力欄に残ったままになった、などを拾う
- **開いている Codex（`codex queue`）に渡した返信は、30 秒で確かめ、送った本文がそのスレッドに届いていなければ失敗として出す**（#474。**そのスレッドがターンの途中なら、ターンが終わるまで決めずに待つ**）。`codex queue` は受け取られたかを返さず、**VS Code 拡張・ChatGPT アプリの裏で動く共有の Codex がスレッドを握ったまま、どの画面もそのスレッドを開いていないと、エラーも出ずに本文が消える**。そのとき失敗は 30 分残し（前は 2 分で消えて、送ったのに何も起きなかったように見えた）、握っているのがその共有の Codex なら pid も出す。**そのアプリか端末でスレッドを開いてから送り直す**（SAI から別の経路で届けることはできない。別の Codex が握っている間は `thread/resume` も断られる）。開いたときに遅れて流れることはある
- **Codex への返信のターンがエラーで終わったら（上限に当たった・モデルが無い など）、その文を失敗として出す**（#475）。エラーで終わったターンでは Codex が notify を鳴らさないので、記録の行が 1 本も残らず、前は「返事が来ない」だけに見えていた。端末に打ち込んだ・queue に渡した返信は rollout の `task_complete` の `error` で、SAI の app-server で回した返信は `turn/completed` の `status: "failed"` で見る。30 分残し、reply.log にも残す
- **処理中でも打ち込める。** 端末で開いている間は、前のターンが動いていても送れる（Claude Code の TUI が次のターンに回す。端末で人が続けて打つのと同じ）。別プロセス（`-p`）の経路は二重起動になるので、すぐには起動せず**預かって、前のターンが終わってから回す**（下の「処理中に送った返信」。#305）。長いターンの間フィードから何も送れないのを避けるため（#170）
- `SAI_TERMINAL=0` で切る（Claude と閉じた Codex は別プロセス、開いている Codex は queue）。`tmux` はサーバの `PATH` から探す（#288）
- tmux 以外の端末と Claude Desktop には届かない（下のとおり別プロセスで回る）

### Claudeは別プロセス、閉じたCodexはapp-serverで回す

**`resume` で別プロセスから回した返信と返答は、そのセッションを開いている端末や Desktop の画面には出ない。** SAI には出るし履歴にも残るが、開いている対話側は会話をメモリに持っていて、外で回ったターンを読み直さない。開いている Codex に使う `queue` はこの制約の対象外で、その会話へ直接届く（**そのスレッドをいま開いている画面があるときだけ**。#474）。確かめたこと（Claude Code 2.1.258 / Codex CLI 0.139）:

- `claude -p --resume <session>` は同じセッションのトランスクリプト（`~/.claude/projects/<project>/<session>.jsonl`）に**追記する**。セッション ID も同じで、別セッションには分岐しない（`--fork-session` を付けたときだけ分岐する）
- app-serverの `thread/resume` → `turn/start` も同じ rollout ファイル（`~/.codex/sessions/YYYY/MM/DD/rollout-*.jsonl`）に追記する。新しい rollout は作らない
- なので、端末を閉じて `claude --resume <session>`（Codex は `codex resume <session>`）で**開き直せば**、SAI から送った返信とその返答も履歴に並ぶ
- 開いたままの端末で続きを打つと、その端末は SAI のターンを知らないまま進む。Claude Code の資料も「同じセッションを2つの端末で再開すると、両方のメッセージが1つのトランスクリプトに交互に入る」としている（[Manage sessions](https://code.claude.com/docs/en/sessions)）。壊れはしないが、対話側のエージェントは SAI で頼んだことを覚えていない
- Claude Desktop は CLI と「別のセッション履歴」を持つ（[Desktop の資料](https://code.claude.com/docs/en/desktop)）。`settings.json` は共有なのでフックは動いて SAI には出るが、Desktop のセッションを `claude -p --resume` で再開できるか、Desktop の画面に出るかは未確認（この Mac に Desktop が無い）

Claude の対話側にも出したいなら、SAI から送るのではなく端末側で打つしかない。Codex は開いていれば queue が同じ会話へ届き、閉じていれば別プロセスで再開する。

「処理中」の正はサーバ（子プロセスが exit するまで `replying` として `GET /api/sessions` / `GET /api/sessions/<id>` / `GET /api/feed` に載る）。画面はそれを見て仮バブルを出すので、リロードしても別タブでも同じ状態になり、一覧のそのセッションには「返信中」が付く。1分を超えると仮バブルに経過（「処理中 3分」）が出て、5分を超えると色が変わる。`replying` が変わると `rev` も変わるので、JSONL が増えなくても画面は描き直す。プロセスが終わったのに行が増えなかったとき（`claude -p` が許可待ちで落ちた、フックが失敗した）は「返信は終わったが記録が増えなかった」と出て入力欄が開く。手がかりは `~/.agent-feed/reply.log`。`session_source` が `synth` のセッション、`unknown-<日付>` に丸められたセッション、`agent` が `unknown` のセッションは ID が合成なので再開できず、入力欄の代わりにその旨が出る。**別のマシンのセッション**（下）も同じく入力欄が出ない。

**閉じた Codex に SAI から返信したターンの許可は、Codex が出した候補だけがボタンになる**（#741）。コマンドでは「許可」（今回だけ）・「ターンを中止」と、Codex が規則の追加を提案していれば **「『git status』を今後聞かない」**（ネットワークなら「『example.com』への通信を今後聞かない」／「今後も断る」）が並ぶ。最後のものを押すと、Codex が自分の規則に足して、**ほかのセッション・次の起動でも聞かれなくなる**（SAI が書くのではない）。**覚えられる範囲をボタンに書き切れないとき（80 字・12 語を超える、改行や制御文字が入っている、形が読めない）は、そのボタンを出さない**（切った範囲を見せて押させない）。提案の全文は詳細の「実行規則の提案」で読める。Codex が出した候補のうち、SAI が形を知らないものもボタンにしない。出せる候補が 1 つも無いときは「ここからは答えられません」と出るので、続けないなら「止める」でターンを止める。Codex が「拒否」を候補に入れてこないコマンドでは、断る手段は「ターンを中止」だけになる（SAI は来ていない選択肢を足さない）。ファイル変更は「許可」「セッション中許可」「拒否」「ターンを中止」。Claude の許可にある SAI の「常に許可」は Codex には出ない。**押すとセッションをまたいで残る候補は、今回だけのボタンと見た目を変える**: 「今後聞かない」は塗りの「許可」と違い枠だけ（許可の色）、「今後も断る」は拒否の色の枠。端末で開いている Codex のダイアログの「今後聞かない」も同じ見た目。「セッション中許可」はセッションの中だけなので、今までどおり。

### 別のマシンのセッション（#114）

複数のマシンの JSONL を 1 か所に集めていると（[#24](https://github.com/Naturalclar/sai/issues/24)、`AGENT_FEED_HOST` と `YYYY-MM-DD.<host>.jsonl`）、**ここでは再開できないセッション**が一覧に混ざる。CLI もその履歴もあちらのマシンにあるので、`claude --resume` を回しても続きにならない。

- サーバは自分のマシン名を**記録側と同じ `AGENT_FEED_HOST`**（無ければ `os.hostname()`）から決め、`GET /api/sessions` と `GET /api/sessions/<id>` の **`host`** に載せる。行の `host` と違えばリモート。前は別の `SAI_HOST` を見ていて、`AGENT_FEED_HOST` だけ設定すると自分のセッションまでリモートになっていた（#288）
- 一覧の項目・チャット見出し・フィードのバブルの `#repo` の隣に **`@<host>`** の印
- **返信の口を出さない。** 判定は `shared/reply.ts` の `replyBlockedReason()` の 1 か所にあり、サーバの受付（`POST …/reply` は `400`）・セッション画面の入力欄・フィードの `@` の候補が同じ答えを見る。理由は合成 ID より先に「別のマシン」を出す（ID が取れていても届かないので、そちらが根本の理由）
- サイドバーの絞り込みに「マシン」が増える（**2 台以上あるときだけ**）
- **`host` が空の行は自分のマシン扱い**（`host` を載せない古い `record.py` の行。今までどおり返信できる）。**サーバが自分の名前を決められないときは何もリモートにしない**（材料が無いのに止めると 1 台で使っている人が返信できなくなる）。ホスト名の比較は大文字小文字を無視し、`.local` などのドメイン部分は落とす（`record.py` の `host_name()` と同じ規則。`shared/host.ts`）

**リモートのマシンで返信を回すことはしない**（そのマシンの SAI に転送する話で、#24 の別の枝）。

**返信のプロセスが失敗したら理由が出る。** 子プロセスが 0 以外で終わったら、サーバは `replying` のその項目に `failed`（`code` と `reply.log` のそのターンぶんの末尾）を付けて 2 分だけ残す。画面は「処理中」ではなく `返信が失敗しました（終了コード 3）: …` と出し、入力欄を開ける。失敗した項目は「処理中」に数えないので、そのまま送り直せる。`replying.json` には書かない（pid はもう死んでいる）。理由の全文は `~/.agent-feed/reply.log`（#172）。

**処理中に送った返信は預かって、前のターンが終わってから回す**（#305）。別プロセスの経路（`claude -p` / 閉じた Codex の app-server / `opencode run`）は同じセッションに 2 本走らせられないので、以前は入力欄を止めていた。いまは送れて、送った分はサーバが預かる。

- 入力欄の上に「前の返信を処理中。送ると預かって、終わってから続けて回す」、送信ボタンは「あとで送る」
- 預けた分は処理中の仮バブルの下に「待機中（1 番目）」のバブルで並び、**取り消す**を押せる。回った分は処理中の仮バブルに移る
- **1 件ずつ回す**（まとめて 1 ターンにはしない）。モデルと許可モードは**回すとき**のセッションの設定を使うので、待っている間に変えれば次の返信から効く（#272）
- **前の返信が失敗したら回さずに止める**（失敗したターンの続きを黙って積み上げない）。先頭のバブルに理由と「続けて送る」が出る。預かった返信を起動できなかったとき（端末に打ちかけがある、cwd が消えた、CLI が無い）も外さずに止める
- 預かりが残っている間は、処理中でなくても後ろに並べる（先に預けたものを追い越さない）
- 預かりは `~/.agent-feed/reply-queue.json` にも書くので、サーバを立て直しても消えない。回すきっかけは `-p` の終わり、SAI 管理の Codex のターンの終わり、画面のポーリング（再起動で引き取った子は終わりを受け取れないので、ポーリングで拾う）
- 1 セッションに 10 件まで
- 端末（tmux）で開いているセッションと、開いている Codex（`codex queue`）は今までどおりすぐ届けるので預からない
- **「着手して」は要約してから送るのが既定**（#579）。セッション画面で 1 行目が `579着手して` / `着手して` / `N対応して` のような着手の形で、返信先が Claude・端末で開いていない・いまのコンテキストが 15 万トークン以上なら、送信ボタンの左に「送り方」が出て**要約してから送る**が選ばれる（ボタンも「要約して送る」）。**携帯では短く出す**（#629。`要約` / `そのまま` / `新規`、ボタンは「送信」。押して開くメニューは正式な名前のまま）。処理中のときの「今のターンに足す」と「あとで送る」も携帯では `足す` / `あとで`（#631）。送ると先に `/compact`（次に取りかかることと、残すもの・捨てるものの指示つき）が回り、仮バブルは「要約中」、本文は預かりのバブルに並び、要約が終わったらそのまま送られる。要約が失敗したら預かりが止まり、「続けて送る」で要約せずに送る
  - 送る前に「そのまま送る」「新しいセッションで送る」に切り替えられる（切り替えは覚えない。次の着手ではまた要約が既定）。新しいセッションは表示名・アイコン・一言の性格を引き継いで始まり、最初の記録が届いたらそちらへ移る（前のセッションは消えず、アーカイブもされない）
- **Codex と OpenCode のセッションは「分岐して送る」が選べる**（#405 / #398）。入力欄の送り方に「そのまま送る」「分岐して送る」が出る（既定はそのまま。狭い画面では「分岐」）。分岐して送ると、**そこまでの会話を全部引き継いだ新しいセッション**が出来て、打った指示はそちらで回る。**元のセッションは変わらない**（外した試行錯誤を元に残さず、別の方針を試せる）。分岐するのは会話の末尾からで、途中のターンは選べない。git も worktree も触らず、作業ディレクトリは元と同じ。
  - 分岐先は別のセッションとして一覧に並び、見出しに「← 分岐元」が出る。モデルは元のセッションのものを引き継ぎ、表示名が付いていれば「（分岐）」を足す。分岐先の画面に出るのは分岐してからのやりとりだけ（前の会話はエージェントの側が覚えているが、SAI の記録は元のセッションの側にある）
  - 送ると元の画面に「始めています」が出て、最初の記録が届いたら分岐先へ移る（「新しいセッションで送る」と同じ）
  - 選択肢に出ないとき: 端末（tmux）で開いている・ID が引けていない（Codex は rollout から。合成 ID のセッション）・別のマシンのセッション・画像を添えているあいだ（本文だけを送る口）
  - 選べるが送ると断られるとき（理由が入力欄の下に出る）: 元のセッションが処理中か預かりがある・ほかのアプリが開いている（Codex）・`SAI_CODEX_APP_SERVER=0`（Codex）・`SAI_OPENCODE_SERVER=0`（OpenCode。一発の `opencode run` では分岐しない）
  - OpenCode で、分岐はできたが最初のターンを始められなかったとき（serve が落ちた、など）は、分岐先が OpenCode の側にだけ残る（題名に「(fork #N)」。SAI には出ない。要らなければ OpenCode の側で消す）。**自分の端末で開いた OpenCode（tmux の外）がそのセッションを回している最中かは、SAI からは見えない**
  - **分岐先が回っているあいだは、元のセッションに返信しない**（同じ作業ディレクトリで 2 本が同時に動くと、返答が別のセッションに記録されることがある。#735。SAI はここを止めていない）
  - **文脈を持ったまま切り替えるなら、見出しの「引き継いで新しいセッション」**（#442。Claude だけ）。押すとそのセッションに引き継ぎ（いま何をしていて・何が決まっていて・何が未決で・次に何をするか）を書かせる。書けたら入力欄の下に「この引き継ぎで新しいセッションを始める」が出て、押すとその返答を最初の入力にして始まる（表示名・アイコン・性格・モデル・許可モードを引き継ぐ）。足りなければ返信して直させ、もう一度引き継ぐ。見出しには前後へのリンク（「← 前のセッション」「→ 続き」）が出る
  - 着手の形でなくても、コンテキストが 40 万トークン（見出しの警告と同じ区切り）を超えていれば「要約してから送る」を選べる（既定はそのまま）
  - 要約のターンは記録に行を残さず、使ったトークンもバブルには付かない（費用の記録には残る）
- **Codex と Claude は「今のターンに足す」も選べる**（#404 / #386）。走っているターンが SAI の回しているものなら、送信ボタンの横に「今のターンに足す」が出て、入れて送ると**そのターンの途中に指示が入る**（Codex は `turn/steer`、Claude は入力の口への 2 通目。Claude は走っているツールが終わった直後に取り込まれ、足した指示も自分のバブルとして出る。ターン完了の行の「頼んだこと」は元の指示のまま）。「そのファイルじゃなくてこっち」「ついでにテストも」のように、終わるまで待つと手遅れなものに使う
  - **既定は今までどおり預かり**（選ばなければ挙動は変わらない）。預かりは取り消せるが、**足した分は取り消せない**（走っているターンの筋がその場で変わる）ので、選んだときだけ足す
  - 足すのは**新しいターンではない**ので、待機中のバブルは出ず、入力欄の下に「走っているターンに足しました」と出る。ターンが終われば足した文も記録に載る
  - 送った瞬間にターンが終わっていた・別のターンになっていたら、**そのまま預かりに落ちる**（本文は落とさない）
  - **その回の行の「自分の発言」は、足した方の文になる**（Codex はターンの入力をまとめて notify に載せ、`record.py` はその末尾を採るため）。元の指示はそのターンの行には残らない（Codex 側の rollout には両方ある）

サーバは処理中の分を `~/.agent-feed/replying.json`（エンティティ ID → `pid` / `since` / `text` / 起動したときの `permission_mode`）にも書き、再起動したら読んで**生きている pid の分だけ引き取る**（死んでいた分は捨てる。以後も見るたびに生存を確かめる）。返信の子プロセスは detached なのでサーバの再起動に巻き込まれない。引き取るので、`pnpm start:watch` の再起動をまたいでも「処理中」は消えず、同じセッションへの 2 つ目の返信は預かりに回り（`queue` を付けなければ `409`）、生き残った返信からの許可の `POST /api/approvals` も通る。答え待ちの承認（下）も `~/.agent-feed/approvals.json` に書き、再起動したら**生きている返信の子の分だけ**引き取る（#440）。MCP 側は SAI に届かない間も 120 秒までは繋ぎ直すので、立て直しの前に出ていた許可にも、立て直したあとの画面から答えられる。

### 返信と許可

Claudeの返信は `claude -p`、閉じたCodexの返信はapp-serverで回す。Claudeは下記MCP、Codexはapp-serverのserver requestを使うため、どちらもSAIから許可・質問へ答えられる。通常起動のCodex TUIはapp-server接続をSAIが所有していないので、回答は端末で行う。

先に許可しておくには、環境変数でサーバに追加の引数を渡す:

```sh
SAI_CLAUDE_ARGS='--allowedTools "Bash(gh *)"' pnpm start        # gh だけ通す
SAI_CLAUDE_ARGS='--permission-mode acceptEdits' pnpm start       # ファイル編集は聞かない（コマンドは聞く）
SAI_CODEX_APP_SERVER_ARGS='-c sandbox_mode="workspace-write"' pnpm start  # app-serverのCodex設定
```

**OpenCode の口のうち、開かないと決めたもの**（#400）。`opencode serve` の API は 162 あるので、使うものだけ足していくと「開かないと決めたもの」が忘れられて後から足されてしまう。理由ごと残しておく:

| 口 | なぜ開かないか |
| --- | --- |
| `POST /session/<id>/share`（共有リンク） | 「SAI は外に出さない」と正面からぶつかる。中身は作業内容そのもので、デプロイ・ホスティング・Slack への送信をしないのと同じ |
| `POST /session/<id>/shell`、`/pty`（`/pty/<id>/connect` の一式） | サーバ越しに任意のシェルが動く。返信の POST を同一オリジンに閉じて守っているので、ここを開くと守る対象が増える。端末は tmux で足りている |
| `opencode serve` の `--mdns` / `--cors` | 外から見つけられるようにする口。同じ理由で渡さない |

**`delivery: "steer"`（動いているターンに割り込む）は「開かない」ではなく「まだ繋いでいない」。** 同じ考え方の `turn/steer` は Codex に入れた（#404。既定は今までどおり預かりで、画面で選んだときだけ足す。足した分は取り消せない）。ただし OpenCode で `delivery` を持つのは **v2 の `POST /api/session/<id>/prompt`** だけで、SAI が使っているのは v1 の `prompt_async`（1.18.30 の `/doc` で確認）。繋ぐなら v2 へ移る話とセットになる。

`claude` の `--allowedTools` は `~/.claude/settings.json` の `permissions.allow` と同じ書き方で、こちらは SAI からの返信にだけ効く（端末の許可設定はそのまま）。**SAI 自身は既定で何も付けない。** `--dangerously-skip-permissions` / `--permission-mode bypassPermissions` / Codex の `--dangerously-bypass-approvals-and-sandbox` も書けるが、返信の POST はブラウザから飛ぶので、その状態で別サイトからの CSRF が通ればエージェントが何でもできる（同一オリジンの検査で止めてはいる）。許可はツール単位で最小にする。

**許可モードはセッションごとに画面から切り替えられる。** 入力欄の**モデルの右**のボタン（Claude のセッションだけ。#265）で選ぶと、そのセッションへの SAI からの返信に `--permission-mode` が付く。送る直前に目線を動かさずに変えられるよう、返信の設定は入力欄に並べてある（`[モデル] [許可]`。差分のボタンだけは入力欄の上に浮かせる。#351）。値はセッションのメタ（`session-meta.json` の `permission_mode`、`PUT /api/sessions/<id>/meta`）。選べるのは 2 つ:

| | |
| --- | --- |
| **Accept edits**（`acceptEdits`） | 編集の許可を聞かれなくなる。コマンドは今までどおり聞く |
| **Auto mode**（`auto`。#691） | 安全性の確認つきで何でも実行する。**許可のバブルには来ない**（実測 2.1.287: SAI から起こしたターンで cwd の外の `rm -rf` も聞かれずに通った。人がはっきり頼んだ操作は止められない）。扱いは素通しと同じで、tailnet の MCP からは送れず、ループも組めない。色は素通しの赤より 1 段弱い色。**使えないモデルでは、エラーにならず黙って `default` で起動する**（実測: `--model haiku`。Auto を選んでいても許可を聞かれる） |
| **Bypass permissions**（`bypassPermissions`。#253） | 許可を一切聞かない。issue に着手してから PR を出すまで押し続けなくて済むように |

**既定の許可モードを 1 か所で決められる**（#582。自分のメニューの「返信の既定の許可モード」。**既定は「決めない」**= `Default`、CLI に任せる）。決めると、**許可モードを選んでいない Claude のセッション**と、**選ばずに始めた新しいセッション**の返信がそのモードで回る。**セッションごとに選んだものがあれば、そちらが勝つ**（既に素通しを選んであるセッションは素通しのまま。まとめて外す口は無い）。選べるのは上と同じ 3 つで、設定は `settings.json` の `reply_mode` に残る（Mac と携帯で揃う）。入力欄のボタンには実際に付くモードが出て、セッションのメニューの `Default` は「設定の既定に従う（Accept edits）」と読める。既定を `Auto mode` / `Bypass permissions` にすると、何も選んでいないセッションも tailnet の MCP から送れず、ループも組めなくなる。既定を決めたあと、あるセッションだけ CLI の既定（毎回聞く）に戻すことはできない

**モードの名前は英語で出す**（#271）。Claude Code 自身が端末の `Shift+Tab` で `accept edits on` / `bypass permissions on` と英語で出すので、同じモードが端末と SAI で別の名前に見えないように揃えてある。メニューでは名前の横に、何が起きるかを日本語で添える（`Accept edits` `ファイル編集は聞かない`）。見出しのタグと盾のモーダルも同じ名前を使う。

- **そのターン限りで、セッションには残らない。** `--model` と違うところ（`--model` は `--resume` に付けるとセッションの設定そのものが変わる）。フラグ付きで回したセッションを端末やフラグ無しで再開すると、許可は元どおり聞かれる
- **端末（tmux）に打ち込む返信には効かない。** その経路は CLI を起動せずペインに文字を送るだけなので、フラグを渡す先が無い（端末側は Shift+Tab で切り替える）。端末で開いている間は select を薄く出す
- **次の返信から効く。処理中のターンは起動したときのモードのまま**（#272）。フラグは `claude -p` を起動するときにしか渡せず、動いている CLI には後から当てられない。`acceptEdits` で回っているターンの途中で素通しに変えても、そのターンは cwd の外への書き込みやコマンドの許可を聞いてくる。何も出さないと「素通しにしたのに聞かれる」ように見えるので、サーバは起動したときのモードを `replying` に載せ（`permission_mode`）、画面は今の設定と違えば**ボタンの横に「次の返信から」**、**許可のバブルに「このターンは「Accept edits」で動いています。「Bypass permissions」は次の返信から効きます」**と出す（`launchedModeNote()`。名前は上と同じ英語）
- **`bypassPermissions` を選ぶと歯止めが一重になる。** それまでは仮に同一オリジンの検査が抜けても「CLI が未許可のツールを拒否する」で止まっていたが、素通しではそれが無い。**選んでいる間は select の横に「素通し」の印が出る**（`modeSkipsRules()`。見出しのタグとモーダルの警告と同じ判定）ので、選んだまま忘れていないか見えるようにしてある
- **`auto` は並べない。** 「安全性の確認つきで何でも実行」の中身が CLI 任せで説明できないため。`REPLY_MODES` に無い値は `PUT` の口でも `400`
- **許可は素通しになるが、質問は素通しにならない。** 実測（Claude Code 2.1.266、`--permission-mode bypassPermissions` + `--permission-prompt-tool` を両方付けて 2 回）: ツールの許可は `--permission-prompt-tool` を**一度も通らず**素通りするのに対し、`AskUserQuestion` は**今までどおり通る**。つまり許可のバブルは出なくなるが、**質問のバブルは出て答えられる**

## 返信中の許可・質問に画面から答える

端末と同じく、返信で回したエージェントが **許可（ツール実行の確認）や質問で止まったら、SAI のチャットに ⏳ のバブルと、実際に選べる決定（質問なら選択肢）が出て、そこから答えられる**。答えるまでエージェントは待っていて、一覧には「待機中」が付く。Claudeだけは [常に許可] も持つ。

**OpenCode も答えられる**（#421）。SAI が起こした `opencode serve` が許可で止まったら、画面の 3 秒のポーリングのついでに `GET /permission`（そのセッションの `directory` を渡す。渡さないと空が返る）を引いて同じ ⏳ のバブル（[許可] [拒否]）にし、押した答えを `POST /session/<セッション>/permissions/<per_…>` で返す。実機（1.18.30）で、`/etc/hosts` を読もうとして止まったターンが [許可] で再開して最後まで走るところまで確かめてある。

- **「常に許可」は出さない。** OpenCode の `always` は `patterns`（`/etc/*` のような glob）に効くので、押した範囲が本人に見えない
- **答えられるのは SAI が起こしたサーバの分だけ。** 端末で開いた OpenCode（TUI）や、自分で立てた `opencode serve` の許可は URL も鍵も知らないので触れない。その分は今までどおり記録の待ちの行として「要対応」に出て、**案内は「端末で答えてください」**になる（返信欄から送っても、止まっているのは許可の待ちなので解けない）
- **保留を見るためだけにサーバは起こさない。** 返信を 1 度も回していないうちは何も聞きに行かない
- 行に残る待ちの文言も **何を聞かれているかまで出す**（`許可待ち: external_directory: /etc/hosts`）。プラグインが `metadata` から拾うキーは**大文字小文字を見ない**（実物は `filepath`）

Codexは `server/reply/codexAppServer.ts` がSAIサーバー配下に長寿命の `codex app-server --stdio` を持ち、`experimentalApi: true`、`approvalsReviewer: user` で `thread/resume` / `turn/start` する。`item/tool/requestUserInput`、`item/commandExecution/requestApproval`、`item/fileChange/requestApproval`、`item/permissions/requestApproval` を受け、同じJSON-RPC request idへ応答する。コマンドは `availableDecisions` の実値をサーバ内に置き、画面へは不透明なidしか出さない。別thread/turn、未提示decision、二重回答は拒否し、request解消・turn完了・切断で待機を消す。

仕組みは `claude -p` の `--permission-prompt-tool`。SAI は返信の `claude` に自分の MCP サーバ（`server/approvals/approve-mcp.ts`。stdio、依存ゼロ）を `--mcp-config` で足し、許可が要るたびにそのツールが呼ばれる。ツールは SAI サーバに預けて（`POST /api/approvals`）答えが付くまで待ち（`GET /api/approvals/<id>?wait=1`）、画面の答え（`POST /api/approvals/<id>/answer`）をそのまま CLI に返す。

```
claude -p --resume … --mcp-config '{"mcpServers":{"sai":…}}' --permission-prompt-tool mcp__sai__approve
   │ 許可が要る
   ▼
approve-mcp.ts ──POST /api/approvals──▶ SAI サーバ ◀──POST /api/approvals/<id>/answer── 画面の [許可] [拒否]
               ◀─{ behavior: allow | deny }─┘
```

- **キーボードで答えられる。** `⌘Enter`（Windows / Linux は `Ctrl+Enter`）で **許可**、`⌘⇧Enter` で **常に許可**。「常に許可」のボタンが無いバブル（`Edit` など）では `⌘⇧Enter` も許可になる。フィードのように複数出ているときは**一番上のバブル**だけが受ける。`AskUserQuestion`（選択肢を選ぶもの）と、処理中・答え済みのバブルは受けない。判定は `web/src/approvalKeys.ts` の `approvalAction()`
- ショートカットは入力欄に文字を打っている最中でも効く（keydown を capture で先に取る）。**答え待ちのバブルが無ければ入力欄の `⌘Enter` は今までどおり送信**で、拾ったときだけ入力欄に渡さない
- 答え待ちはサーバのメモリと `~/.agent-feed/approvals.json`（#440。立て直しをまたぐ）。返信のプロセスが終われば（許可を待たずに落ちた、`claude` を kill した）その分は拒否扱いで消える。MCP 側が 90 秒取りに来なければ捨てる
- `AskUserQuestion` は **1 問ずつ**出る（1 回で最大 4 問聞かれるので、全部積むと携帯で読めない）。「1 / 3」の残数と [戻る] が付き、最後の 1 問に答えた時点で全問ぶんの `answers` をまとめて 1 回で返す（1 問でも欠けると CLI が「答えが無い」扱いにする）。`ExitPlanMode` はプランの先頭が出て、許可すれば進む
  - **選択肢のほかに [その他] の自由記入がある**（端末の同じダイアログと同じ）。書いた文字列はそのままエージェントに届く（label 以外でも CLI が受け取ることは実測ずみ）
  - **推奨には「推奨」バッジが付く。** 印の付きかたはツールが決めているわけではなく質問を書くモデルの書き癖なので、label 末尾の `(Recommended)` / `（推奨）` と、`description` の書き出しの `推奨` / `Recommended` の両方を拾う（label からは印を落とす）。判定は `shared/approvals.ts` の `askQuestions()`
  - **`description` は選択肢の下にそのまま出す**（ツールチップだと携帯で読めない）。`multiSelect: true` の質問はいくつでも選べて、答えはカンマ区切りになる
  - 画面は `web/src/AskQuestions.tsx`
**いま何が許可されているかは見出しの盾のアイコンから見られる。** そのセッションの `cwd` に効いている設定を読んで、評価の順（**拒否 → 毎回聞く → 許可**）に出す。読む先は強い順に、組織の `managed-settings.json`（macOS は `/Library/Application Support/ClaudeCode/`）、`<cwd>/.claude/settings.local.json`（**[常に許可] が書く先**）、`<cwd>/.claude/settings.json`、`~/.claude/settings.json`、それと `SAI_CLAUDE_ARGS` の `--allowedTools` / `--disallowedTools`（SAI から返信したターンにだけ効く）。**拒否はどの出どころのものでも許可に勝つ**ので、階段ではなく種類ごとに並べて出どころを添える。端末側の `claude --settings` は SAI からは分からないので読まない。読むだけで、ここからは足せない・消せない。

許可モード（`permission_mode`。行に載っている一番新しい値）も併せて出す。ルールが 1 件も無くても `auto` や `bypassPermissions` なら通ってしまうので、ルールだけ見ると誤解する。`default` 以外のときは一覧とチャット見出しに印が付く。Codex は許可の形が別（`~/.codex/config.toml` の `approval_policy` / `trust_level`）なので対象外。

- **[常に許可]** は端末の「今後も許可」と同じ。決定に `updatedPermissions`（`Bash(gh pr:*)` のような Claude の許可ルール。`destination: localSettings`）を付けて返すと、CLI が返信先の cwd の `.claude/settings.local.json` に書き、次のプロセスからその形は聞かれない（CLI 2.1.259 で確認）。ルールは SAI が組み立てる（`shared/approvals.ts` の `alwaysAllowRules`。CLI は候補を送ってこない）: Bash はコマンドの先頭 1 語、`gh` / `git` / `npm` のようにサブコマンドを持つ CLI は 2 語で前方一致。MCP ツールはそのツール名。Edit / Write などファイル系と `AskUserQuestion` / `ExitPlanMode` には出さない（設定に焼くには広すぎる）。「常に拒否」は無い
- **つないだコマンドは部品ごとにルールを書く**（#705）。Claude Code は `&&` / `||` / `;` / 改行 / `|` でつないだコマンドを部品ごとに見て、全部の部品が通ったときだけ通すので、`cd web && pnpm test && pnpm lint | tail -5` なら `Bash(pnpm test:*)` と `Bash(pnpm lint:*)` の 2 つを書く。**何が書かれるかは、ボタンの下に全部並ぶ**（押す前に見える）。もう設定にあるルールは足さない
  - `cd` と、読むだけのコマンド（`head` / `tail` / `grep` / `wc` / `sort` / `cat` / `echo` / `ls` など）にはルールを書かない（読むだけのコマンドしか無いのに聞かれたときは、その部品に書く）。ルールが無くても聞かれず、`Bash(cd:*)` は一度も効かない（プロジェクトの中への `cd` はルール無しで通り、外への `cd` はルールがあっても聞かれる）
  - 環境変数の代入はルールに入れる（`FOO=1 pnpm test` → `Bash(FOO=1 pnpm test:*)`。`Bash(pnpm test:*)` では通らない）
  - **押しても効かない形には [常に許可] を出さない**: `cd` と書き込み系（`touch` / `mkdir` / `rm` / `mv` / `cp` / `sed` / `tee`）や `git` をつないだもの、プロジェクトの外への `cd`、ファイルへのリダイレクト（`> out.txt`。`/dev/null` と `2>&1` は別）、展開（`$X` / `$(…)` / バッククォート / `{a,b}`）、シェルの構文（`for` / `while` / `if`）とサブシェル、バックグラウンド（`&`）。どれも、ルールが揃っていても Claude Code が聞いてくる（2.1.287 で実測。表は [history/approvals.md](history/approvals.md)）。コミットメッセージの `"$(cat <<'EOF' … EOF)"` だけは通るので出す
- **同じ形の許可を何度もしていると、[常に許可] を勧める**（#445）。SAI の画面で人が許可した回数を、作業ディレクトリと「常に許可」で書かれるルールの組（`Bash(gh pr:*)`、つないだコマンドなら `Bash(pnpm test:*) + Bash(pnpm lint:*)`）ごとに数え、2 回目からバブルに「N 回目の許可（ルール）」を出し、**3 回目からは [常に許可] のボタンを目立たせる**。盾のモーダルの一番上にも「よく許可しているが、ルールに無いもの」を並べる。**勧めるだけで、ルールは書かない**（書くのは今までどおり [常に許可] を押したときだけ）。数えるのは直近 30 日で、拒否・Jev の自動の許可・端末で答えた許可・ルールが作れないツール（`Edit` など）は数えない。数は `~/.agent-feed/approvals.jsonl`（答えるたびに 1 行。コマンドの全文は入らない）から数え直すので、消しても数がゼロに戻るだけ
- 答える口は同一オリジンのみ（`isCrossOrigin`）。ここが通ると別サイトから許可が押せてしまうので外さない
- **Claude だけ。** Codex に同等の口は無い（返信は今までどおり、承認が要るものは拒否される）
- 外すなら `SAI_APPROVE=0`。運用者が `SAI_CLAUDE_ARGS` に自前の `--permission-prompt-tool` を入れていれば SAI は足さない。`--mcp-config` は追加なので、`~/.claude.json` や `.mcp.json` の MCP サーバはそのまま使える（`--strict-mcp-config` は付けない）
- 返信のプロセスと画面の間は `127.0.0.1` の HTTP だけで、外には出ない。MCP の子プロセスに渡す宛先（`SAI_URL`）は**サーバ自身が待ち受けているアドレス**（`http://127.0.0.1:8787` など。`selfUrl()`）で、ブラウザの `Host` は使わない。tailscale serve 経由（`https://<host>.ts.net` → `127.0.0.1:8787`）で開いた画面から返信しても、子プロセスは同じマシンにいるのでループバックに戻ってくる（`Host` を使うと `http://<host>.ts.net` の 80 番に投げて「SAI に届かない: fetch failed」になる）

「フィード」は全チャンネルを時系列に流したもの（`/api/feed`）。フィードからも返信できる。全セッションが混ざっているので返信先を選ぶ必要があり、入力欄で半角の `@` を打つと候補が出て、↑↓ と Enter で選ぶと、Slack と同じく入力欄の中に表記（`@repo`。同じリポジトリが複数なら `@repo/branch`）が入り、入力欄の上のチップ（`→ #repo リポジトリ branch「タイトル」`）も差し替わる。**候補とチップには、どのリポジトリのセッションかを小さく添える**（#301。表記の `@repo` は worktree のディレクトリ名なので、`@main` がどのリポジトリのものか、`dev-*` がどれのものかが見えなかった。分からなければ出さず、worktree 名と同じ名前なら重ねて出さない）。`@` の後ろにリポジトリ名の一部（`@repo-c` や owner の `@other-org`）を打っても絞れる。**チップの名前の部分を押すと、そのセッションの最後の発言までチャットが送られて光る**（#297。エージェントの発言が無ければ自分の入力。押しても入力欄のフォーカスは外れないので、打ちかけのまま確かめられる。もう一度押せばまた送られる。フィードにそのセッションの発言が無い＝日数の窓の外やリポジトリの絞り込みで隠れているときは押せない）。表記は送信時に本文から外す。表記を手で消すか、チップの ✕ を押すと既定に戻る。何も選ばなければ**一番新しい行のセッションのうち、返信を処理中でないもの**に送る（既定でもチップに出る）。A に返信した直後は A が処理中なので、次に新しい B が既定になり、そのまま打てば B に届く。複数のセッションと並行して話せる。処理中のセッションは候補に「処理中」が付き、選ぶと送信ボタンが止まって「`#A` は前の返信を処理中。`@` で別のセッションに返信できます」と出る（全部が処理中のときだけ送れない）。入力中は既定が勝手に変わらない。再開できないセッションは候補に薄く出て選べない。送る先は同じ `POST /api/sessions/<id>/reply`。

候補は**サイドバーの一覧に出ているセッション**（絞り込みと日数はサイドバーのもの。表示名・アイコンが付いていればそれで出る）を先に、一覧に無くてフィードにだけ出ている行のセッションを後ろに並べる。リポジトリ / ブランチ / タイトルで絞れる。一覧の取得は画面全体で 1 回で、サイドバーとフィードが同じ結果を見る。

### 許可して問題なさそうかの予想（Jev。#491）

答えられる許可のバブルには、**許可して問題なさそうかを Jev（TypeSafe AI の判定専用モデル）で予想した確率**が `Jev: 問題なさそう 97%` のように付く（0.8 以上は「問題なさそう」、0.3 未満は「危なそう」で色が変わり、間は「判断が割れる」）。**既定では表示だけで、自動では答えない**（押すのは人）。自分のメニューの「自動で常に許可」（#499）を入にすると、**Claude の返信の Bash の許可**で、この回のコマンドと書かれるルール（`Bash(git status:*)` など。Jev に別の文で聞く。つないだコマンドは部品ごとに聞き、**一番低いもの**で判定する）の両方が閾値（80 / 90 / 95 / 99%）以上なら、人を待たずに [常に許可] と同じ答えを返す（ルールが cwd の `.claude/settings.local.json` に書かれ、次からその許可は出ない。`reply.log` に残る。画面を開いていなくても動く）。Edit / Write / MCP ツール（Jev に引数を送らない）と Codex / OpenCode（「常に許可」が無い）と質問は対象外で、今までどおり人が答える。Jev を切ると閾値も「しない」に戻る。

- **Jev は外部 API なので、許可の中身が外に出る**（「SAI は外に出さない」の例外）。送るのはツール名・コマンド・パス・URL・説明・理由と、Codex / OpenCode の要約（コマンド・パスから組んだもの）・Codex のダイアログの中身まで（`shared/jev.ts` の `jevState()`）。**ファイルの中身（Write / Edit の本文）・メッセージの本文と cwd は送らない**。Claude の要約（`許可待ち: …`）は、MCP のツールなどで入力の JSON がそのまま入るので送らない（#493 のレビュー）
- **鍵（`JEV_API_KEY`）がサーバの環境に無ければ何も送らない**。鍵は環境変数のままで、画面からは変えられない。送り先は固定で、リダイレクトは追わない（鍵を付けたまま別の場所へ送らない）
- **自分のメニューの「許可を Jev で予想する」で切れる**（`settings.json` の `jev`。既定は入）
- 聞くのは **SAI が答えられる許可だけ**（Claude の `-p`・SAI の Codex app-server・OpenCode・読めた Codex TUI のダイアログ）。検出だけの待ちと、質問（`AskUserQuestion` / `ExitPlanMode`）は聞かない
- **同じ許可には 1 回だけ**聞き（失敗しても聞き直さない。答えを忘れるのは見なくなってから 30 分で、長く待っている許可も聞き直さない）、同時に投げるのは 2 本まで。答えを待たずに画面を返し、届いたら次のポーリングで出る（1〜2 秒）
- 聞く文は英語の 1 文（`Allowing this action is safe: it does not destroy data, leak secrets, or make irreversible changes`）。作りもので確かめた値: `git status` 0.97 / `pnpm test` 0.79 / `Edit src/app.ts` 0.59 / `git push --force origin main` 0.08 / `curl … | sh` 0.05 / `rm -rf ~/` 0.01

## セッション同士のメッセージ（#310）

SAI から返信して回っている Claude のターンは、**同じリポジトリの別のセッションに頼んだり聞いたりできる**。人が片方の返答を読んで、もう片方に打ち直さなくて済むように。

- エージェントには、SAI の MCP サーバ（返信の `claude -p` に `--mcp-config` で渡しているもの）からツールが 3 つ見える
  - `sai_sessions`: 話しかけられる相手の一覧（呼び名・ブランチ・処理中か・最後の発言の 1 行。本文は載せない）
  - `sai_send(to, text)`: 送る。相手が処理中なら預かり（#305）に並び、終わってから回る
  - **宛先（`to`）は id でも呼び名でも書ける**（#625）: 表示名（`セッション A`）・worktree 名（`dev-worktree-a`）・`sai_sessions` に出る呼び名。完全一致だけで（大文字小文字と前後の空白は無視）、ちょうど 1 つに決まったときだけ送る。同じ名前が 2 つ以上・1 つも無いときは送らずに、候補（id と呼び名）を返す。id を引くためだけに `sai_sessions` を呼ぶ 1 往復が要らなくなる。返事には届いた相手の id と呼び名が出る
  - **着手の依頼は、相手が要約（`/compact`）してから始める**（#624）: 本文の 1 行目が着手の形（`#N に着手してください。` だけの行）で、相手が要約できる（Claude・端末で開いていない・文脈が 15 万トークン以上）なら、画面から「要約してから送る」で送ったのと同じに回る（見出しは「要約中」→ 本文のターン）。質問や、1 行目に続きを書いた依頼は要約しない。送る側は `compact: true / false` で選ぶこともできる。相手が処理中のときは要約を挟まずに預かりに並ぶ（画面からの送信と同じ）。返事には「相手は要約してから始めます」と、要約の前の文脈の大きさが出る
  - `sai_wait(message_id)`: 相手のそのターンが終わるまで待って、返答（相手の最後の発言）を受け取る
- **使うときは許可を聞かれる**。MCP のツールなので、`claude -p` の許可が画面の許可のバブル（`許可待ち: mcp__sai__sai_send: …`）に出る。いつも通すなら「常に許可」
- **受け取った側**の自分バブルは `【SAI】#<リポジトリ> の「<送り元の呼び名>」からのメッセージです（id: …）` で始まるので、人の入力と見分けられる。受け取ったエージェントにも、別のセッションから来たことと、このターンの最後の発言が返答になることが伝わる
- **送れる相手**: 送り元と同じリポジトリ（`project`）の、SAI から返信できる別のセッションだけ。別のマシン・合成 ID・アーカイブ済みは出ない。既定を同じリポジトリに絞っているのは、素通し（`bypassPermissions`）のセッションに外から指示が入る範囲を狭めるため。**別のリポジトリのセッションへは、自分のメニューの「別のリポジトリへ送る」で許した組だけ送れる**（#747。既定は空。組は向きつきで「送り元 → 宛先」、選べるのは記録で知っているリポジトリだけ。逆向きは別に許す。「やめる」で外す）。許した組の先のセッションは、エージェントの `sai_sessions` に「別のリポジトリ（送れる）」として並ぶ（呼び名・エージェント・空いているか、まで。ブランチ・最後の発言・同じファイルは出ない）。**宛先が許可を聞かないモード（Bypass / Auto）でも送れる**ので、送り元のエージェントが読んだ文に指示が混ざっていると、宛先のリポジトリまで届く（範囲は許した組で縛る）。回数・読み直しの予算・預かり・「送信を止める」は同じに効く。別のリポジトリの相手は、id か人が付けた表示名でだけ指せる（worktree 名・題名では当てない）。呼び名がリポジトリをまたいで重なるとき・送り元のリポジトリに同じ名前のセッションが居るとき（アーカイブ済みでも）は送らず、リポジトリ名付きの候補を返す。組を外すと、相手の預かりに並んでいたその向きのメッセージも取り消す
- **トークンを使いすぎない**（#311）。受け取った側はそれまでの会話を丸ごと読み直すので、1 回送るだけでも大きい
  - その場で送れるのは 1 ターンに 3 回まで（人が次の指示を打てば数え直す）。**超えた分は断らずに預かり、そのセッションのターンが終わってから SAI が順に送る**（#727。1 巡 3 件まで、巡の間は約 1 分。人が「残りも送って」と打たなくてよい）。1 つの依頼（1 ターンで頼んだ分）で合計 8 件・読み直しの合計 約 600 万トークンまでで、超える依頼は 1 件も預からずに断る。預かっている分は「別のセッションへのメッセージ」の枠に「預かり（N 番目に送ります）」と並び、**「送信を止める」で残りも止まる**。サーバを立て直しても預かりは残る（送っている途中で立て直された 1 件だけは送り直さず、「送っていません」と出る）
  - 受け取ったメッセージで回っているターンからは、さらに別のセッションへ送れない（連鎖は 1 段まで）。人がそのセッションに返信し直せば解ける
  - 送れる本文は 4,000 字まで。`sai_wait` が返す返答も 4,000 字で切る
  - 待つのはサーバ側（1 回 20 秒を MCP サーバが繰り返し、最長 30 分）。エージェントに何度もツールを呼ばせない
  - **相手のエージェントの使用量の枠が残り少なければ送らない**: 5 時間の枠が 80%、週の枠が 95% を超えている、か上限に当たっているとき（ヘッダの使用量と同じ値。Claude の割合はステータスラインを配線していないと取れず、そのときは止めない）
  - **相手が読み直す量を出し、1 ターンの予算を持つ**: `sai_sessions` に相手の直近の呼び出しの入力トークン（「読み直す量: 約 88 万トークン」）を載せ、送るたびに足していく。1 ターンで 300 万トークンを超える相手には送らない（人が次の指示を打てば数え直す）。`sai_send` の返事にも、読み直す量と予算の残りが出る。量は transcript / rollout の末尾から読む。OpenCode は手元にファイルが無いので本体（SAI が起こした `opencode serve`）に最後の返答の入力トークンを聞き（#396）、サーバが立っていなければ数えない（分からない相手は足さない）
- **見る・止める**（#311）: 別のセッションへ送ったことがあるセッションの画面では、チャットの末尾に「別のセッションへのメッセージ」の枠が出る。このターンの往復数（`2/3 回`）と読み直させた量（`約 180 万トークン / 約 300 万トークン`）、直近 5 件の送り先と状態（返答待ち / 返答あり / 失敗）。**「送信を止める」**を押すと、そのセッションからは送れなくなり、預かりに並んでいたそのセッションからのメッセージも取り消す（相手でもう回っているターンは止めない。動いている CLI を殺すと相手の会話が途中で切れる）。「再開する」で戻る。止めたことは `agent-messages.json` に残るので、SAI を立て直しても止まったまま（#440）
- **返答はチャットに並ぶ**（#588）: 送ったセッションの画面には、相手の返答が相手の名前と**アイコン**（#666。相手が付けていれば。無ければエージェントの頭文字）と「送ったメッセージへの返答」（押すと相手のセッションを開く）付きのバブルで、返答が届いた時刻の位置に出る。**送った側のエージェントが返答を待たずにターンを終えても出る**（着手を頼むような長い仕事は待たないのがふつうなので、前は送った側の会話が「頼みました」で止まり、返事が無いように見えていた）。このセッションの未読には数えない。フィードと要対応には出さない
- **返答のバブルから、その場で相手へ返信できる**（#700）: 返答のバブルの下の「返信」を押すと入力欄が開き、**相手のセッションへ人の返信として送る**（相手のセッション画面で打つのと同じ口。送り元のエージェントのターンは起こさず、送り元の会話にも足さない）。入力欄の上に「◯◯ のセッションへ送ります」と出る。開いた入力欄にはフォーカスが入り、そのまま打ち始められる。相手の最新の返答のバブルには、相手の「次に送る文面の案」を 1 押しで送るボタン（「『マージして』と送る」）も出る（相手が処理中・預かりが残っているときは出さない）。送ったことはチャットのバブルにせず、そのバブルの下の小さい 1 行（「→ ◯◯ に『マージして』と送った 12:34」。長い文は頭だけ）で出し、相手が処理中の間は「処理中」を添える。**相手がその返信に返した返答も同じ並びに出る**（見出しは「送った返信への返答」）。狭い画面でもリンクに落とさず、その場で開く。返信できない相手（別のマシン・アーカイブ済み・一覧の窓の外）には出さない。相手が処理中なら預かりに並び、送れなければ「入力欄に戻す」が出る。打ちかけは相手のセッション画面と共有する。「送ったメッセージへの返答」のリンク（相手のセッションを開く）は残る。
  - **返答は送った側のエージェントの次のターンの頭にも届く**（#594）: 待たずに終えた送り元に SAI から次を送る（返信・預かりが回る）と、まだ渡していない返答（最大 8 件・合計 12,000 字。送って 7 日以内のもの）が指示の頭に添えられる。自分のバブルには打った文だけが出て、「返答 N 件を添えました」の印が付く。返答のバブルの見出しには「次のターンで渡す / 会話に渡した」が出る。失敗した依頼は 1 行で知らせる。端末で直接続けたターンには添えられないので、次に SAI から送るときまで残る
  - **送った側がまだ回っていれば、返答はその場で足される**（#594）: SAI が起こした Claude のターンなら、届いた返答が走っているターンの途中に入る（自分のバブルに「（走っているターンの途中で届いた返答です…）」と「返答 N 件を添えました」が出る）。次のターンには重ねない
  - **エージェントが `wake` を付けて送ったものは、返答がそろうと送った側が起きる**（同じターンで付けたものが全部返ったとき 1 回だけ）。「送信を止める」にしていれば起きず、使用量の枠が残り少ないときも起きない。起きたターンからは別のセッションへ送れない
- **安全**: エージェント用の口（`/api/agent/*`）は画面の返信の口とは別。`~/.agent-feed/agent-token`（0600）の中身を要り、ブラウザから（`Origin` / `Sec-Fetch-Site` 付き）は通さない。送り元は、SAI が起動していまターンを回しているセッションだけ（MCP サーバに渡した `SAI_ENTITY`）
- **まだできないこと**: 端末で開いているセッションから送る（MCP サーバが付いていない）、Codex / OpenCode から送る（#310）。送り先は Codex / OpenCode のセッションでもよい（返信の経路で届く）
- 誰から誰に送ったか・止めたか・1 ターンの回数と量は `~/.agent-feed/agent-messages.json` にも書き、SAI を立て直しても残る（#440）。`sai_wait` は立て直しのあとも相手の返答を探せる（MCP サーバが繋ぎ直す）

## ループ（#634）

1 回の依頼ではなく、**目的に向かって何周も回す**。3 つを組にしてある:

| | 誰が決めるか |
| --- | --- |
| 目的と終わりの条件 | **人**が組むときに書く（空では組めない） |
| 次にいつ起きるか・終わったか | **エージェント**が周の終わりに言う（`sai_loop_next`） |
| 上限（周の数・時刻・使用量）と止めること | **SAI**（エージェントからは動かせない） |

- **組む**: セッション画面の見出し（狭い画面は「⋯」）の「ループを組む」。目的・終わりの条件・上限（既定 10 周・2 時間。最大 50 周・24 時間）・既定の間隔（既定 10 分。1〜60 分）を書いて「組んで 1 周目を送る」。組むとすぐ 1 周目を送る
- **周**: SAI が毎周の頭に、目的・終わりの条件・何周目か・前の周の申し送り・ツールの呼び方を組んで送る（返信と同じ経路。モデル・許可モードはそのセッションのまま）。画面のバブルには全文ではなく「ループ N 周目」と出て、「ループが送りました」の印が付く（全文は記録に残る）
- **エージェントが言うこと**（周の終わりに 1 回）: 続ける（何秒後に起こすか＋次の周への申し送り）／終わり（条件を満たした根拠）／諦める（進められない理由）。秒は 60〜3600 に丸める。**呼ばずに終わったら既定の間隔**でもう一度起こす（一定の間隔の見回りはこの形）。終わりと言ったらそこで止め、根拠を画面に出す（SAI の側では確かめない）
- **見る**: チャットの末尾に「ループ中: 3 周目 / 上限 10・次は 12:30・14:00 まで」と目的・終わりの条件・申し送り・止まった理由。サイドバーには「ループ 3/10」（一時停止は「ループ停止中」）。次の周を待っている間は要対応の「終わって次を待っている」に出さず、終わった・諦めた・止まった・一時停止したら出る
- **操作**: 「止める」（次の周を起こさない。**回っている周のターンは止まらない**）・「いま起こす」（次の時刻を待たない）・「再開」（一時停止から）・「片付ける」（終わったループの表示を消す）
- **歯止め**（どれもエージェントからは外せない）:
  - 周の上限と終わりの時刻で止まる
  - 前のターンが回っている間（**許可・質問で止まっている間も**）と、預かりが残っている間は次を送らない。SAI は許可を自動で返さない
  - 周のターンが失敗したら止まる
  - 使用量の枠が残り少なければ止まる（セッション同士のメッセージと同じ: 5 時間 80%・週 95%・上限に当たっている）
  - **人がそのセッションに自分で送ったら・ターンを止めたら一時停止**する（再開は人が押す）
  - 申し送りが 3 周続けて同じなら止まる（進んでいない）
- **組めないセッション**: Claude 以外・端末（tmux）で開いている（端末の `/loop` と二重に回るのを見分けられない）・許可を聞かないモード（Bypass permissions / Auto mode）・別のマシン・アーカイブ済み・`SAI_APPROVE=0`（エージェントが次を言う口が無い）。組んだあとにそうなったら、次の周の前に一時停止する
- ループは `~/.agent-feed/loops.json` にも書くので、SAI を立て直しても続く（送った周は送る前に書くので、同じ周を 2 回は送らない）。**画面を開いていなくても回る**（サーバが 5 秒ごとに見る）
- やらないこと: 複数のセッションをまたぐ輪・cron のような汎用のスケジューラ・上限なしのループ・端末の `/loop` の置き換え

## 待ち（「PR の CI が終わったら起こして」。#732）

エージェントが「CI が通ったら報告します」と言ってターンを終えると、そこから先は人が見に行くまで止まっていた。**エージェントが待ちを SAI に預けると、SAI が CI を確かめて、終わったらそのセッションを 1 回だけ起こす。**

- **預けるのはエージェント**（`sai_wait_for`。SAI から回っている Claude のターンにだけ出るツール）。渡すのは **PR の番号**と**起きたときにやることの 1 文**だけで、リポジトリはそのセッションのもの。もうマージ・クローズされていれば預からず、その場でそう返す
- **確かめるのは SAI**（`gh pr view` の決まった形を 60 秒おき）。**待っている間、エージェントのターンは回らない**（usage を使わない）
- **終わったら 1 回だけ起こす。** 通っても落ちても 1 回で、同じ待ちで 2 回は起きない。**「通った」「落ちた」は、続けて 2 回（60 秒あけて）同じに見えてから**起こす（push・回し直しの直後は、前の結果や速いチェックだけが載っていることがある。預けるときにもう通っている・落ちているように見えても、その場では返さず預かる）。**1 つ落ちていても、走っているチェックがあるうちは起こさない**（全部終わってから 1 回。落ちた名前をまとめて渡す）。マージ済み・クローズは 1 回で終わり。渡すのは結果の要点（通った・落ちた・落ちたチェックの名前）だけで、ログは渡さない。PR が待っている間にマージ・クローズされたときも、それを伝えて 1 回起こす
- **起きたターンでやってよいのは、結果を確かめて報告するまで**（本文にそう書いて渡す）。そのターンからは、別のセッションへ送ることも、次の待ちを預けることもできない（SAI が断る）
- **起こさないとき**は、チャットの末尾の待ちの帯に理由が出る:
  - セッションが処理中・預かりが残っている・前の返信が失敗している（終わる・片付くまで待つ。追い越さない）
  - **使用量の枠が残り少ない**（枠が戻ったら起こす）
  - 待ちで自動で起こすのは **24 時間に 6 回まで**
  - 預けたあとに、許可を聞かないモードにした・端末で開いた
- **人ができること**（待ちの帯のボタン）: **止める**（その待ちをやめる。終わった待ちの片付けも同じ）・**いま起こす**（使用量の枠と 1 日の回数に関係なく起こす。CI がまだなら「まだ終わっていません」と渡す。処理中・前の返信の失敗・許可を聞かないモードは越えない）
- **上限**（仮の値）: 同時に 2 件・1 件は 2 時間まで（過ぎたら最後に 1 回だけ確かめ、終わっていなければ起こさず、帯に「終わりませんでした」と残る）。終わったのに 6 時間起こせなかった待ちは、見に行くのをやめて帯に残す
- **預けられないセッション**はループと同じ: Claude 以外・端末で開いている・**許可を聞かないモード（`Auto mode` / `Bypass permissions`。セッションで選んだものも、設定の既定も）**・`SAI_APPROVE=0`
- 読み直す量が大きいセッション（15 万トークン以上）は、要約（`/compact`）してから起こす。このとき起こす本文は預かり（#305）に置かれ、待ちの帯は要約が始まった時点で消える（要約が失敗すると、預かりが止まった形で残る）
- 待ちは `~/.agent-feed/waits.json` にも書き、SAI を立て直しても残る。起こしている途中で立て直されたものは、届いたか分からないので起こし直さず、帯に残す
- SAI は許可を自動で返さず、権限のフラグも足さない（起こすのは返信と同じ経路）

## Manager（#323）

このリポジトリのセッションで `/manager` を呼ぶと、そのセッションが**別のリポジトリのセッションとの橋渡し役**になる。SAI に並んでいる全セッション（別のリポジトリのものも）の記録を読み、どのセッションに何を送るとよいかを、宛先・理由（どのセッションのどの発言を見たか）・そのまま貼れる本文の形で提案する。

- **自分からは送らない。** 送るのは人で、フィードの `@` で宛先を選んで貼る
- 読む口はリポジトリの `.mcp.json` の `sai-read`（手元の SAI の `/mcp` の読むツール `sai_sessions` / `sai_session` / `sai_progress` と、案を置く `sai_suggest`。[tailnet.md](tailnet.md) の表）。上のセッション同士のメッセージの `sai`（同じリポジトリの相手しか見えない）とは別の口
- SAI から返信して回すターンでは承認なしで付く。端末で開いたセッションは、最初に `.mcp.json` の承認を聞かれる
- 1 回に読むのは 5 セッションまで（読んだぶん Manager の会話が膨らむ）。自分の worktree のセッションは対象にしない。許可・質問の待ちは答えを決めず、人に知らせるだけ
- **「置いて」と言うと、提案の本文を宛先の入力欄に「案」として置く**（#565。`sai_suggest`）。置くだけで送らず、ターンも起こさない。宛先のセッションの入力欄が空のとき、入力欄のすぐ上に **「Manager からの案」** の札で全文が出て（長ければ頭だけで「全部見る」）、入力欄の背面にも同じゴーストが出る。**`→` か「入れる」で入力欄に入る**だけで、読んで直してから送る。「捨てる」で消える。1 セッションに 1 つで、置き直すと前の案は消える。**24 時間か、そのセッションに人が何か送ると消える**。打ちかけがあるときは出さず、一言の口の「次に送る文面の案」より先に出る（打ちかけ > Manager の案 > 次に送る文面の案）。前の返信を処理中のときは出さない。別のリポジトリのセッションにも、素通しのセッションにも置ける（送るのは人なので）。置いた・捨てた・入れたは `reply.log` に 1 行ずつ残る。`/manager` は人が「置いて」と言ったときだけ置き、呼ぶたびに許可を聞かれる（自動の許可には入れていない）
- まだできないこと: 提案をボタンにして 1 回で送る、Manager から送る

## 変更内容の diff を見る

入力欄の上に浮かんでいる差分のボタン（`+12 -3` のように行数が出ている。**ボタンがある間はその高さぶんチャットが縮む**ので、一番下の発言に重ならない。差分が無ければ余白も空かず、入力欄の位置は変わらない）を押すと、**そのセッションの worktree の差分**がその場で出る（GitHub を開かなくてよい）。**広い画面ではチャットの右にもう1枚のペインとして開く**ので、会話を見ながら差分を読める。狭い画面（900px 未満）は画面が足りないのでモーダルで重ねる。**ローカルの git を読むだけ**で、PR が立つ前の途中の作業でも見られる。

**ボタンはトグル**で、出しているときにもう一度押すと閉じる（✕ と Esc でも閉じる。別のセッションやフィードへ移ると閉じる）。**差分が何も無いセッションではボタンごと出ない。** 入力欄の上のボタンはフィードには出ない（返信先が `@` で動くので、どのセッションの差分か決まらない）。ペインでもモーダルでも**流れるのは中身だけ**で、題名と ✕ は上に出たまま（#221。前はモーダル全体が流れたので、閉じるは差分の一番下にあった）。

**フィードでは、PR を出した返信のバブルから開ける**（#280）。そのセッションの**いまのブランチの PR**（入力欄の上のボタンに出る番号と同じ、`gh pr view` の結果）に本文が触れているバブルの下に、同じボタンが出る。**差分ビューアが出すのは worktree のいまの差分**で、返信した時点のものではないので、**前に出した PR（番号が違う）のバブルには出さない**（押すと別のブランチの差分が出てしまう。worktree を使い回して PR を何本も出すのが普通で、手元では PR に触れたセッション 8 つのうち 7 つが 5〜16 本出していた）。行数と PR 番号を取りに行くのは、フィードの行にそのリポジトリの番号（`#12` / `owner/repo#12` / PR の URL）が出てくるセッションだけで、そのセッションに新しいターンが記録されたときだけ取り直す（3 秒ごとには取らない）。別のマシンのセッションには出ない。フィードから開いた差分は、フィードにいる間とそのセッションを開いている間は出たまま（別のセッションへ移ると隠れ、戻れば出る）。

**開いた時点で本文は開いている**（#221）。上から順に、描く行数が予算（`web/src/diffOpen.ts` の `AUTO_OPEN_LINES` = 4000 行）に収まるぶんだけ開き、超えたぶんは閉じたまま出して「差分が大きいので、下の N ファイルは閉じたままにしています」と添える（押せば開く）。実測ではこのリポジトリの差分は 1 セクション 218〜1903 行なので、普段は**全部開く**。以前はファイル数（5 件以下）で決めていたが、ブランチの差分は 11〜35 ファイルあるのが普通で、読みたいほうが必ず全部閉じて出ていた。**開閉は覚えない**（閉じて開き直すと既定に戻る）。

**ファイルの見出しは、開いている間は上に貼り付く**（#644）。長いファイルの途中を読んでいても、パス・`+N −N`・畳む `▾` が上に残り、次のファイルの見出しが来たら押し出される。**貼り付いた見出しを押して畳むと、そのファイルの先頭まで戻る**（すぐ下に次のファイルの見出しが来る。戻さないと縮んだぶん先のファイルの途中に飛ぶ）。ペイン・モーダル・PR の画面（`#/pr/…`）で同じ。貼り付くのはファイルの見出しだけで、区切りの見出し（「ブランチの差分」「未コミット」）は流れる。長いパスは貼り付いても折り返したまま（切らない）。横に送っても見出しは動かない。

| | 何を | git |
| --- | --- | --- |
| ブランチの差分 | GitHub の PR で見るのと同じもの | `git diff <base>...HEAD`（merge-base から） |
| 未コミット | まだコミットしていない書き換え | `git diff HEAD` |
| 追跡外 | 新しく置かれたファイル（名前だけ） | `git ls-files --others --exclude-standard` |

比べる相手（base）は `origin/HEAD` → `origin/main` → `origin/master` → `main` → `master` の順にローカルで探す（ネットワークは叩かない）。**`origin/HEAD` は bare clone だと未設定**なので、この順で落ちるようにしてある。**`origin/main` と `main` のように同じ名前の組が両方あるときは、新しい方と比べる**（#289）。bare clone + worktree では `origin/main` が一度作られたまま進まないことがあり、古い方と比べると後から `main` に入った他の PR まで「このブランチの差分」に出ていた。普通の clone では逆にローカルの `main` が古いので、どちらが新しいかは毎回 git に聞く（同じコミットか分岐しているときは `origin/main`）。`?base=` で他のブランチやタグに変えられる。

**その差分を Codex にレビューさせられる**（#403）。区切りの見出し（「ブランチの差分」「未コミット」）の右に「レビューさせる」が出て、押すとその差分を Codex が読んで指摘を返す。**Codex のセッションで、いま返信できるときだけ**出る（Claude / OpenCode にはこの口が無い。Claude に頼むなら本文に `/review` を送る）。押した瞬間は普通の返信と同じ「処理中」で、**結果はチャットのバブルとして届く**（差分の行には紐づかない）。比べる相手は上の表と同じ選び方なので、差分ビューアに出ているものがそのままレビューされる。**前の返信を処理中のときは押せない**（預かりには回らないので、終わってから押す）。**端末（tmux）やほかのアプリでそのセッションを開いているときも断る**（#430。レビューはそのスレッドを SAI 側で開き直して回すので、開いている端末の会話を奪ってしまう。返信なら端末に打ち込むか queue に回せるが、レビューにはその道が無い）。返ってくるのは「レビュー結果: …」＋指摘の箇条書きで、どのファイルの何行目かも付く。

**差分の行にコメントを書いて、まとめて返信欄に入れられる**（#511）。**本文は見えている行だけ描く**（#287。大きい差分でも軽い）。そのため、ブラウザのページ内検索（⌘F / iPhone の「ページを検索」）は画面から遠い行には当たらず、全部を選んでコピーしても画面の近くの行しか入らない（いったん諦めている。困ったら差分の中を探す検索欄を別 issue で）。行番号を押すとその行の下に欄が開き（⌘Enter で残す・Esc でやめる）、残したコメントは差分ビューアの上に「コメント N 件」と溜まる。「入力欄に入れる」で、ファイル・行番号・**その行の中身（引用）**・コメントを並べた本文がそのセッションの返信欄に入る（打ちかけがあれば後ろに足す。**送るのは返信欄から**なので、端末への打ち込み・預かり・失敗したら戻す、は返信と同じ。狭い画面はモーダルを閉じて返信欄を見せる）。下書きはセッションごとにブラウザ（localStorage の `sai.diffComments`）に残り、閉じても再読み込みしても消えない。差分はいまの worktree を開くたびに読み直すので、書いたあとにエージェントが編集すると行がずれる。そのときは「書いたあとに行が変わりました」と出し、行ごと消えたコメントは差分の上にまとめて出す（送るのは止めない。本文には書いたときの行を引用する）。**書けるのはそのセッションを開いていて、返信できるときだけ**（フィードから開いた差分は読むだけ）。GitHub の PR のコメントとしては出さない。

- **読むだけ。** `rev-parse` / `symbolic-ref` / `merge-base` / `diff` / `ls-files` しか呼ばない（`server/git/diff.ts` の `RealGit` が他を弾く）。`cwd` はセッションの行から取り、リクエストからは受けない
- 3 秒のポーリングには乗せない。**本文（patch）はボタンを押したときに 1 回だけ**、**行数と PR 番号は `?summary=1` の軽い口**（`--numstat` だけで patch を作らない）から、セッションを開いたときと新しいターンが記録されたときだけ読む
- 大きすぎる差分は本文を落とす（1 ファイル 200KB、1 セクション 2MB）。**ファイルの一覧は必ず全部返す**ので何が変わったかは分かり、`remote` があれば GitHub の compare へのリンクを添える
- worktree が別のブランチに移っていれば、セッションの `branch` と今の `HEAD` の食い違いを出す
- `cwd` が消えている・git のリポジトリでないときは `404`（画面はボタンを出さないだけ）

### ボタンに出る PR 番号

そのブランチに GitHub の PR が出ていれば `#211` のように併記する。**ここは SAI が外のネットワークに問い合わせる場所の 1 つ**（もう 1 つは許可の予想の Jev。#491）なので次のように閉じてある（`server/git/pr.ts`）:

- 叩くのは `gh pr view <branch> --json number,url,state,isDraft,reviewDecision` の **1 形だけ**（#636 で `reviewDecision` を足した）。他のサブコマンドは組み立てられない
- **認証は `gh` に任せる**（SAI は鍵を持たない）。`gh` が入っていない・ログインしていない・その PR が無い・ネットワークが死んでいる、のどれでも**番号が付かないだけ**で、差分そのものは今までどおり出る
- `SAI_GH=0` で丸ごと切れる。実行ファイルはサーバの `PATH` の `gh`
- `cwd` はセッションの行から、ブランチ名は git から読む。**どちらもリクエストからは受けない**。detached HEAD のときは引かない
- 同じ (cwd, ブランチ) は 60 秒引き直さない。4 秒で応答が無ければ諦める（差分の表示を待たせない）

マージ済み・クローズ済みの PR も番号は出る（どの状態かはボタンにマウスを乗せると出る）。

## GitHub の PR を見る（#/prs。#524）

サイドバーの固定項目「PR」（要対応の下）から、GitHub に出ている open な PR を並べて読む。**自分が出したもの以外も出す**（他人のコードのレビューのため）。**GitHub に書くのは、人が確認の画面で押したときのレビューの投稿だけ**（#526。下）。

- **並べるのは、SAI が記録で知っているリポジトリだけ**（直近 30 日のセッションの remote が GitHub のもの。アーカイブ済みのセッションも数える）。画面から任意のリポジトリ名を受けて `gh` に渡すことはしない（1 本の画面の URL の `owner/repo` も、知っているものの中から引く）
- **自分にレビューが頼まれているもの**（`review-requested:@me`。チームへの依頼も GitHub の検索が拾う）を各リポジトリの先頭に「レビュー依頼」の印付きで並べ、残りは新しく動いた順。「レビュー依頼だけ」で絞れる。承認済みの PR には「承認済み」の文字にチェックの印が付く（PR の画面も同じ。#636）。
- 1 本を開く（`#/pr/<owner>/<repo>/<番号>`）と、題名・出した人・ブランチ・チェック（CI）・レビューの判定・本文（Markdown）と、**差分をセッションの差分と同じビューア**で出す。上限も同じ（1 ファイル 200KB / 全体 2MB。超えたら本文を落として GitHub へのリンクを出す）
- **GitHub に付いている会話のコメントとレビューを、本文の下（差分の上）に時刻の古い順で並べる**（#600。**読むだけ**で、SAI からは返信も解決もしない）。書いた人・いつ・本文（Markdown。外の URL の画像は読み込まずリンクになる）と、レビューなら判定（承認 / 修正の依頼 / レビュー）。**GitHub で畳まれたコメントと bot のコメントは 1 行に畳み、押すと開く**（bot かどうかは名前で見る: `github-actions`・`dependabot` などの知っている名前と、`app/…`・`…[bot]`。知らない bot は畳まれずに出る）。本文の無い「レビュー」（行コメントを運ぶだけのもの）は出さない。多いときは新しい 100 件だけ出して、出していない数を見出しに書く。長い本文（20000 字超）は途中まで出して GitHub へのリンクを添える。取るのは開いたときと「更新」だけで、**コメントだけ読めなかったときは「コメントを読めませんでした」と出し、本文と差分はそのまま出す**
- **GitHub で差分の行に付いたコメント（レビューの行コメントと返信）は、差分のその行の下に出す**（#600。これも読むだけ）。下書きのコメント（青い線）と同じ場所に、**書かれたもの**として緑の線で出し、返信は 1 つのまとまりにする。**行に出すのは、いまの差分のその側にその行があり、中身がコメントの付いた行と同じときだけ**（行は取り違えない）。当たらないもの（前の版へのコメント・ファイル全体へのコメント・差分に出していないファイルのもの）は、差分の上に「いまの差分の行に当てられなかったコメント」としてファイル名と元の行番号つきでまとめる。解決済みかは見分けない（全部出す）。コメントのあるファイルは見出しに「コメント N」の印が付く（閉じているファイル・大きくて閉じたまま出たファイルでも気づける）。コメントの付いた行は、見えていなくても DOM に置いたまま（#287 の仮想化の例外。下書きと同じ）。行コメントだけ読めなかったときは 1 行出すだけで、ほかはそのまま出る
- **コメントを、その PR を書いたセッションの返信欄に入れられる**（#600）。会話のコメント・レビュー・行のやり取りのそれぞれに「返信欄に入れる」があり、押すと書いたセッション（#525 と同じ引き方）へ移って、入力欄の後ろに引用として足す（1 行目は「PR #番号「題名」に付いたコメント / レビュー / 行コメントです（URL）。」、行コメントはファイル・行・その行の中身のあとに、書いた人ごとの本文）。**足すだけで送らない**（送るのは人。打ちかけは消さない）。書いたセッションが見つからない・返信できない PR では出ない
- **その PR を書いたセッションが見つかれば、差分の行にコメントを書いて、そのセッションの入力欄に入れられる**（#525）。書いたセッションは**同じリポジトリで、いまのブランチが PR の head と同じ一番新しいセッション**（直近 30 日。サイドバーの絞り込みには依らない）。セッションの差分（#511）と同じく行番号を押して書き、題名の行の「『名前』の入力欄に入れる」でそのセッションへ移って入力欄の後ろに足す（打ちかけは消さない。**直接は送らない**）。本文の 1 行目は「PR #番号「題名」の差分へのコメントです（URL）。」で、どの PR の話かが分かる。コメントは PR ごとに残る（閉じても再読み込みしても消えない）。**見つからなければ書く口は出さない**。書いたセッションが返信できない（別のマシン・合成 ID・アーカイブ済み）ときは、その理由を出す。ブランチ名は別の worktree で使い回すことがあるので、**入れる先のセッションをボタンに名前で出す**（違っていれば気づける）
- **同じ下書きを GitHub にレビューとして投稿できる**（#526。**SAI が GitHub に書く唯一の口**で、「SAI は外に出さない」の例外）。`gh` でログインしていて PR が open のとき、題名の行の「Submit review」（GitHub のボタンと同じ文言。#649）で**確認の画面**を開く。書いたセッションが見つかる PR では入力欄に入れる方が既定なので、投稿は控えめに並ぶ。書いたセッションが見つからない PR（他人の PR）では投稿が既定
- **この 2 つのボタンは題名の行にあり、差分のどこを読んでいても押せる**（#646。題名の行は流れない）。その PR の既定の方が主のボタン、もう片方は枠付きの副ボタン（#698。「Submit review」も文字だけにせず、GitHub のように操作だと分かる形）。下書きがあるときだけ数を添える（投稿は行コメント＋全体のコメント、入力欄に入れる方は行コメントだけ）。投稿は下書きが 0 件でも出したまま（確認の画面で全体のコメントだけ書ける）、入力欄に入れる方は 0 件の間は押せない。**狭い画面（幅 900px 以下）では文言が短くなる**（「レビュー 3」「入力欄へ 3」）。差分の上に残るのは下書きの中身（「下書き: 行コメント 3 件・全体のコメント」）と「全部消す」だけ（消す操作は、いつも見えている行には置かない）
  - 確認の画面は**GitHub に載る形そのまま**: 全体のコメント（ここで書ける。PR ごとに下書きとして残る。**開くとここにフォーカスが入り、すぐ書ける**——タッチ端末ではキーボードで下が隠れるので入れない。#649）・種類（**既定は Comment**。Approve / Request changes は選んだときだけ。**自分の PR には Comment しか出さない**——GitHub が自分の PR への承認・変更要求を受けない）・行ごとのコメント（場所・書いたときの行・本文）。**押すまで何も送らない**
  - **開いたときに PR を読み直し、読んだあとに head が進んでいれば送らせない**（「更新」で取り直してから）。**読み直した差分で行が変わった・見当たらないコメント**は「行が変わりました」と出し、「外す」か「全体のコメントに移す」（場所と書いたときの行を引用して全体のコメントの末尾に足す）を選ぶまで送らせない（差分に無い行へのコメントは GitHub が断る。黙って送らない・黙って落とさない）
  - サーバも同じことを確かめる: **同一オリジンのみ**、宛先は記録で知っているリポジトリだけ、`commit_id`（読んだときの head）がいまの head と違えば送らない、**行の位置は画面から来たものをそのまま渡さず、いまの差分でその行を探し直して中身が同じときだけ**組み立てる。送るのは `gh api -X POST repos/<owner>/<repo>/pulls/<番号>/reviews` の 1 形だけ（認証は `gh`）。`gh` が無い・未ログイン・`SAI_GH=0` なら口を出さない
  - 送れたら下書きを消して「Open in GitHub」（そのレビューへ飛ぶボタン。GitHub の印付き）を出す。GitHub が断ったら理由を出し、下書きは残す。**送った・断られたことは `reply.log` に 1 行**（宛先・種類・行コメントの数・SHA。本文は書かない）
  - 携帯（tailnet 越し）からも同じ口で送れる（追加の関所は無い。Serve の本人確認は今までどおり）
- **3 秒のポーリングには乗せない**（リポジトリの数だけ `gh` が走る）。開いたときと「更新」（回る矢印のアイコン付き。取っている間は「更新中…」でアイコンが回り、狭い画面ではアイコンだけ）を押したときだけ取る。一覧はサーバが 60 秒覚える（「更新」は覚えを捨てる）
- **GitHub へ出るリンクは、GitHub の印 + 「Open in GitHub」のボタンに揃えてある**（#655。PR の見出し・レビューを送ったあと・差分が大きくて一部を出していないときの案内。差分ビューアの案内も同じ）。見出しのものだけ、狭い画面（900px 以下）では印だけになる。ホバーの説明に出す文言も同じ（PR 番号のリンクは「PR #531（オープン） — Open in GitHub」）
- **サイドバーのセッションにも、そのセッションの PR を出す**（#548）。セッションの remote の `owner/repo` とブランチが、open な PR のリポジトリと head のブランチに一致すれば、2 行目に `[GitHub の印] #番号` の印を付ける。色は下書き（薄く）・チェックが落ちている（赤）・承認済み（緑）・それ以外、の順に 1 つ。チェックの印（#636）は色とは別で、承認されていれば下書き・チェック落ちでも付く。題名と状態はマウスを乗せると出る
  - 材料は同じ `GET /api/prs`（`gh pr list` をリポジトリごとに 1 本）で、**セッションごとに `gh` は叩かない**。一覧の 3 秒のポーリングとは別に、開いたとき・見えている間の 60 秒おき・タブに戻ったときだけ取る（サーバも 60 秒覚えるので `gh` は増えない）
  - **fork のブランチから出た PR は付けない**（`gh` の `isCrossRepository`。ブランチ名だけで結ぶので、他人の同じ名前のブランチを拾う）。既定のブランチ（PR の base と同じ名前。`main` など）にいるセッションにも付けない。同じブランチに 2 本あれば新しく動いた方。出すのは open な PR だけ（マージ済み・閉じたものは消える）
  - **印はリンクにしない**（項目そのものがセッションへのリンクで、リンクの中にリンクは置けない）。開いたセッションの差分ボタンの横に PR へのリンク（#536）がある。承認済みならチェックの印が付く（#636）
- **要対応の行とフィードのバブルの見出しにも、同じ印を出す**（#554）。こちらは**押すと SAI の PR 画面**（差分も読める。GitHub へはその画面から）を開くリンク。要対応は名前の行の右端（名前はセッションへのリンクなので、その外に並べる）、フィードはブランチの横（見出しごとに出す。ブランチと同じ扱い）。要対応は上段・下段（終了）のどちらにも出す。材料は同じ `GET /api/prs` の結果で、画面ごとに取り直さない
- 読むのは `gh pr list` / `gh pr list --search review-requested:@me` / `gh pr view` / `gh pr diff` / `gh api user`（ログインしている人。投稿の口を出すか・自分の PR か）だけで、書くのは上のレビューの投稿だけ（`server/git/prs.ts`。どれも `--repo` で名指しし、チェックアウトも fetch もしない）。**認証は `gh` に任せる**。`gh` が無い・未ログイン・時間切れ（10 秒）は、そのリポジトリに「読めませんでした」と出すだけ。`SAI_GH=0` で丸ごと切れる

## 一言コメントと性格（digest）

エージェントの返答は長い説明になりがちで、フィードを眺めるには重い。右上の自分のメニューで「一言コメントを作る」を入にすると（#288。前は `SAI_DIGEST=1` でサーバを起動していた）、**新しく届いたターン完了の行**ごとに本文を **1〜2 文の一言コメント**（「PR #35 マージ、返信の二重起動を直したやつ。次は #31 やる？」のような）に言い換えて、バブルの本文をそれにする。元の本文は消えず、一言の横の「詳細」で今までどおり Markdown で開ける。自分の入力と待ちバブルは変えない。一覧の「最後の発言」も一言があればそれになる。

- **一言は「何が起きたか」と「人が次にすること」の 2 つで出来ている**（#713）。本文に人への頼みの文（「〜してください」「『マージして』と言ってください」）があれば、**その文は言い換えずに本文の言葉のまま**一言の後ろに付く（性格の口調も付かない）。口調が付くのは「何が起きたか」の側だけで、うまくいかなかったことを書く文には飾り（！・〜・絵文字）を付けさせない。見出し（「起きたこと:」など）は出さず、続けて読める文にする。本文に頼みが無ければ「何が起きたか」だけ。長さの目安（80 文字）は 2 つそれぞれに当てるので、頼みの文が付く一言は 80 文字を超えることがある
- **2 つは場所ごとに出し分ける**（#713）。同じ 2 つの文を使い回し、順番と大きさだけ変える:

  | 場所 | 出し方 |
  | --- | --- |
  | セッション画面・フィードのバブル | 「何が起きたか」を本文に、その下に「人が次にすること」を 1 行（左に細い線。見出しは付けない） |
  | 要対応の「終わって次を待っている」の行 | 「人が次にすること」を先に、「何が起きたか」を後ろに小さく |
  | 一覧の「最後の発言」 | 「何が起きたか」だけ |

  「人が次にすること」の無い一言（報告だけの回・2 つに分かれていない前の一言）は、どの場所でも今までどおり 1 つの文で出る。タブの題名は件数だけ、通知は答え待ち・待機中の文言だけで、どちらにも一言は出ない（終わっただけの行では鳴らさない。#438）
- **issue / PR は番号だけでなく「何をするものか」も残す。** 「#134 作成」だけでは何を作ったか思い出せないので、プロンプトで短い説明を添えさせる（元の本文から分かる範囲で。分からなければ番号だけ）。番号が複数並ぶときは主なものだけでよい。この分の余裕として一言の長さの目安は 80 文字（`DIGEST_MAX_CHARS`。目安を渡すだけで、超えても切らない）
- **作るのは LLM**で、既定は返信と同じ `claude` CLI を `claude -p --model haiku --output-format json` で叩く。**一言は文を返すだけなので、道具・MCP（claude.ai のコネクタも）・スキルの一覧は載せずに起こし、思考も切る**（#740。そのままだと 1 回 30〜85 秒かかり、90 秒の時間切れに掛かった。外すと 5〜16 秒）。利用者の設定ファイル（`~/.claude/settings.json`）は今までどおり読む（設定の `env` の送り先・プロキシを変えない）。外すフラグを知らない古い CLI では、外さない前の形に自動で戻る（実行ファイルはサーバの `PATH` の `claude`。モデルは自分のメニューの欄で変えられる。空なら `haiku`）。ローカルの LLM で作る口もある（下）。結果は `~/.agent-feed/digest.jsonl` に追記する。JSONL（記録）は触らず、派生データなので消しても履歴は壊れない
- **既定はオフ。** トークンと時間を使うのと、本文を LLM に送るので、黙って走らせない。入にしても**入にしたあと（起動時に入なら起動したあと）に増えた行**だけ作る（過去の行は作らない。切っていた間に届いた行もさかのぼらない）
- **出来上がりを機械で確かめ、駄目なら 1 回だけ作り直す**（#346）。見るのは元の本文と突き合わせれば分かる食い違いだけで、良し悪しは判定しない: **人に言ってほしい言葉として引用された依頼が問いかけに化けた**（本文の `よければ「マージして」と言ってください` が一言で `マージして？` になる。読む側の動作が変わる）、本文に無い番号、**番号に添えた動作の取り違え**（本文が `PR をマージしました` なのに一言が `PR 作成`。出したのか入ったのかで、読んだ人の次の一手が変わる。#378）、要約せずプロンプトに答えた、前置きや引用符、長さ超過。引っかかったら理由を添えてもう一度だけ頼み、**問題が減ったときだけ**新しい方を採る。2 回目でも残ったら、そのまま出して `digest.log` に残す（一言が消えるより、残って数えられる方がよい）。手元の実測（一言 667 件）では 13.8% が引っかかり、口による差が大きかった（`qwen3:8b` 17.6% / `haiku` 6.2%）
- **一言は「話の筋」で書く**（#359）。①何をしようとしたか ②そのままできなかったならなぜか ③いまどうなっているか（待っているなら何を待っているか）④人が次にすること、を**本文に書いてあるぶんだけ**残す。**本文に無い理由や次の一手は書かない**（`main` が進んでいただけの回に「衝突したので」と書かない）。前は「何をしたか」だけで、`PR #353 を main（#354 入り）リベース。テストOK！CI待ってます！` のように、なぜリベースしたのかと、通ったら人が何と言えばよいかが落ちていた
- **落ちていたら作り直す**（#359）。本文に「〜してください」「〜と言ってください」があるのに一言が触れていない、「待っている」で終わっていて**終わったらどうなるか**も書いていない、のどちらかなら作り直す（手元の実測で、前者は本文に依頼がある 203 件のうち 45 件、後者は「待っている」と言う 42 件のうち 36 件）。**本文に「人がすること」が書かれていない回もある**（「通ったら私がマージします」だけ）ので、そこは `通ったら…` があれば咎めない。口語の依頼（`〜してね` / `〜しましょう` / `〜して 🚀`）は残っている扱いにする
- **一言が変だと思ったら、その場で残せる**（#346）。一言の横の「変？」を押すと理由（意味が変わった / なぜそうしたか分からない / 次にすることが分からない / 事実が違う / 長い / 前置き / 口調）を選べて、任意で「こうしてほしい」も書ける。**その場の一言は変わらない**（作り直さない）。`~/.agent-feed/digest-feedback.jsonl` に溜まり、規則を直すときの材料と回帰テストの素材になる。溜めたものは**外には出さない**
- **一言と案が使われたかを手元で数える**（#446）。一言の「詳細」を開いたとき（一言では足りなかった）と、次に送る文面の案を `→` / ボタンで受け取ったときに、「変？」と同じ `~/.agent-feed/digest-feedback.jsonl` に 1 行ずつ溜める（同じ一言・同じ案は、画面を開いている間 1 回だけ）。**外には出さない**し、画面にも数字は出さない。見るときは `python3 -m feed.digest_stats`（一言のうち詳細を開いた割合・案の受け取り率を、全体・モデルごと・性格ごとに。数え始めてから作ったものと、それより前で合図が付いたものが分母。`--all` で全部）。この数字で一言を自動で作り直すことはしない（規則を直すときに人が読む材料）
- **同じタイミングで「次に送る文面の案」も作る**（#371）。一言を作った直後に同じ口へもう 1 回頼み、そのセッションの**一番新しいターン完了の行**の分だけ、次にあなたが送る文を 1 つ（60 文字以内）考えさせる。材料はその行の返答とあなたの直前の入力だけで、**本文に無い番号や作業は書かせない**。**出来上がりが人の返信として読めないとき**（エージェントの問いをそのまま聞き返している・「〜します」と宣言している・あなたへの頼みを頼み返している・本文の文の写し）は、1 回だけ作り直し、それでも駄目なら**案を出さない**（#729。判定は決め打ちの規則で、外には聞かない。あなたへの頼みで終わる返答では、ほとんど出なくなる）。出来上がりは**入力欄が空のときだけ**、打ちかけの続きと同じ**ゴースト**（placeholder の位置に薄く）で出て、**`→`** で受け取れる（タッチ端末は矢印キーが無いので、今までどおり入力欄の上のボタン）。入るだけで**送らない**（読んで直してから送る）。打ちかけの続きとは同時に出ない。**前の返信を処理中のときは出さない**（placeholder がそちらを出す）。**案は一言とは別に入切する**（#560。自分のメニューの「次に送る文面の案を作る」。口とモデルは一言と共有）。一言を全体で切っていても、セッションで「作らない」にしていても、案は作る（一言は一覧とフィードの見た目の話で、案は入力の手間の話）。一言を切っているときは**一番新しい行の分しか口を叩かない**ので、案を作るのは 1 ターンに 1 回のまま（出来上がりが人の返信として読めないときだけ、その中でもう 1 回頼む）。材料は**要約する前の返答**で、一言は使わない（要約で落ちた質問・選択肢・番号に答えられなくなるため）。設定に案の入切が無い古い `settings.json` は一言の入切に従う（一言を入にしていなかった人の本文を黙って送り始めない）。フィードには出さない（返信先が `@` で動くため）。エージェント自身が出す入力の候補は SAI には届かないので、これは SAI が作っている
- 1 行ずつ直列で回す。失敗した行（`claude` が無い、ログインしていない、90 秒で終わらない）は一言無しのままで、画面は本文を出す。理由は `~/.agent-feed/digest.log` に残る。案だけが失敗しても一言は残る
- 一言を作る `claude -p` が自分自身を記録しないよう、その子プロセスには `AGENT_FEED_SKIP=1` を渡す（`record.py` はこれが立っていると何も書かない）。`--bare` は OAuth を読まないので使えない。フックが指す `record.py` が古くてこれを知らない間は子のターンが JSONL に書かれてしまうが、子は `~/.agent-feed` を `cwd` にして起動するので、サーバは **`cwd` がそこの行を SAI 自身の雑音として読み飛ばす**（画面に出ず、要約もしない）。フックの checkout を最新にすれば書かれなくなる
- **ローカルの LLM で作る**（Ollama / LM Studio / llama.cpp / vLLM）: 口を「OpenAI 互換」にすると、`claude` の代わりに OpenAI 互換の `POST <SAI_DIGEST_URL>/chat/completions` を Node の `fetch` で叩く（依存は足さない。`server/digest/digest.ts` の `OpenAISummarizer`）。`SAI_DIGEST_URL` の既定は Ollama の `http://127.0.0.1:11434/v1`、LM Studio なら `http://127.0.0.1:1234/v1`。**モデル名は必須**（`haiku` はローカルに無い。空のまま入にするとメニューに理由が出て一言が付かないだけ）。鍵が要る口には `SAI_DIGEST_API_KEY`（`Authorization: Bearer`）。**送り先と鍵はサーバの環境変数だけ**で、画面からは変えられない（本文の送り先を同一オリジンの `PUT` 1 つで外に向けられないように。#288）。思考つきのモデル（qwen3 など）が本文に混ぜる `<think>…</think>` は落とす。子プロセスを立てないので `AGENT_FEED_SKIP` の話は無く、`claude` が無い環境でも動く。口調（MBTI）の指示は同じプロンプトで出すので、小さいモデルだと崩れる。崩れるならモデルを上げる。例: `ollama pull qwen3:8b` してから、メニューで口を「OpenAI 互換」、モデルを `qwen3:8b` にして入にする。思考つきのモデル（qwen3 など）には要求に `reasoning_effort: "none"` を付けて思考を切る（切らないと一言のために思考を先に何百トークンも生成して 90 秒の timeout に掛かり、作り直しのあいだ GPU を占有する）。付けたまま 4xx で断る口には外して 1 回だけ送り直し、通ればその口には付けない。

- **性格は MBTI の 16 タイプから**選ぶ（性格なしも選べる）。口調の指示だけが変わり、中身（何をしたか）は変えない。**全体の既定**はヘッダの select（`~/.agent-feed/settings.json` の `persona`、`GET/PUT /api/settings`）、**セッションごと**はチャット見出しの select（セッションのメタ `session-meta.json` の `persona`、`PUT /api/sessions/<id>/meta`）。セッションに設定が無ければ既定に従い、「既定」を選び直せば消える。サーバが作るときに行のセッションのメタを引いて決めるので、変えると**以後の行から**効く。過去の一言は作ったときの性格のまま（作り直さない）。MBTI は口調の「型」として借りるだけで、診断や性格分析の話にはしない。口調の表は `shared/persona.ts`
- **セッションごとに「作らない」にできる**（#263）。同じ select の一番下の「一言を作らない」で、そのセッションだけ止まる（`session-meta.json` の `digest_off`）。**「性格なし」はオフではない**（口調が中立になるだけで一言は作られる）ので別にしてある。切ると**以後は作られず、切る前に作ってあるぶんも一覧・チャット・フィードに出ない**。ただし `digest.jsonl` からは消さないので、戻せばまた出る。全体を止めるのは自分のメニューの「一言コメントを作る」
- **人に判断・回答を求めている返答は一言にしない**（#638）。「決めてほしいこと」の類の見出し・太字がある返答と、最後の段落が問いかけ（「どちらにしますか？」「〜でよいですか。」）の返答は、言い換えずに**本文をそのまま出す**（長ければ今までどおり折りたたむ）。読まないと答えられない返答で毎回「詳細」を開かずに済む。判定は決め打ちの規則で、外には聞かない。**一言の口が `openai`（手元のモデル）のときは、規則が当てなかった返答をそのモデルにも聞き**、「終わった作業の報告」ではなく「判断を待っている途中の話」（案の比較・提案・相談）と答えたら同じく本文をそのまま出す（#639。1 ターンに呼び出しが 1 回増える。`claude` の口では聞かない）。切り替えは置いていない。「次に送る文面の案」は今までどおり作る。一覧の「最後の発言」は本文の 1 行目になる
